# 类的继承机制
## 继承 (inheritance)
如果一个类别A **继承** 自另一个类别B，就把继承者A称为 **子类** ，被继承的类B称为 **父类** 、 **基类** 或 **超类** 。
## 代码复用
[[12.代码组织#^260aea|复用（reuse）与DRY原则]] 
利用继承可以从已有类中衍生出新的类，添加或修改部分功能。 新类具有旧类中的各种属性和方法，而不需要进行任何复制。
## 类的继承示例
```python
# 定义父类 Car
class Car:
    # 初始化方法：绑定车名与初始剩余里程
    def __init__(self, name):
        self.name = name          # 绑定车名属性
        self.remain_mile = 0      # 剩余里程属性，初始为0

    # 实例方法：加燃料里程
    def fill_fuel(self, miles):   # 加燃料里程
        self.remain_mile = miles

    # 实例方法：跑miles英里
    def run(self, miles):         # 跑miles英里
        print(self.name, end=': ')
        # 如果剩余里程大于等于要跑的里程
        if self.remain_mile >= miles:
            self.remain_mile -= miles
            print("run %d miles!" % (miles,))
        else:
            print("fuel out!")

# 定义子类 GasCar（燃油车），继承自 Car
class GasCar(Car):
    # 重定义 fill_fuel 方法：加汽油gas升
    def fill_fuel(self, gas):     # 加汽油gas升
        self.remain_mile = gas * 6.0  # 每升跑6英里

# 定义子类 ElecCar（电动车），继承自 Car
class ElecCar(Car):
    # 重定义 fill_fuel 方法：充电power度
    def fill_fuel(self, power):   # 充电power度
        self.remain_mile = power * 3.0  # 每度电3英里

# ===== 下面是测试代码 =====
gcar = GasCar("BMW")       # 实例化 GasCar 子类对象
gcar.fill_fuel(50.0)       # 调用 GasCar 自己的 fill_fuel 方法：50.0 * 6.0 = 300.0英里
gcar.run(200.0)            # 隐式继承调用父类 Car 的 run 方法

ecar = ElecCar("Tesla")    # 实例化 ElecCar 子类对象
ecar.fill_fuel(60.0)       # 调用 ElecCar 自己的 fill_fuel 方法：60.0 * 3.0 = 180.0英里
ecar.run(200.0)            # 180.0 < 200.0，里程不足
---#输出
BMW: run 200 miles!
Tesla: fuel out!
```

# 子类与父类
## 定义
如果两个类具有“一般-特殊”的逻辑关系，那么特殊类就可以作为一般类的“子类”来定义，从“父类”继承属性和方法。
class <子类名>(<父类名>):
	def <重定义方法>(self, …):

> [!notes] 
> 可修改（覆盖）父类中的方法（如上面的汽车加油问题），或重新定义新的方法。
## 覆盖 (Override)
子类对象可以调用父类方法，除非这个方法在子类中重新定义了。 如果子类同名方法覆盖了父类的方法，仍然还可以调用父类的方法。
## 子类添加父类中没有的方法和属性
```python
class GasCar(Car):
    # 重写初始化方法：传入名称和排量
    def __init__(self, name, capacity):  # 名称和排量
        # super()函数：调用父类（超类）的初始化方法，里面只处理名称
        super().__init__(name)           # 父类初始化方法，只有名称
        # 子类自己新增的排量属性
        self.capacity = capacity         # 增加了排量属性
```

> [!question] 为什么这里还要用 `super().__init__(name)` 调用超类（父类）？
>  **一句话原因：为了复用父类已经写好的初始化逻辑，避免重复造轮子（DRY原则）。
>  ** 父类 `Car` 本来就已经懂得如何处理 `name` 属性（`self.name = name`）。 子类 `GasCar` 是在父类的基础上“做扩展”：把属于父类管辖的 `name` 交给父类原本的逻辑去打包处理，子类自己只需要专心处理 **新增的** `capacity` 属性即可。
>
> **如果不调用超类会怎样？
> ** 子类一旦自己写了 `def __init__(self, …)`，父类的初始化过程就会被 **彻底覆盖（屏蔽）** ！ Python 会完全以子类自己写的这段代码为准，把父类的初始化代码当成“不存在”直接抛在一边。造出来的 `GasCar` 对象身上就会缺少 `name` 属性，后续访问 `c.name` 会直接报 `AttributeError` 错误。

> [!tips] 显式调用与隐式调用的区别
> 在编程里，“显”就是 **明明白白写在代码里** ，“隐”就是 **没写出来、系统在背后自动完成** 。 
> **显式调用（Explicit）** ：如 `super().__init__(name)`。当子类重写了 `__init__` 方法，Python 不会自动在后台帮你去执行父类的初始化，你 **必须白纸黑字亲手写出来** ，父类的属性才会被初始化。
>  **隐式调用（Implicit）** ：如果子类 **完全没有自己写** `__init__` 方法（或直接调用子类没重写的 `run()` 方法），Python 会 **默默在后台自动寻找并调用** 父类的 `__init__` 方法或 `run()` 方法。

# 关于self
## 基本规则与作用
在类定义中，所有方法的首个参数一般都是 **self** 。 在类内部，实例化过程中传入的所有数据都赋给这个变量。
[[21.类的定义与调用#调用类|调用类与self基础概念]]
> [!tips] 
> `self` 的底层角色：对象引用（类似指针 / Java 的 `this`） 
> 虽然 Python 没有 C 语言那种裸露的指针语法，但 [[5.变量和引用|Python 处处皆引用]]。 
> **self 的本质就是一个存着当前对象内存地址的专属引用** （在角色上完全等价于 Java / C++ 里的 `this`，只是 Python 要求显式写在第一个形参位置）。 
> 在方法内部通过 `self.name` 修改数据，其实就是 **顺着这个内存地址，直接在内存原地修改当前那个对象** 

## self实际上代表对象实例
`<对象>.<方法>(<参数>)` 等价于： `<类>.<方法>(<对象>, <参数>)` 这里的 `<对象>` 就是传给方法第一个参数的 **self** 。
```python
gcar = GasCar("BMW")
gcar.fill_fuel(50.0)
# 下面两行代码完全等价：
gcar.run(200.0)          # 对象通过点号调用方法（Python自动把 gcar 塞给 self）
GasCar.run(gcar, 200.0)  # 类直接调用方法（显式把对象 gcar 作为第一个参数传给 self）
```

## 核心疑难问答 (Q&A)
> [!question] Q1: 语句 `obj = 类名(参数)` 的本质是什么？为什么类方法里的第一个参数必须是 `self`？ 
> **1. `obj = 类名(…)` 触发了三步操作：** 创建空壳：在内存里分配一个崭新的、专属的对象空间。 自动调用 `__init__` 方法进行初始化：把新空间的控制权交给 `__init__` 方法，把参数填进去。 返回实例：把做好的对象赋值给变量 `obj`。
> **2. `self` 的本质：** 写类定义的时候，Python 还不知道你将来会创建哪一个具体的对象（不知道叫 `p1` 还是 `p2`），所以用代词 `self` 来占位，代表 **“当前正在被操作/刚诞生的那个对象实例自己”** 。 当你执行 `p1 = Person("张三")` 时，Python 后台实际执行的是：`Person.__init__(p1, "张三")`。此时 `self` 接收到的就是刚诞生的 `p1`。

> [!question] Q2: 在 `def __init__(self, name):` 下写 `self.name = name` 究竟是在做什么？
>  这一步是在 **把外面传进来的临时数据，永久“装绑”到这个新创建的对象身上，成为它自己的专属属性** 。 **等号右边的 `name`（临时传进来的参数）** ：是方法的 **形式参数** [[12.代码组织#形式函数和实际参数]]，生命周期非常短，`__init__` 方法运行完就会随之消失。 **等号左边的 `self.name`（对象身上的专属属性）** ：在当前对象（`self`）身上贴一个叫 `name` 的属性标签。一旦绑定在 `self` 身上，就会一直保存在该对象的内存空间里，不会随方法结束而消失。 **如果不写这一行** ：传进来的数据在方法结束后直接被丢弃，后续通过 `p1.name` 读取时会直接抛出 `AttributeError` 报错。

> [!question] Q3: 为什么 Python 会知道传入的 `"张三"` 正好对应形参 `name`？
>  依靠 Python 的 **函数传参规则** [[12.代码组织#调用函数的参数|位置参数与关键字参数]] 来匹配： 
>  **默认情况（位置参数）** ：依靠位置顺序排队入座。调用 `Person("张三")` 底层转换为 `Person.__init__(p1, "张三")`——第1个位置的实参 `p1` 传给第1个形参 `self`；第2个位置的实参 `"张三"` 传给第2个形参 `name`。
>   **主动指定（关键字参数）** ：依靠参数名字对应，如 `p1 = Person(name="张三")`，此时可以不按顺序对应。

> [!question] Q4: 如果类中除了 `__init__` 方法，还定义了其他普通方法，`Person(…)` 会去调用其他方法吗？
>  **绝对不会，只会去找 `__init__` 方法！** **`类名(参数)`** ：唯一使命就是实例化对象并 **自动触发 `__init__` 方法** 。
>  无论类里定义了多少个其他方法（如 `show()`、`add()`、`run()`），直接用 `类名(…)` 调用时，Python 内部写死的规则永远只认 `__init__` 方法。 **`对象名.方法名(参数)`** ：专供其他普通方法。
>  普通方法在创建对象时处于“待命”状态，必须等对象创建完毕后，由对象在外部显式通过点号 `.` 去调用才会被执行。
