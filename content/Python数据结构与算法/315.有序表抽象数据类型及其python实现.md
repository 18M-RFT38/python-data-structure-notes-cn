# 抽象数据类型：有序表 OrderedList
## 有序表的定义
有序表是一种数据项依照其某种 **可比性质**（如整数大小、字母表先后）来决定在列表中 **位置** 的数据集。

越“小”的数据项越靠近列表的头，越靠“前”。
![[file-20261030203747376.png|255]]

## 操作定义
抽象数据类型有序表 `OrderedList` 由如下操作定义：

`OrderedList()`类构造器：创建一个空的有序表对象，无参数，返回值为空有序表。
`add(item)`方法：在表中添加一个数据项，并保持整体顺序，假设此项原不存在，无返回值。
`remove(item)`方法：从有序表中移除一个数据项，此项应存在，有序表被修改，无返回值。
`search(item)`方法：在有序表中查找数据项，返回是否存在（布尔类型值）。
`isEmpty()`方法：检测并返回有序表是否为空，返回布尔类型值。
`size()`方法：返回有序表中数据项的个数，返回值为整数。
`index(item)`方法：返回数据项在表中的相对位置序号，此项应存在，返回值为整数。
`pop()`方法：移除并返回有序表中最后一项，表中应至少存在一项。
`pop(pos)`方法：移除并返回有序表中指定位置的数据项，此位置应存在。

# 有序表 OrderedList 的链表实现
## 数据项的比较与 Python 扩展性
在实现有序表的时候，需要记住的是，数据项在链表中的相对位置，完全取决于它们之间的“大小”比较。

由于 Python 的良好扩展性，对数据项的讨论并不仅适用于整数。
得益于 Python 的面向对象与运算符重载机制，有序表可适用于所有定义了 `__gt__` 方法（即支持 `>` 比较操作符）的数据类型。

## 类的定义与 Node 复用
有序表同样采用单向链表方法实现。
底层节点结构完全复用 [[313~314.无序表抽象数据类型及其python实现#Node 类的 Python 代码实现]] 的定义。
`OrderedList` 类也设置一个 `head` 属性来保存链表表头的引用，空表的 `head` 属性为 `None`。

```python
class OrderedList:
    def __init__(self):
        # 初始化表头引用属性，空表时指向 None
        self.head = None
```

## 方法的复用与修改对比
对于 `isEmpty()`、`size()`、`remove()` 这些方法，由于其算法逻辑与节点的排列次序无关，所以其具体实现跟 [[313~314.无序表抽象数据类型及其python实现#无序表核心方法的链表实现|UnorderedList 是完全一样的]]。
`search()` 和 `add()` 方法则因为直接依赖数据项的次序，需要进行算法重构与修改。
# 有序表核心方法的重构与实现
## search(item) 方法：升序剪枝与提前终止
### 算法优化原理
在无序表的 `search` 中，如果需要查找的数据项不存在，则会搜遍整个链表，直到表尾才能确定。
对于有序表来说，可以利用链表节点有序排列的特性，来为 `search` 节省不存在数据项时的无效查找时间。
此处是以升序列表为例：一旦当前节点的数据项大于所要查找的数据项，则说明链表后面已经不可能再有要查找的数据项，可以直接返回 `False`。

假设要在有序表 $(17, 26, 31, 54, 77, 93)$ 中，去查找数据项45：
![[file-20261030200804924.png|327]]
游标引用 `current` 从表头 $17$ 出发，依次向后步进经过 $17 < 45$、$26 < 45$、$31 < 45$。
当 `current` 到达节点 $54$ 时，由于当前节点的数据项 $54 > 45$，说明链表后面所链接的 $77, 93$ 必然都大于 $45$。
此时算法无需继续向后搜索，直接判定 $45$ 不存在并终止退出。
### search(item) 代码实现
```python
def search(self, item):
    current = self.head              # 游标引用 current 从表头 self.head 出发
    found = False                    # 命中标志变量 found
    stop = False                     # 提前终止标志变量 stop
    # 循环条件：未到表尾、未找到、且未触发提前终止条件
    while current != None and not found and not stop:
        if current.getData() == item:
            found = True             # 命中目标数据项
        else:
            # 升序查找剪枝：当前项已大于待查项，后续不可能再有匹配，提前停止
            if current.getData() > item:
                stop = True
            else:
                current = current.getNext() # 未达到目标大小，向后步进
    return found
```

有序性对顺序查找带来的主要优化是：对不存在数据项的平均比对次数由 $n$ 减少为约 $n/2$ 次，最坏情况时间复杂度依然为 $O(n)$。

## add(item) 方法：有序插入与双指针定位
相比无序表，改变最大的方法是 `add`，因为 `add` 方法必须保证加入的数据项添加在合适的位置，以维护整个链表的有序性。
比如在 $(17, 26, 54, 77, 93)$ 的有序表中加入数据项 $31$：我们需要沿着链表，找到第一个比 $31$ 大的数据项 $54$，并将 $31$ 插入到 $54$ 的前面。
![[file-20261030214334096.png|288]]
由于涉及到的插入位置是当前节点之前，而单向链表无法得到前驱节点的引用。
所以要跟 [[313~314.无序表抽象数据类型及其python实现#remove(item) 代码实现|remove 方法类似]]，引入一个 `previous` 的引用，紧跟当前节点 `current` 爬行。
一旦找到首个比 $31$ 大的数据项（$54$），`previous`（指向 $26$）就派上用场了。

### 插入逻辑的三大模块
模块一（发现插入位置）：使用 `previous` 与 `current` 协同遍历，发现第一个满足 `current.getData() > item` 的节点。
模块二（插入在表头）：若 `previous == None`，说明待插入数据项比原链表中所有元素都小，或者原表为空表，直接让新节点指向原首节点并更新 `self.head`。
模块三（插入在表中或表尾）：若 `previous != None`，让新节点指向 `current`，再让 `previous` 指向新节点。
### add(item) 代码实现
```python
def add(self, item):
    current = self.head
    previous = None                           # 引入前驱指针 previous
    stop = False                              # 发现插入位置标志变量 stop
    
    # 发现插入位置：寻找首个比 item 大的节点
    while current != None and not stop:
        if current.getData() > item:          # 发现第一个比 item 大的节点
            stop = True
        else:
            previous = current                # previous 跟进
            current = current.getNext()       # current 步进
            
    temp = Node(item)                         # 调用 Node() 类构造器创建新节点
    
    # 插入在表头（原表为空或 item 小于所有现有节点）
    if previous == None:
        temp.setNext(self.head)
        self.head = temp
    # 插入在表中或表尾
    else:
        temp.setNext(current)
        previous.setNext(temp)
```
复杂度分析：由于必须沿着链表遍历寻位，平均需比较 $n/2$ 次，时间复杂度为 $O(n)$。
# 链表实现的算法分析与存储模型对比
## 链表复杂度分析：看是否涉及遍历
对于链表复杂度的分析，主要是看相应的方法 **是否涉及到链表的遍历**。
对于一个包含节点数为 $n$ 的单向链表：
`isEmpty`方法是 $O(1)$：因为仅需要检查 `self.head` 是否为 `None`。
`size`方法是 $O(n)$：因为除了遍历到表尾，没有其它办法得知节点的数量。
`search`方法是 $O(n)$：因为涉及到链表的遍历，按照概率其平均操作的次数是 $n/2$。
`remove`方法是 $O(n)$：因为涉及到链表的遍历寻位，按照概率其平均操作的次数是 $n/2$。
有序表的 `add` 方法是 $O(n)$：因为涉及到链表的遍历寻位，按照概率其平均操作的次数是 $n/2$。
无序表的 `add` 方法是 $O(1)$：因为仅需要直接插入到表头，无需任何遍历。
## 链表实现与 Python 内置列表的性能对比
链表实现的 `List`，跟 Python 内置的列表数据类型，在有些相同方法的实现上的时间复杂度不同。
主要是因为 Python 内置的列表数据类型是基于 **顺序存储** 来实现的，并由底层的 CPython 进行了高度优化。
### 常见操作时间复杂度对比表
| 操作方法                         | 无序链表 UnorderedList            | 有序链表 OrderedList              | Python 内置列表 list                |
| :--------------------------- | :---------------------------- | :---------------------------- | :------------------------------ |
| `isEmpty()`                  | $O(1)$                        | $O(1)$                        | $O(1)$                          |
| `size()`                     | $O(n)$                        | $O(n)$                        | $O(1)$                          |
| `add(item)` / `append(item)` | $O(1)$（表头插入）                  | $O(n)$（按序寻位）                  | 平摊 $O(1)$（表尾追加）                 |
| `search(item)`               | $O(n)$（全表遍历）                  | $O(n)$（升序剪枝顺序查找）              | $O(n)$（底层线性查找）                  |
| `remove(item)`               | $O(n)$（寻位 $O(n)$ + 移除 $O(1)$） | $O(n)$（寻位 $O(n)$ + 移除 $O(1)$） | $O(n)$（寻位 $O(n)$ + 内存搬移 $O(n)$） |
| 表头操作（头部增删）                   | $O(1)$                        | $O(1)$（特例）                    | $O(n)$（后续数据需整体平移）               |
| 随机索引访问（如 `list[i]`）          | $O(n)$（逐跳遍历）                  | $O(n)$（逐跳遍历）                  | $O(1)$（内存地址直接偏移计算）              |

>[!notes] 架构选型总结
>若业务场景涉及频繁在表头插入和删除元素，且极少依赖按序号随机访问，链式存储具有天然的常数级优势。
>若业务场景以随机按索引读取、尾部动态追加、全量快速顺序迭代为主，Python 原生内置的顺序列表（动态数组）具有卓越的缓存局部性（Cache Locality）和执行效率。
