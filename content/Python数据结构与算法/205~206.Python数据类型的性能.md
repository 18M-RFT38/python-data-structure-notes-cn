前面我们了解了 “大O表示法” 以及对不同的算法的评估。

下面来讨论下Python两种内置数据类型上各种操作的大O数量级。

列表list和字典dict是两种重要的Python数据类型，后面的课程会用来实现各种数据结构。
本节会通过运行试验来估计其各种操作运行时间数量级。

# 对比list和dict的操作

| 类型 | list | dict |
|---|---|---|
| 索引 | 自然数i | 不可变类型值key |
| 添加 | append、extend、insert | b[k]=v |
| 删除 | pop、remove* | pop |
| 更新 | a[i]=v | b[k]=v |
| 正查 | a[i]、a[i:j] | b[k]、copy |
| 反查 | index(v)、count(v) | 无 |
| 其它 | reverse、sort | has_key、update |
# List列表数据类型
list类型各种操作（interface）的实现方法有很多，如何选择具体哪种实现方法？
总的方案就是，让最常用的操作性能最好，牺牲不太常用的操作
80/20准则：80%的功能其使用率只有20%

## List列表数据类型常用操作性能
list最常用的是：按索引取值和赋值（v=a[i], a[i]= v）
由于列表的随机访问特性，这两个操作执行时间与列表大小无关，均为O(1)

另一个常用功能的是列表增长，可以选择append()和__add__() “+”

list.append(v)，执行时间是O(1)
list= list+ \[v\]，执行时间是O(n+k)，其中k是被加的列表长度
选择哪个方法来操作列表，决定了程序的性能

## 使用timeit模块对函数计时
![[file-20261027214205724.png|322]]

创建一个Timer对象，指定需要反复运行的语句和只需要运行一次的 “安装语句”
![[file-20261027214856489.png|478]]
![[file-20261027214913231.png|390]]
`timeit.Timer` 是 timeit 模块的核心类，用于封装「待测试代码」和「前置准备代码」，专门用于精准统计代码片段的执行耗时。
![[file-20261027214349285.png|190]]
	stmt：要计时的目标代码，字符串格式。可以是函数调用、单行表达式，这段代码会被重复执行多次。
	setup：初始化 / 安装代码，字符串格式。**仅在计时开始前执行 1 次**，用来导入模块、定义变量、准备测试数据，执行耗时不计入最终结果。
建好 Timer 对象后，调用 `.timeit(number=执行次数)` 方法，返回总耗时（单位：秒）。
![[file-20261027214759138.png|219]]

```python
from timeit import Timer

t1 = Timer("test1()", "from __main__ import test1")
print(f"concat {t1.timeit(number=1000):f} seconds\n")

t2 = Timer("test2()", "from __main__ import test2")
print(f"append {t2.timeit(number=1000):f} seconds\n")

t3 = Timer("test3()", "from __main__ import test3")
print(f"comprehension {t3.timeit(number=1000):f} seconds\n")

t4 = Timer("test4()", "from __main__ import test4")
print(f"list range {t4.timeit(number=1000):f} seconds\n")
```
我们看到，4种方法运行时间差别很大
![[4种建表计时结果.png|296]]
列表连接（concat）最慢，List range最快，速度相差近200倍。
append也要比concat快得多。
另外，我们注意到列表推导式速度是append两倍的样子
## list.pop的计时试验
pop()从列表末尾移除元素，O(1)
pop(i)从列表中部移除元素，O(n)

原因在于Python所选择的实现方法
从中部移除元素的话，要把移除元素后面的元素全部向前挪位复制一遍，这个看起来有点笨拙
但这种实现方法能够保证列表按索引取值和赋值的操作很快，达到O(1)
这也算是一种**对常用和不常用操作的折衷方案**

为了验证表中的大O数量级，我们把两种情况下的pop操作来实际计时对比
相对同一个大小的list，分别调用pop（）和pop(i)
对不同大小的list做计时，期望的结果是pop()的时间不随list大小变化，pop(i)的时间随着list变大而变长
```python
import timeit

# 全局测试列表：供 Timer 的 setup 语句导入
x = list(range(2000000))

# 测试从列表头部弹出元素
popzero = timeit.Timer("x.pop(0)", "from __main__ import x")
# 测试从列表尾部弹出元素
popend = timeit.Timer("x.pop()", "from __main__ import x")

# 各执行 1000 次，打印总耗时
print(f"pop(0) 总耗时: {popzero.timeit(number=1000):.6f} 秒")
print(f"pop()   总耗时: {popend.timeit(number=1000):.6f} 秒")
```
![[file-20261027213220767.png|285]]
对于长度2百万的列表，执行1000次
pop()时间是0.0007秒
pop(0)时间是0.8秒
相差了近1000倍

我们再通过改变列表的大小来测试两个操作的增长趋势
```python
import timeit

popzero = timeit.Timer("x.pop(0)", "from __main__ import x")
popend = timeit.Timer("x.pop()", "from __main__ import x")
print("pop(0)   pop()")
for i in range(1000000, 100000001, 1000000):
    x = list(range(i))
    pt = popend.timeit(number=1000)
    x = list(range(i))
    pz = popzero.timeit(number=1000)
    print(f"{pz:15.5f}, {pt:15.5f}")
```
![[file-20261027213553604.png|220]]
将试验数据画成图表，可以看出增长趋势
pop()是平坦的常数
pop(0)是线性增长的趋势

1)

## list和dict的in操作对比
设计一个性能试验来验证list中检索一个值，以及dict中检索一个值的计时对比
生成包含连续值的list和包含连续关键码key的dict，用随机数来检验操作符in的耗时。

```python
import timeit
import random

for i in range(10000, 1000001, 20000):
    t = timeit.Timer(f"random.randrange({i}) in x",
                     "from __main__ import random, x")
    x = list(range(i))
    lst_time = t.timeit(number=1000)
    x = {j: None for j in range(i)}
    d_time = t.timeit(number=1000)
    print(f"{i}, {lst_time:10.3f}, {d_time:10.3f}")
```
![[file-20261027221016441.png|173]]
可见字典的执行时间与规模无关，是常数时间O(1)。（代价是字典不能有重复的 key）

而列表的执行时间则随着列表的规模加大而线性上升。（逐个遍历比对元素的规模）
