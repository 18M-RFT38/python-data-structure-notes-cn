# 什么是树

## 树的基本概念
本章讨论一种基本的==“非线性”==数据结构——**树（Tree）**。

与此前学习的 [[301~302.线性结构及栈抽象数据类型|线性结构]]（如栈、队列、列表）不同，树在计算机科学的各个领域中被广泛应用，包括操作系统、图形学、数据库系统、计算机网络等。

跟自然界中的树一样，数据结构树也分为**根、枝和叶**等三个部分；但一般数据结构的图示把==根放在上方，叶放在下方==。

## 生活中的树示例

### 生物学物种分类体系
生物学物种分类体系按层级划分为：**界（Kingdom）$\to$ 门（Phylum）$\to$ 纲（Class）$\to$ 目（Order）$\to$ 科（Family）$\to$ 属（Genus）$\to$ 种（Species）**。
![[file-20261117200003852.png|242]]
#### 分类树的特征
![[file-20261117200433815.png|263]]
**层次化**：树是一种分层结构，越接近**顶部**的层越**普遍**，越接近**底部**的层越**独特**。
**叶节点唯一性（第三个特征）**：每一个叶节点都具有==唯一性==，可以用从根开始到达每个种的完全路径来唯一标识每个物种。

例如家猫的完整路径为：`动物界 -> 脊索门 -> 哺乳纲 -> 食肉目 -> 猫科 -> 猫属 -> 家猫种`，对应英文路径 `Animalia -> Chordate -> Mammal -> Carnivora -> Felidae -> Felis -> Domestica`。

>[!notes] 同名叶节点的唯一性辨析
>上例中家猫（`Felis -> Domestica`）与家蝇（`Musca -> Domestica`）在最底层种名都为 `Domestica`，但由于从根节点 `Animalia` 出发的完全路径不同，它们在树中依然各自对应唯一物种。
### 文件系统
类 Unix/Linux 文件系统以根目录 `/` 为根，向下延伸出 `dev/`、`etc/`（含 `cups/`、`httpd/`、`init.d/`、`postfix/`）、`sbin/`、`tmp/`、`Users/`（含 `bmiller/`、`jmiller/`、`mysql/`）、`usr/`（含 `bin/`、`lib/`、`local/`）、`var/`（含 `log/`、`spool/`、`yp/`）等目录。

Windows 文件系统以盘符 `C:\` 为根，向下延伸出 `Windows\`（含 `System32\Drivers\etc\hosts`、`Fonts\`、`Temp\`）、`Program Files\`、`Python27\`（含 `Lib\`、`Doc\`、`Tools\`）等目录。

![[file-20261117200517565.png|365]]
### HTML 文档（嵌套标记）
HTML 文档通过成对的嵌套标记组织页面结构，天然对应一棵文档树（DOM 树）。
```html
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en" lang="en">
  <head>
    <meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
    <title>simple</title>
  </head>
  <body>
    <h1>A simple web page</h1>
    <ul>
      <li>List item one</li>
      <li>List item two</li>
    </ul>
    <h2><a href="http://www.cs.luther.edu">Luther CS</a></h2>
  </body>
</html>
```
该文档对应的树以 `html` 为根，下分 `head`（子节点为 `meta`、`title`）和 `body`（子节点为 `ul`、`h1`、`h2`），其中 `ul` 包含两个 `li` 子节点，`h2` 包含 `a` 子节点。

![[file-20261117200540529.png|333]]
>[!notes] 与栈的关联
>此前在 [[303.简单括号匹配|栈的应用]] 中使用栈检查嵌套标签是否配对，而将嵌套标签展开后的整体包含关系正是一棵树。
### 域名体系（DNS）
互联网域名体系以 `ICANN` 为根节点，向下分出 `.com`、`.cn`、`.name` 等顶级域。

`.com` 下有 `google`（`www`、`mail`）、`apple`、`facebook`；`.cn` 下有 `edu` $\to$ `pku`（`www`、`its`、`mail`）、`tsinghua`、`ruc`；`.name` 下有 `chenbin` $\to$ `www`。

例如 `its.pku.edu.cn` 在树中对应的完整路径是从根到叶的 `ICANN -> .cn -> edu -> pku -> its`（域名文本书写顺序为从叶到根反向排列）。

# 树结构相关术语
## 基本构成术语
**节点 Node**：组成树的基本部分。
每个节点具有名称，或==“键值”==，节点还可以保存额外数据项，数据项根据不同的应用而变。

**边 Edge**：组成树的另一个基本部分。
每条边恰好连接两个节点，表示节点之间具有关联，边具有出入方向。
每个节点（除根节点）恰有==一条==来自另一节点的**入边**；每个节点可以有==多条==连到其它节点的**出边**。

**根 Root**：树中==唯一一个没有入边==的节点（例如 HTML 树中的 `html` 节点）。

**路径 Path**：由边依次连接在一起的节点的**有序列表**。

例如 `HTML -> BODY -> UL -> LI` 就是一条路径。
![[file-20261117200726139.png|365]]
## 节点关系与层级术语
**父节点 Parent**：一个节点是其所有出边所连接节点的父节点（英文 `Parent` 为性别中性词，中文也可理解为“亲节点”）。

**子节点 Children**：入边均来自于同一个节点的若干节点，称为这个节点的子节点。

**兄弟节点 Sibling**：具有同一个父节点的节点之间称为兄弟节点（英文 `Sibling` 不分性别，中文也可理解为“同胞节点”或“近亲节点”）。

**子树 Subtree**：一个节点和其所有子孙节点，以及相关边的集合。

**叶节点 Leaf**：没有子节点的节点称为叶节点（也是没有出边的节点）。

**层级 Level**：从根节点开始到达一个节点的路径，所包含的**边的数量**，称为这个节点的层级。例如在三层示例树（`根` $\to$ `B/C` $\to$ `D/E/F`）中，根节点的层级为 `0`，`B`、`C` 的层级为 `1`，`D`、`E`、`F` 的层级为 `2`。

**高度 Height**：树中所有节点的==最大层级==称为树的高度（如上述三层示例树的高度为 `2`）。
![[file-20261117200816009.png|352]]
>[!attention] 高度与深度的定义歧义（具体情况具体分析）
>不同教材对“高度”和“深度”的起始计数约定不同，做题前务必先确认题干或教材体系：
>**本课程体系**：根节点层级 `Level = 0`（按路径边数计），树的**高度**定义为所有节点的最大层级（上例为 `2`）。
>**国内经典教材 / 408 常见体系**：通常以根节点为第 `1` 层，**深度（Depth）**从根向下计数，**高度（Height）**从最深叶节点向上计数（叶节点高度为 `1`，整棵树的高度与最大深度数值相等，上例为 `3`）。
# 树的定义
树的定义 1（点边集合视角）
树由若干**节点**，以及两两连接节点的**边**组成，并有如下性质（可看作点和边的一种特殊的集合）：
其中一个节点被设定为**根**；
每个节点 $n$（除根节点），都恰连接==一条==来自节点 $p$ 的边，$p$ 是 $n$ 的父节点；
每个节点从根开始的路径是==唯一==的；
如果每个节点最多有两个子节点，这样的树称为 **“二叉树”**。
![[file-20261117201125226.png|289]]
树的定义 2（递归定义）
树是：**空集**；或者由**根节点**及 **$0$ 或多个子树**构成（其中子树也是树），每个子树的根到根节点具有边相连。
![[file-20261117201141444.png|326]]
>[!tips] 递归定义的意义
>树的这种自相似递归定义，是理解 [[404.递归可视化：分形树|分形树]] 以及编写树遍历（前序、中序、后序）、树高计算等递归算法的直接理论基础。
