# 找零兑换问题：递归解法
## 寻找确定最优解的方法
贪心策略是否有效依赖于具体的硬币体系。
为了找一种**肯定能找到最优解**的方法，我们可以采用 [[401.什么是递归|递归]] 算法来解决找零兑换问题。
## 基于递归三定律的问题分解
对照 [[401.什么是递归#递归“三定律”|递归三定律]]，将找零兑换问题拆解为基本结束条件与规模缩小的子问题：
### 确定基本结束条件
兑换硬币这个问题最简单直接的情况（最小规模）就是：需要兑换的找零，其面值**正好等于某种硬币**。
如找零 25 分，答案就是 1 个硬币！
### 减小问题的规模并调用自身
我们要对每种硬币尝试 1 次，例如美元硬币体系（1分、5分、10分、25分）：
找零减去 1 分（penny）后，求兑换硬币最少数量（递归调用自身）。
找零减去 5 分（nickel）后，求兑换硬币最少数量（递归调用自身）。
找零减去 10 分（dime）后，求兑换硬币最少数量（递归调用自身）。
找零减去 25 分（quarter）后，求兑换硬币最少数量（递归调用自身）。
上述 4 项中选择**最小的一个**。
数学归纳公式表示为：
$$numCoins = \min \begin{cases} 1 + numCoins(originalamount - 1) \\ 1 + numCoins(originalamount - 5) \\ 1 + numCoins(originalamount - 10) \\ 1 + numCoins(originalamount - 25) \end{cases}$$
## 递归解法代码实现
```python
# 定义找零兑换递归函数 recMC()，接收硬币面值列表参数 coinValueList 和找零金额参数 change
def recMC(coinValueList, change):
    # 定义局部最小硬币数变量 minCoins，初始赋值为当前找零金额变量 change（即全部用 1 分硬币兑换的最坏情况）
    minCoins = change
    # 基本结束条件（最小规模）：使用 in 运算符判断找零金额变量 change 是否直接在硬币面值列表参数 coinValueList 中
    if change in coinValueList:
        # 最小规模，直接返回 1 个硬币
        return 1
    else:
        # 使用列表推导式筛选出小于等于 change 的硬币面值，并通过 for 循环遍历每个可用面值变量 i
        for i in [c for c in coinValueList if c <= change]:
            # 减小规模并调用 recMC() 函数自身：当前硬币数 1 加上剩余找零 change - i 的最少硬币数
            numCoins = 1 + recMC(coinValueList, change - i)
            # 若当前尝试得到的硬币数变量 numCoins 小于已知最小硬币数变量 minCoins，则更新最优解
            if numCoins < minCoins:
                minCoins = numCoins
    # 返回最终求得的最少硬币数变量 minCoins
    return minCoins

# 调用 recMC() 函数计算 63 分找零的最少硬币数，并调用内置函数 print() 打印结果
print(recMC([1, 5, 10, 25], 63))


```

> [!notes] 列表推导式过滤说明
> 
> 代码中 `[c for c in coinValueList if c <= change]` 使用了 [[26.推导式与生成器#列表推导式|列表推导式]]（非函数或方法调用），作用是从硬币面值列表参数 `coinValueList` 中筛选出所有面值小于等于当前找零金额 `change` 的硬币，生成一个新的列表对象供 `for` 循环遍历，每次减去一种硬币面值以挑选最小数量。
> 
>   
## 性能瓶颈：极其低效
递归解法虽然能解决问题，但其最大的问题是：**极！其！低！效！** 对 63 分的兑换硬币问题，需要进行 `67,716,925` 次递归调用！ 在测试笔记本电脑上花费了约 40 秒时间才得到解：6 个硬币。

# 找零兑换问题：递归解法改进
## 消除重复计算的思路（查表法 / 记忆化）
对这个递归解法进行改进的关键就在于**消除重复计算**。 
我们可以用一个表将计算过的中间结果保存起来，在计算之前查表看看是否已经计算过。
  
这个算法的中间结果就是**部分找零的最优解**，在递归调用过程中已经得到的最优解被记录下来。
在递归调用之前，先查找表中是否已有部分找零的最优解： 如果有，**直接返回**最优解而不进行递归调用。 
如果没有，才进行递归调用。

## 递归解法改进代码实现

```Python
# 定义改进后的找零递归函数 recDC()，接收硬币列表 coinValueList、找零金额 change 和记录表列表参数 knownResults
def recDC(coinValueList, change, knownResults):
    # 定义局部最小硬币数变量 minCoins，初始赋值为找零金额变量 change
    minCoins = change
    # 递归基本结束条件：找零金额变量 change 直接等于某一种硬币面值
    if change in coinValueList:
        # 通过列表索引将最优解 1 记录到列表参数 knownResults 的对应位置中
        knownResults[change] = 1
        return 1
    # 查表判断：访问列表参数 knownResults 的索引项 knownResults[change]，若大于 0 说明已计算过该子问题
    elif knownResults[change] > 0:
        # 查表成功，直接返回记录表列表参数 knownResults 中的最优解，不再向下递归
        return knownResults[change]
    else:
        # 使用列表推导式筛选出可用硬币面值并遍历每个硬币面值变量 i
        for i in [c for c in coinValueList if c <= change]:
            # 减小规模，递归调用 recDC() 函数自身，同时传入记录表列表参数 knownResults
            numCoins = 1 + recDC(coinValueList, change - i, knownResults)
            if numCoins < minCoins:
                minCoins = numCoins
                # 找到当前规模的最优解，通过列表索引记录到列表参数 knownResults 中
                knownResults[change] = minCoins
    # 返回当前找零金额的最少硬币数变量 minCoins
    return minCoins

# 调用 recDC() 函数，传入通过列表重复运算 [0]*64 创建的长度为 64 的初始记录表列表，并调用内置函数 print() 打印结果
print(recDC([1, 5, 10, 25], 63, [0] * 64))
```

## 改进后的性能对比
改进后的解法，极大减少了递归调用次数。 对 63 分兑换硬币问题，仅仅需要 `221` 次递归调用，是改进前的三十万分之一，瞬间返回！

> [!tips] 记忆化递归与动态规划的衔接
> 
> 这种在递归自顶向下分解问题的过程中，利用列表或字典缓存子问题计算结果（查表避免重复递归）的方法，在算法设计中称为**记忆化搜索（Memoization）**。
