# 抽象与实现
## 计算机科学研究什么
计算机科学不仅仅是对计算机的研究，虽然计算机是非常重要的计算工具。
计算机科学主要研究的是**问题、问题解决过程，以及问题的解决方案**。
其研究内容包括前述的 [[104~105.算法与计算复杂性#计算复杂性 (Computational Complexity)|计算复杂性理论]]，以及对算法的研究。

## 什么是抽象和实现
### 抽象的引入
为了更好地处理**机器相关性或独立性**，引入了==“抽象”==的概念。
抽象是一种工具，用以从==逻辑（Logical）==或者==物理（Physical）==的不同层次上看待问题及解决方案。
### 例子：汽车
从司机的角度看汽车，只需掌握方向盘、油门、刹车、档位这些**接口（Interface）**，操纵这些装置来达到运输的目的即可，无需了解内部构造，这是汽车的==“逻辑”==层次。
从汽车修理工的角度看同一辆汽车则相当不同，他还需要清楚每项功能是如何实现的，如发动机工作原理、档位操作的机械结构、发动机舱内各处温度如何测量和控制等等。
这些内部构造构成了汽车的==“物理”==层次，其工作过程就称为**实现（Implementation）**。
>[!notes] 
>**逻辑相对于物理，接口对应于实现。抽象也对应于具体的实现。**
>逻辑层回答“怎么用”，物理层回答“怎么做”；抽象不是凭空而来，它总是落在某个具体实现之上，与“接口↔实现”一一对应。

### 例子：计算机
从一般大众用户的观点看来，计算机可以用来编辑文档、收发邮件、上网聊天、处理照片等等，并不需要具备计算机内部如何处理的知识。利用这些功能，是计算机的==“逻辑”==层次。
而对于计算机科学家、程序员、技术支持、系统管理员来说，就必须了解从硬件结构、操作系统原理到网络协议等各方面的低层次细节。内部如何实现，是计算机的==“物理”==层次。
![[file-20261026160227866.png|321]]
### 抽象发生在各个不同层次上
即使对于程序员来说，使用编程语言进行编程也会涉及==“抽象”==。
以计算一个数的平方根为例，程序员可以直接调用库函数 `math.sqrt()` 得到结果，而无需关心其内部如何实现。

```python
>>> import math
>>> math.sqrt(16)
4.0
```

这种功能上的“黑盒子”称作**过程抽象（Procedural Abstraction）**，即把“怎么做”封装进函数，调用者只关心“做什么”。
黑盒模型

## 抽象与实现：编程
编程是通过一种程序设计语言，将**抽象的算法**实现为计算机**可以执行的代码**的过程。
没有算法，编程无从谈起。

**编程即算法的实现。**
算法是抽象层，代码是物理实现层，编程就是把前者落地为后者的动作。

图灵奖获得者、Pascal 语言设计者 Niklaus Wirth 提出著名公式：
**算法 + 数据结构 = 程序**
此公式相当于物理中的 $E=mc^2$。
## 程序设计语言实现算法的基本机制
程序设计语言需要为算法的实现提供实现==“过程”==和==“数据”==的机制，具体表现为**控制结构**和**数据类型**。
程序设计语言均有语句对应控制结构：顺序处理、分支选择、循环迭代。
![[file-20261026160519995.png|254]]

程序设计语言也提供最基本的数据类型来表示数据，如整数、字符等。
但对于复杂的问题而言，直接使用这些基本数据类型不利于算法的表达。
![[file-20261026160701209.png|243]]

# 为什么研究数据结结构和算法？
## 清晰高效地表达算法
为了控制问题和问题解决过程的复杂度，利用抽象来保持问题的“**整体感**”，而不会陷入到过多的细节中去。
这要求对现实问题建模时，对算法所要处理的**数据**，也要保持与问题本身的一致性，不要有太多与问题无关的细节。

问题自顶向下逐层分解
![[file-20261026160942438.png|267]]
## 数据抽象：ADT 抽象数据类型
“**过程抽象**”启发我们进行“**数据抽象**”。
相对于程序设计语言中的基本数据类型，**抽象数据类型**（ADT，Abstract Data Type）是对数据进行处理的一种**逻辑描述**，并不涉及如何实现这些处理。

抽象数据类型 ADT 建立了一种对数据的“**封装**（Encapsulation）”。
封装技术将可能的处理实现细节隐蔽起来，能有效控制算法的复杂度。

在 ADT 模型中，用户（User）经由接口（Interface）上的操作（Operations）与数据交互，实现（Implementation）则被隐藏在内部。
![[file-20261026161054978.png|199]]
## 数据结构是对 ADT 的具体实现
同一 ADT 可以采用不同的数据结构来实现。

采用程序设计语言的**控制结构**和**基本数据类型**来实现 ADT 所提供的**逻辑接口**，属于 ADT 的“==物理==”层次。
![[file-20261026161309216.png|257]]
对数据实现“逻辑”层次和“物理”层次的**分离**，可以定义复杂的数据模型来解决问题，而不需要立即考虑此模型如何实现。

## 接口的两端：抽象与实现
### 同一接口、多种实现
以电动车与汽油车为例：底层动力、能源都不同，但开车的操作接口（方向盘、油门、刹车、档位）基本相同。司机无需重新考驾照，而车厂可以持续改进实现技术。
由于对抽象数据类型可以有多种实现方案，需要建立**独立于实现的数据模型**。
让底层开发程序员专注于实现和优化数据处理，又不改变数据的使用接口。
让用户专注于用数据接口来进行问题的解决，而无需考虑如何具体实现这些接口。
通过**层层抽象**，降低问题解决过程的复杂度。
# 小结
## 抽象与实现的关系

>[!tips] 贯穿全课的三对二元关系
>**逻辑↔ 物理**：司机看到的功能 ↔ 修理工看到的内部构造。
>**接口↔ 实现**：方向盘油门 ↔ 发动机变速箱。
>**抽象 ↔ 具体实现**：算法 / ADT ↔ 代码 / 数据结构。
>
>两大抽象机制：过程抽象（函数黑盒，如 `math.sqrt()` 函数）与数据抽象（ADT 封装，隐藏实现细节）。

**抽象**：抛弃与当前问题无关的信息，抛弃底层的具体实现细节。
**实现**：针对具体应用环境，用某种特定的技术让逻辑功能“落实”。

先抽象再实现的好处在于解耦与关注点分离：
抽象阶段专注于“做什么（What）”，定义清晰的问题模型；
实现阶段专注于“怎么做（How）”，保持接口契约的长期稳定性。
## 面向过程与面向对象：抽象层次的演进
### 过程抽象（面向过程）
面向过程的设计核心是“属性编码，过程抽象”。
代码将现实数据降维抽象为基本容器（如列表），通过一系列独立的全局函数进行操作：
```python
# 属性编码为列表
alist = [76, 83.5, 90, 95, 86, 84, 84, 84]

# 调用独立的函数进行数据处理
average(alist)              # average() 函数
median(alist)               # median() 函数
normal_distribution(alist)  # normal_distribution() 函数
```
**面向过程直接面向数据处理，忽略了业务领域本身的语义结构，优先追求通用算法与底层的纯粹计算性能。**
### 数据抽象（面向对象）
面向对象的设计核心是“实体抽象接口化，数据抽象”。 将数据属性与对数据的操作绑定在一起封装为类，对外提供稳定的交互接口：

```Python
# 定义课程成绩类
class CourseGrade:
    def __init__(self, raw_score):
        self.raw_score = raw_score # 成绩属性

    def average(self): # 实例方法：计算平均分
        pass

    def median(self): # 实例方法：计算中位数
        pass

    def normal_distribution(self): # 实例方法：正态分布计算
        pass

# 调用 CourseGrade() 类（构造器）实例化对象
myclass = CourseGrade([76, 83.5, 90, 95])

# 调用对象内部的实例方法
myclass.average()
myclass.median()
myclass.normal_distribution()
```

为什么面向对象要“尽量把具体实现推后”？
面向对象直接面向问题领域建模。推迟底层存储结构与算法细节的绑定（Late Binding），使得上层业务能够保持高度的灵活性和多态适应性。
虽然带来了微小的封装开销，却换取了更强的可维护性与现实语义保真度。
