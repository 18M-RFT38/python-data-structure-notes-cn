# 插入排序（Insertion Sort）

## 算法核心思路
插入排序的时间复杂度仍然是 $O(n^2)$，但算法思路与[[503.冒泡排序和选择排序算法及分析]]不同。

插入排序维持一个已排好序的子列表，其位置始终在列表的前部，然后逐步扩大这个子列表直到全表。
![[file-20261108144128917.png|142]]
>[!tips] 扑克牌理牌模型
>想象整体扑克牌总是从左到右排列。
>握持的是前部已经排好序的牌堆（有序子列表），右边是没有排好的散牌（无序区）。
>每次从右边乱牌当中找到一张牌作为“新项”，在前面已经排好的牌堆中从右向左比对找到它应该插入的合适位置，将比它大的牌往后挪腾出空位，最后在正确的位置插入。
## 多趟执行机制
第 1 趟：子列表仅包含第 1 个数据项，将第 2 个数据项作为“新项”插入到子列表的合适位置中，这样已排序的子列表就包含了 2 个数据项。

第 2 趟：再继续将第 3 个数据项跟前 2 个数据项比对，并移动比自身大的数据项，空出位置来，以便加入到子列表中。

排序完成条件：经过 $n-1$ 趟比对和插入，子列表扩展到全表，排序完成。
![[file-20261108144231838.jpeg|197]]
### 单趟空位移动机制示例
以有序子列表 `[17, 26, 54, 77, 93]` 插入新项 `31` 为例：

首先将新项 `31` 提取暂存，原位置留出空位。

接着自右向左依次比对并移动所有比“新项”大的数据项：
$93 > 31$，将 `93` 向右移动一格覆盖空位。
$77 > 31$，将 `77` 向右移动一格。
$54 > 31$，将 `54` 向右移动一格。
$26 < 31$，比对停止，将新项 `31` 插入到当前空位（原 `54` 所在的位置）。
![[file-20261108144250077.jpeg|229]]
## Python 代码实现

`insertionSort()` 函数：接收待排序列表变量 `alist`，通过原地单向移动元素并插入新项实现升序排序。
`len()` 内置函数：返回列表 `alist` 的元素总个数。
`range()` 内置类（构造器）：生成从索引 `1` 到 `len(alist) - 1` 的不可变整数序列，依次提供每趟待插入新项的下标。
```python
def insertionSort(alist):
    # range() 类（构造器）：生成从 1 到 len(alist)-1 的索引序列，第 0 项默认作为初始有序子列表
    for index in range(1, len(alist)):
        currentvalue = alist[index]  #局部变量（属性）：暂存本趟待插入的新项/插入项数值
        position = index             #局部变量（属性）：记录当前空位所在的索引位置

        # 内层循环：自右向左比对，移动所有比“新项”大的数据项
        while position > 0 and alist[position - 1] > currentvalue:
            alist[position] = alist[position - 1]  # 元素单向右移（仅 1 次赋值操作）
            position = position - 1                # 空位索引向前递减

        # 找到合适位置后，将新项写入最终空位
        alist[position] = currentvalue
```
## 算法复杂度与性能分析
比对目的：插入排序的比对主要用来寻找“新项”的插入位置。

最差情况：待排列表完全逆序，每趟都与子列表中所有项进行比对，总比对次数与冒泡排序相同（$\frac{1}{2}n^2 - \frac{1}{2}n$），数量级仍是 $O(n^2)$。

最好情况：列表已经排好序的时候，每趟仅需 1 次比对即可确认无需移动，总比对次数是 $O(n)$。
> [!notes] 移位操作相对于交换操作的性能优势
> 
> 由于单向移动操作（`alist[position] = alist[position - 1]`）每次仅包含 1 次赋值，是冒泡排序交换操作（3 次赋值）开销的 $1/3$，所以插入排序的实际运行性能会比冒泡排序更好一些。
> 
>   
# 谢尔排序 / 希尔排序（Shell Sort）
## 算法改进思路
插入排序的比对次数在最好的情况下是 $O(n)$，这种情况发生在列表已是有序的情况下。
实际上，列表越接近有序，插入排序的比对次数就越少。
  
从这个情况入手，谢尔排序以插入排序作为基础，对无序表进行“间隔（Gap / Increment）”划分子列表，每个子列表都分别执行插入排序。
![[file-20261108170221325.png|282]]

随着子列表的数量越来越少（间隔逐步缩小），无序表的整体越来越接近有序，从而大幅减少整体排序的比对次数。

当取间隔为 3 时，3 个子列表分别执行插入排序后，整体状况更加接近有序。
  ![[file-20261108170431960.png|314]]
## 间隔设定策略与收尾过程
子列表的间隔一般从 $n/2$ 开始，每趟缩小一半（子列表元素成倍增加）：$n/2, n/4, n/8 \dots$ 直到间隔变为 $1$。

以长度 $n = 9$ 的列表为例： 
当取间隔为 4（$9 // 2 = 4$）时，分为 4 个独立子列表分别进行插入排序： 
sublist 1（索引 0, 4, 8）：`[54, 77, 20]` 
sublist 2（索引 1, 5）：`[26, 31]` 
sublist 3（索引 2, 6）：`[93, 44]` 
sublist 4（索引 3, 7）：`[17, 55]`
![[file-20261108170858165.png|293]]


最后一趟（间隔为 1）：这是标准的插入排序，但由于前面几趟已经将列表处理到接近有序，这一趟仅需少数几次移动即可完成
（例如上述间隔为 3 处理后的列表，在最后一趟中仅需为 `20` 移动 1 次、为 `31` 移动 2 次、为 `54` 移动 1 次，共 4 次移动即完成整表排序）。
![[file-20261108171228914.png|274]]
## Python 代码实现
`shellSort()` 函数：主控函数，负责设定初始间隔

`sublistcount`、循环调用子列表排序函数并逐趟折半缩小间隔。
`gapInsertionSort()` 函数：辅助函数，接收原列表

`alist`、子列表起始索引 `start` 以及步长间隔 `gap`，对特定子列表执行带步长的插入排序。`print()` 内置函数：输出每趟间隔排序完成后的列表状态。
```Python
def shellSort(alist):
    sublistcount = len(alist) // 2  # 局部变量：初始间隔设定为列表长度的一半（亦即子列表个数）
    while sublistcount > 0:

        # range() 类（构造器）：遍历每个子列表的起始偏移位置 startposition
        for startposition in range(sublistcount):
            # 调用 gapInsertionSort() 函数：对当前子列表进行带间隔的插入排序
            gapInsertionSort(alist, startposition, sublistcount)

        # print() 内置函数：打印本趟间隔排序后的中间结果
        print("After increments of size", sublistcount,
              "The list is", alist)

        sublistcount = sublistcount // 2  # 间隔缩小：整除 2 进入下一趟

def gapInsertionSort(alist, start, gap):
    # range() 类（构造器）：从子列表的第 2 个元素 start+gap 开始，以 gap 为步长跳跃遍历
    for i in range(start + gap, len(alist), gap):

        currentvalue = alist[i]  # 局部变量：暂存子列表当前待插入的新项
        position = i             # 局部变量：记录当前空位在原列表中的真实索引

        # 在子列表内部自右向左跳跃比对（步长为 gap），移动比新项大的元素
        while position >= gap and alist[position - gap] > currentvalue:
            alist[position] = alist[position - gap]  # 子列表前序元素向后跨越 gap 个位置覆盖
            position = position - gap                # 空位索引向前跳跃递减 gap

        # 将新项插入子列表的正确空位
        alist[position] = currentvalue
```

> [!question] 为什么 `gapInsertionSort` 的循环是从 `start + gap` 开始，且条件为 `position >= gap`？
> 
> 在子列表中，索引 `start` 是该子列表的**第 1 项**（默认自身构成长度为 1 的有序子列表），而 `start + gap` 才是该子列表的**第 2 项**（即第一个需要向前比对插入的“新项”）。
> 
> 因为内层 `while` 循环后续执行的是 `position - gap`（使第二项与第一项进行比较），为了防止索引越界变成负数，左边界保护条件必须对应设定为 `position >= gap`。当 `start = 0` 且 `gap = 1` 时，这段代码就完全退化还原为标准的 `insertionSort()` 函数。
> 
>   

## 算法复杂度分析
粗看上去，谢尔排序以插入排序为基础，似乎并不会比插入排序好。但由于每趟都使得列表更加接近有序，这过程会减少很多原先需要的“无效”比对。

时间复杂度范围：对谢尔排序的详尽数学分析比较复杂，大致介于 $O(n)$ 和 $O(n^2)$ 之间。

间隔序列优化：如果将间隔保持在 $2^k - 1$（如 $1, 3, 5, 7, 15, 31 \dots$ 等递增间隔序列），谢尔排序的时间复杂度约为 $O(n^{3/2})$
（即 $O(n^{\frac{3}{2}})$）
