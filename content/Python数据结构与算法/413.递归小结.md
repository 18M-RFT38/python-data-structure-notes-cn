# 递归算法的核心特征与三定律
## 什么是递归
递归是一种解决问题的方法，其精髓在于将复杂问题分解为规模更小的 **相同问题**。
递归算法通过持续分解，直到问题规模缩小到可以用极其简单直接的方式解决。
递归在程序表达上的核心特征是：在算法流程中 **调用自身** [[401.什么是递归#什么是递归|什么是递归]]。
从本质上看，递归是解决某些具有 **自相似性（Self-similarity）** 的复杂问题的有效技术。
## 递归“三定律”
为了规范递归算法的闭环设计，计算机科学家总结出了递归算法必须严格遵循的“三定律” [[401.什么是递归#递归“三定律”|递归“三定律”]]：
### 第一定律：必须具备基本结束条件（Base Case）
递归算法必须具备一个或多个 **基本结束条件**，用于直接返回最小规模问题的确定解，防止程序陷入无限递归与调用栈溢出（Stack Overflow）。
### 第二定律：必须改变状态向基本结束条件演进
递归算法在每次执行时，必须缩小待解决问题的规模，改变内部状态，确保算法能够在有限步骤内向基本结束条件持续演进。
### 第三定律：必须调用自身
递归算法必须在缩小了规模的相同问题上重新调用自身，将子任务的求解过程委托给底层的递归机制。

>[!notes] 递归思维与数学归纳法
>理解递归逻辑的关键在于摆脱人脑对底层压栈出栈微观细节的穷举，建立宏观数学等式。
>递归是 **数学归纳法** 在程序设计中的逆向运用：
>1. 基础步骤（Base Case）对应递归的基本结束条件；
>2. 归纳假设（Inductive Hypothesis）对应坚信子递归能够正确完成更小规模的任务（黑盒外包）；
>3. 归纳递推（Inductive Step）对应单层函数内部基于子问题解完成当前步的业务拼接。
# 递归与迭代的对比及局限
## 递归与迭代循环的关系
在绝大多数计算场景下，递归与循环迭代是可以相互等价转换的。
某些情况下，递归可以完全代替循环迭代来控制程序的执行流程。
递归算法的代码表达通常能够与数学定义及问题的自然表达高度契合，逻辑精炼直观，能够大幅简化复杂自相似问题（如树的遍历、分形图形绘制、分治查找）的代码量。
## 递归调用的底层代价与局限
递归不总是最合适的算法。
函数递归调用依赖系统底层的 **调用栈（Call Stack）** 来保存每一层的局部变量、形参以及函数返回地址。
过深的递归层级会导致调用栈深度过大，面临栈溢出风险。
更为严峻的问题在于，未经优化的纯递归算法在处理具有重叠子结构的问题时，会引发 **巨量的重复计算**。
例如在无缓存的**斐波那契数列计算与找零兑换问题**的纯递归解法中，相同的子状态会被反复展开计算，导致算法的时间复杂度从多项式阶陡增至指数级阶 $O(2^n)$。
# 记忆化与函数值缓存
## 解决重复计算的利器
针对递归调用中产生的大量重复子问题，**记忆化（Memoization）** 是一种以空间换时间的典型优化策略。
“**记忆化/函数值缓存**”的核心机制在于开辟额外的辅助存储空间，在递归执行过程中记录已经计算过的中间子问题结果。
当后续递归分支再次进入相同的子问题时，不再重复展开递归树，而是直接查表读取已缓存的结果返回，从而有效消除冗余计算。
## 缓存机制的实现形式
在算法实现中，记忆化缓存通常有两种常见方式：

**手动构建备忘录（Lookup Table）**
在递归函数外层或作为参数传入一个 Python 内置的 `dict` 字典类或 `list` 列表类实例对象。
在每次递归执行计算前，先通过条件分支检索当前参数是否存在于字典中；若已存在则直接返回缓存值，若不存在则在计算得出结果后将其写入字典。

**标准库装饰器函数**自动化缓存
Python 标准库 `functools` 模块提供了 `@lru_cache` 装饰器函数。
@lru_cache(maxsize=None)装饰器会挂载到下方的函数上，为它提供无限容量的备忘录缓存，避免重复计算相同的子状态。
通过修饰递归函数，系统底层会自动利用 **最近最少使用（LRU）** 缓存算法管理函数调用入参与返回值的映射关系，无侵入式地消除重复计算。
```python
from functools import lru_cache

# 调用 functools 模块提供的 lru_cache() 装饰器函数对递归函数进行自动化记忆化缓存。
@lru_cache(maxsize=None)
def fib(n: int) -> int:
    # 递归第一定律：基本结束条件
    if n < 2:
        return n
    # 递归第二与第三定律：减小规模并调用自身
    return fib(n - 1) + fib(n - 2)
```

>[!tips] 从记忆化递归到动态规划
>如果一个问题的**最优解由其规模更小的相同问题的最优解构成**，并且具备大量重叠子问题，那么通过**记忆化递归消除重复计算的思路**，正是通往 **动态规划（Dynamic Programming）** 的关键桥梁。
>记忆化递归属于 **自顶向下（Top-Down）** 的带备忘求解，而标准动态规划通常采用 **自底向上（Bottom-Up）** 的递推填表。
# 贪心策略与动态规划的本质区别
## 贪心策略的核心特征
贪心算法/ [[408.优化问题：贪心策略|贪心策略]]（Greedy Strategy）在每一步决策时，都采取当前状态下看起来最好的选择。
贪心算法要求问题具备 **“贪心选择性质”**，即 **“局部最优等同于总体最优”**。
在执行流程上，贪心策略遵循“尽量大步”推进的原则，每一步仅依赖于当前已做出的**局部选择**，一旦选定**绝不回溯，单向直达最优解**。
## 动态规划的核心特征
 [[411.动态规划：找零问题|动态规划]]（Dynamic Programming）要求问题具备 **“最优子结构”**，即 **“问题最优解包括规模更小相同问题的最优解”**。
动态规划在决策时，绝不轻率地仅凭当前一步的局部指标做定论，而是必须综合权衡所有可能前驱规模更小子问题的最优解。
在执行流程上，动态规划通过**构建状态转移表**（一维数组或二维网格矩阵），系统性地记录所有子问题的最优状态，并通过**填表与回溯**（如二维矩阵网格中根据状态转移箭头回溯）得出**真正的全局最优解**。
## 二者的核心差异对比
**决策依据**：贪心算法仅依赖**当前规模较小的局部最优解**做出**单向抉择**；
动态规划则依赖于所有**规模更小的子问题最优解的全局状态空间**。

**回溯能力**：贪心算法一旦步进决策则**不提供回溯机制**；
动态规划记录了**完整子状态空间**，通过状态转移表能够回溯出达到全局最优解的具体决策路径。

**适用条件严格度**：贪心算法成立的条件极其苛刻，要求局部最优必须能严格推导出总体最优（如特定整倍数货币面额下的硬币兑换）；**当局部最优无法保证总体最优时（如含有特定面额 `[1, 5, 10, 21, 25]` 的找零问题），贪心策略会失效**，必须使用动态规划遍历最优子结构。
# 动态规划的适用范围与反例分析
## 动态规划的三大适用特征
一个最优化问题能否有效采用动态规划进行求解，取决于其是否严格满足以下三个核心前提条件：
### 最优子结构（Optimal Substructure）
问题的最优解包含**子问题的最优解**。
若**无法通过规模更小的相同问题的最优解推导出当前问题的最优解**，则动态规划的状态转移方程无法建立。
### 无后效性（No Aftereffect）
当前阶段的状态仅**由以前阶段决定**；
**后续阶段状态的变化绝对不会反过来影响当前阶段**已经确定的状态。
即“未来只取决于现在，与过去如何到达现在无关”。
### 重叠子问题（Overlapping Subproblems）
在求解问题的分解过程中，子问题存在大量重叠（冗余计算）。
动态规划正是通过表格记录子问题解，避免了重复计算，这也是动态规划效率显著优于朴素递归的根源所在。
## 典型反例：无权图的最长简单路径问题
并非所有具有子结构分解形式的问题都能使用动态规划，最典型的不可用反例是无向图中的 **最长简单路径问题（Longest Simple Path Problem）**。

考虑由四个顶点组成的无向简单环图：顶点 $A, B, C, D$ 连成闭环（$A-B, B-C, C-D, D-A$）。
求从节点 $A$ 到节点 $C$ 的最长简单路径（路径中不包含重复顶点）。

![[file-20261106220316407.png|420]]


显然，从 $A$ 到 $C$ 的最长简单路径长度为 2（可以是 $A \to D \to C$ 或 $A \to B \to C$）。
假设选择经过 $B$ 的路径，该路径为 $A \to B \to C$。

然而，这条最长路径 **并不一定包含从 $A$ 到 $B$ 的最长简单路径**。
因为如果单独考察从 $A$ 到 $B$ 的最长简单路径，其结果应当是 $A \to D \to C \to B$（长度为 3）；但如果把这段最长子路径代入到 $A$ 到 $C$ 的整体路径中，由于子路径已经占用了目标节点 $C$ 和中间节点 $D$，从 $B$ 出发就无法在不重复经过顶点的前提下再走到 $C$。

子问题之间存在顶点互斥与资源竞争，严重破坏了 **最优子结构** 与 **无后效性**，因此最长简单路径问题无法使用动态规划求解，属于 NP-Hard 难题。

>[!attention] 最长路径与最短路径的本质区别
>**最短路径问题** 具备严格的最优子结构与无后效性（两点间最短路径的任意子路径必定也是对应两点的最短路径，不会产生顶点排他冲突），因此可以使用 Dijkstra 贪心算法或 Floyd-Warshall 动态规划算法求解；
>而 **最长简单路径** 因顶点不可重复访问导致子问题互相依赖，彻底破坏了无后效性。
