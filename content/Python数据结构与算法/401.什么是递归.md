# 什么是递归（Recursion）
递归是一种解决问题的方法，其精髓在于将问题分解为规模更小的 **相同问题**。
持续分解，直到问题规模小到可以用 **非常简单直接的方式** 来解决。
递归的问题分解方式非常独特，其算法方面的明显特征就是：在算法流程中 **调用自身** [[12.代码组织#定义和调用函数|函数的定义与调用]]。
递归为我们提供了一种对复杂问题的优雅解决方案，精妙的递归算法常会出奇简单，令人赞叹。

# 初识递归：数列求和
## 迭代求和与无循环设问
**问题定义**：给定一个列表，返回所有数的和。
列表中数的个数不定。
常规思路需要一个循环语句和一个累加变量来迭代求和。
```python
# 定义列表求和函数 listsum()，接收列表参数 numList
def listsum(numList):
    # 定义局部累加变量 theSum 并初始化为 0
    theSum = 0
    # 使用 for 循环遍历列表参数 numList 中的每一个元素变量 i
    for i in numList:
        theSum = theSum + i
    # 返回累加求和结果变量 theSum
    return theSum

# 调用 listsum() 函数计算列表元素之和，并调用内置函数 print() 输出结果
print(listsum([1, 3, 5, 7, 9]))
```

>[!question] 思考：假如不能用循环语句？
>程序很简单，但如果既不能用 `for` 循环，也不能用 `while` 循环 [[11.控制流程#循环结构|循环结构]]，还能对 **不确定长度** 的列表求和么？
## 递归思路转化
我们认识到求和实际上最终是由一次次的 **加法运算** 实现的，而加法恰有 **2个操作数**，这个是确定的。
因此可以想办法将问题规模较大的列表求和，分解为规模较小而且固定的 **2个数求和（加法）**。

同样是求和问题，但规模发生了变化，完全符合递归解决问题的特征。

换个方式来表达数列 `[1, 3, 5, 7, 9]` 求和，可写成 **全括号表达式** `(1+(3+(5+(7+9))))`。
上面这个式子中，最内层的括号 `(7+9)` 是无需循环即可直接计算的，实际上整个求和的计算过程如下：
![[file-20261030191258683.png|316]]
观察上述过程中所包含的重复模式，可以把求和问题归纳成如下形式：
**数列的和 = “首个数” + “余下数列”的和**
如果数列包含的数少到 **只有1个** 的话，它的和就是这个数本身，这时规模小到可以做**最简单的直接处理**。（如返回）

## 递归求和程序实现
将上面的递归算法转化为 Python 程序：
```python
# 定义递归求和函数 listsum()，接收列表参数 numList
def listsum(numList):
    # 基本结束条件（最小规模）：调用内置函数 len() 获取列表参数 numList 的长度，判断是否为 1
    if len(numList) == 1:
        # 访问列表索引 numList[0] 直接返回唯一元素的值
        return numList[0]
    # 减小规模并调用自身
    else:
        # 访问首元素 numList[0]，与调用 listsum() 函数自身处理切片新列表 numList[1:] 的返回值相加
        return numList[0] + listsum(numList[1:])

# 调用 listsum() 函数传入测试列表，并调用内置函数 print() 打印返回值
print(listsum([1, 3, 5, 7, 9]))
```

### 递归程序的两个核心要点
**调用自身**：问题分解为 **更小规模** 的相同问题，在代码中表现为函数内部调用 `listsum()` 函数自身。
**最小规模直接解决**：对 **最小规模** 问题（列表长度为 `1`）的解决简单直接，无需继续递归即可直接返回 `numList[0]`。

>[!notes] Python 列表切片语法说明
>代码中 `numList[1:]` 使用了列表的 **切片操作** [[6.容器类型#切片|列表与切片]]（非函数或方法调用），作用是从索引 `1` 开始截取至列表末尾，返回一个去掉了首元素 `numList[0]` 的新列表对象，从而使问题规模减少 `1`。

# 递归程序如何被执行
## 递归函数调用和返回过程的链条
递归程序的执行过程由 **层层分解调用（递推）** 和 **层层回溯返回（回归）** 两个阶段的链条组成。
![[file-20261030191502170.png|293]]
### 第一阶段：层层向下调用（递推分解）
调用 `listsum([1, 3, 5, 7, 9])` 函数，分解为 `1 + listsum([3, 5, 7, 9])`。
调用 `listsum([3, 5, 7, 9])` 函数，分解为 `3 + listsum([5, 7, 9])`。
调用 `listsum([5, 7, 9])` 函数，分解为 `5 + listsum([7, 9])`。
调用 `listsum([7, 9])` 函数，分解为 `7 + listsum([9])`。
调用 `listsum([9])` 函数，触发 `len(numList) == 1` 基本结束条件，直接确定结果为 `9`。
### 第二阶段：层层向上返回（回溯计算）
`listsum([9])` 函数返回 `9` 给上一层，计算 `7 + 9` 得到 `16`。
`listsum([7, 9])` 函数返回 `16` 给上一层，计算 `5 + 16` 得到 `21`。
`listsum([5, 7, 9])` 函数返回 `21` 给上一层，计算 `3 + 21` 得到 `24`。
`listsum([3, 5, 7, 9])` 函数返回 `24` 给最外层，计算 `1 + 24` 得到 `25`。
最外层 `listsum([1, 3, 5, 7, 9])` 函数最终返回总和 `25`。
# 递归“三定律”
## 递归算法的核心定律
为了向阿西莫夫的“机器人三定律”致敬，递归算法也总结出 **“三定律”**：
**第一定律（基本结束条件）**：递归算法必须有一个 **基本结束条件**（最小规模问题的直接解决）。
**第二定律（状态演进）**：递归算法必须能改变状态向基本结束条件 **演进**（减小问题规模）。
**第三定律（调用自身）**：递归算法必须 **调用自身**（解决减小了规模的相同问题）。
## 结合数列求和问题解析“三定律”
### 基本结束条件
数列求和问题首先具备了 **基本结束条件**：当通过 `len()` 内置函数判断列表长度为 `1` 的时候，直接输出列表所包含的唯一数 `numList[0]`。
### 向基本结束条件演进
数列求和处理的数据对象是一个 **列表**，而基本结束条件是长度为 `1` 的列表，因此递归算法就要改变列表并向长度为 `1` 的状态 **演进**。
具体做法是通过列表切片 `numList[1:]` 每次将列表长度减少 `1`。
### 调用自身
**调用自身** 是递归算法中最难理解的部分，实际上将其理解为 **“问题分解成了规模更小的相同问题”** 即可。
在数列求和算法中，调用 `listsum(numList[1:])` 函数自身就代表解决 **“更短数列的求和问题”**。
>[!attention] 递归边界与异常注意
>1. **缺少基本结束条件或状态未演进**：如果忘记编写 `if len(numList) == 1:` 分支，或者递归调用时传入的仍是原列表 `numList` 而非切片后的 `numList[1:]`，函数将无限调用自身，最终耗尽调用栈空间并抛出 `RecursionError` 异常类实例。
>2. **空列表边界扩展**：课件中的基础实现假设输入列表至少包含 `1` 个元素；若考虑传入空列表 `[]` 的防御性编程，可补充 `if len(numList) == 0: return 0` 作为空输入的基本结束条件。
