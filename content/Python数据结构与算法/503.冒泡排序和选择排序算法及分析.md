# 冒泡排序（Bubble Sort）
## 算法思路与流程
冒泡排序的算法思路在于对无序表进行 **多趟（Pass）比较交换**。
每趟包括了多次 **两两相邻比较**，并将逆序的数据项互换位置，最终能将本趟的 **最大项就位**。
经过 $n-1$ 趟比较交换，实现整表排序。
每趟的过程类似于“气泡”在水中不断上浮到水面的经过。
### 多趟递减机制
1. **第 1 趟比较交换**：共有 $n-1$ 对相邻数据进行比较。一旦经过最大项，则最大项会一路交换到达最后一项（下标 $n-1$ 处）。
2. **第 2 趟比较交换**：最大项已经就位，需要排序的数据减少为 $n-1$，共有 $n-2$ 对相邻数据进行比较。
3. **第 $n-1$ 趟完成**：最小项一定在列表首位，就无需再处理了。

## 代码实现（`bubbleSort`）
```python
def bubbleSort(alist): # 定义冒泡排序函数，接收待排序列表 alist
    # 调用 range() 函数生成从 len(alist)-1 递减到 1 的序列，控制执行 n-1 趟
    for passnum in range(len(alist) - 1, 0, -1):
        # 调用 range() 函数遍历 0 到 passnum-1，控制本趟相邻比对的下标
        for i in range(passnum):
            # 比较相邻两个数据项，判断是否为逆序（前项大于后项）
            if alist[i] > alist[i + 1]:
                # 序错，借助临时变量 temp 交换两个相邻元素的位置（3次赋值）
                temp = alist[i]
                alist[i] = alist[i + 1]
                alist[i + 1] = temp

alist = [54, 26, 93, 17, 77, 31, 44, 55, 20]
# 调用 bubbleSort() 函数对列表进行原地排序
bubbleSort(alist)
print(alist) # 输出: [17, 20, 26, 31, 44, 54, 55, 77, 93]
```

>[!tip] Python 语法特性补充
>1. **直接交换**：Python 支持利用元组解包直接互换变量，可将三行交换代码简化为一行：
>   `alist[i], alist[i + 1] = alist[i + 1], alist[i]`
>2. **可视化辅助**：可通过算法可视化网站 `https://zh.visualgo.net/sorting` 动态观察排序过程。
## 算法分析
### 1. 比对次数与时间复杂度
无序表初始数据项的排列状况对基础冒泡排序的比对次数 **没有影响**。
算法过程总需要 $n-1$ 趟，随着趟数的增加，**比对** 次数逐步从 $n-1$ 减少到 $1$，并包括可能发生的数据项 **交换**。
比对次数是 $1 \sim n-1$ 的累加：
$$\sum_{i=1}^{n-1} i = \frac{1}{2}n^2 - \frac{1}{2}n$$
比对的时间复杂度是 **$O(n^2)$**。
### 2. 交换次数分析
关于交换次数，时间复杂度也是 **$O(n^2)$**，通常每次交换包括 **3 次赋值**。
- **最好情况**：列表在排序前已经有序，交换次数为 **$0$**。
- **最差情况**：每次比对都要进行交换（完全逆序表），交换次数等于比对次数（$\frac{1}{2}n^2 - \frac{1}{2}n$）。
- **平均情况**：是最差情况的一半。
### 3. 综合评价
**劣势（对比基准）**：冒泡排序通常作为时间效率较差的排序算法，来作为其它算法的对比基准。
其效率主要差在每个数据项在找到其最终位置之前，必须要经过 **多次** 比对和交换，其中大部分的操作是 **无效** 的。

**优势（原地排序）**：**无需** 任何额外的存储空间开销，空间复杂度为 $O(1)$。适应性较广，在链表中也可以实现。
# 冒泡排序：性能改进（短路冒泡）
## 提前终止思路
通过监测每趟比对是否发生过交换，可以提前确定排序是否完成（这也是其它多数排序算法无法做到的）。

如果某趟比对 **没有发生任何交换**，说明列表已经排好序，可以 **提前结束算法**。
## 代码实现（`shortBubbleSort`）
```python
def shortBubbleSort(alist): # 定义改进的短路冒泡排序函数
    exchanges = True # 初始化布尔标志位 exchanges 为 True，确保能进入首趟循环
    passnum = len(alist) - 1 # 初始化趟数计数器为 n-1
    # 当还有待排趟数（passnum > 0）且上一趟发生过交换（exchanges 为 True）时继续循环
    while passnum > 0 and exchanges:
        exchanges = False # 每趟开始前，先将交换标志位重置为 False
        # 遍历当前未排序区间进行相邻比对
        for i in range(passnum):
            if alist[i] > alist[i + 1]:
                exchanges = True # 一旦发生逆序交换，将标志位设为 True
                temp = alist[i]
                alist[i] = alist[i + 1]
                alist[i + 1] = temp
        passnum = passnum - 1 # 本趟结束，待排区间长度减 1

alist = [20, 30, 40, 90, 50, 60, 70, 80, 100, 110]
# 调用 shortBubbleSort() 函数测试局部无序列表
shortBubbleSort(alist)
print(alist) 
# 输出: [20, 30, 40, 50, 60, 70, 80, 90, 100, 110]
```

>[!notes] 改进效果
>对于已经有序或接近有序的列表，短路冒泡排序可在 $1$ 趟或极少趟数内提前退出，最好情况下的总时间复杂度可优化至 **$O(n)$**。
>但总的时间复杂度不会被改变。
# 选择排序（Selection Sort）
## 算法思路与改进机制
选择排序对冒泡排序进行了改进，保留了其基本的多趟比对思路，每趟都使当前最大项就位。
但选择排序对交换进行了削减：相比起冒泡排序进行多次交换，选择排序 **每趟仅进行 1 次交换**——在比对过程中仅 **记录最大项的所在位置**，最后再跟本趟最后一项交换。
### 复杂度对比
- **比对次数**：不变，还是 **$O(n^2)$**（依然是 $\frac{1}{2}n^2 - \frac{1}{2}n$ 次比对）。
- **交换次数**：减少为 **$O(n)$**（每趟仅交换 1 次，共 $n-1$ 次）。
- **结论**：选择排序的时间复杂度比冒泡排序稍优（大幅减少了数据赋值的物理开销）。

## 代码实现（`selectionSort`）
```python
def selectionSort(alist): # 定义选择排序函数
    # 外层循环：fillslot 代表本趟最大项需要就位的目标槽位索引（从 len-1 递减到 1）
    for fillslot in range(len(alist) - 1, 0, -1):
        positionOfMax = 0 # 打擂台初始化：先假定索引 0 处的元素是当前扫描范围的最大项
        # 内层循环：location 从索引 1 遍历到目标槽位 fillslot（包含 fillslot）
        for location in range(1, fillslot + 1):
            # 若当前位置元素大于已记录的最大项，则更新最大项的位置索引
            if alist[location] > alist[positionOfMax]:
                positionOfMax = location # 只记录位置下标，不发生列表元素交换

        # 本趟扫描结束后，将最大项 alist[positionOfMax] 与目标槽位 alist[fillslot] 进行 1 次交换
        temp = alist[fillslot]
        alist[fillslot] = alist[positionOfMax]
        alist[positionOfMax] = temp
```

>[!attention] 核心循环边界与“打擂台”逻辑重点解析
>**`for fillslot in range(len(alist) - 1, 0, -1):`（目标槽位倒序递减）**
>   - `fillslot` 表示本趟挑出的最大值要放入的“坑位”。
>   - 第 1 趟放最末尾 `len(alist) - 1`，倒数第 1 趟放到索引 `1`。当索引 `1` 到末尾都排好后，索引 `0` 自然是最小项，因此 `range` 终点写 `0`（左闭右开，实际停在 `1`）。
>  
**`positionOfMax = 0`（打擂台初始化）**
>   - 每一趟开始寻找最大值时，先默认 `0` 号位置的元素是“擂主”，用 `positionOfMax` 记录当前最大值的**索引**。
>
**`for location in range(1, fillslot + 1):`（挑战者遍历区间）**
>   - **为什么从 `1` 开始**：因为 `0` 号位置已经是初始擂主，无需自己和自己比，直接从索引 `1` 开始比对。
>   - **为什么到 `fillslot + 1` 结束**：本趟待排查的范围是索引 `0` 到 `fillslot`。由于 Python 的 `range(start, stop)` **不包含终点 `stop`**，所以必须写成 `fillslot + 1`，才能让 `location` 真正取到 `fillslot` 这个位置。
