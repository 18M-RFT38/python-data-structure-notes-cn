# 快速排序的基本思路
## 核心分治思路 
快速排序（Quick Sort）的思路是依据一个 **“中值”（pivot value，基准值）** 数据项来把数据表分为 **两半**：小于中值的一半和大于中值的一半，然后每部分分别进行 **快速排序（递归）**。 
>[!notes] 什么是“中值”？ 
>中间值/中值：此‘中值’非彼中值，只是被选择出来作为‘参考’的一项数据项。不是中位数，也不是‘中间位置’”。 
>**概念辨析**：课件中的“中值”对应英文 `pivot value`（常译为 **基准值** 或 **支点**）。
>它既不是统计学上刚好排在正中间大小的 **中位数（Median）**，也不代表索引处于正中间的元素，仅仅是被挑选出来作为分界参考标准的一个普通数据项。 

如果希望分裂出的这两半拥有相等数量的数据项，理想情况下应该找到数据表的 **“中位数”**。 
但寻找真正的中位数需要额外的计算开销！要想没有开销，只能随意找一个数来充当 **“中值”**。
比如，直接选取数据表的 **第1个数**。

![[file-20261109144554044.png]]
（例如列表 `[54, 26, 93, 17, 77, 31, 44, 55, 20]` 中，直接将首个数据项 `54` 作为第一个基准值 `first pivot value`）。
## 快速排序的递归三要素 
快速排序采用递归算法实现，其 **“递归三要素”** 如下：

**基本结束条件**：数据表仅有 `1` 个数据项（或为空）时，自然是排好序的。 

**缩小规模**：根据 **“中值”**，将数据表分裂为两半，最好情况是相等规模的两半。 

**调用自身**：将分裂后的两半分别调用自身进行排序（排序的核心基本操作实际上发生在分裂过程中）。 
## 分裂数据表的机制与图示过程 
**分裂数据表的目标**：找到 **“中值”** （在排好序后）最终应处的位置（即分裂点 `split point`）。 

**分裂数据表的手段**：设置左右标
（`leftmark` 左标变量 / `rightmark` 右标变量）。 

在除“中值”外的剩余数据项两端设置左标和右标，左标向右移动，右标向左移动，逐步向中间收敛：
**左标移动规则**：左标一直向右移动，碰到比中值 **大** 的数据项就停止。 
**右标移动规则**：右标一直向左移动，碰到比中值 **小** 的数据项就停止。 
**左右标交换**：当左右标都停止时，把左右标所指的数据项进行 **交换**。 

**终止与中值就位**：交换后继续相对着移动，
直到 **左标移到右标的右侧**
（即 `rightmark < leftmark`，两标相错），
停止移动。
这时 **右标所指位置** 就是“中值”应处的最终位置，将 **“中值”和这个位置的数据项交换** 。 

**分裂完成**：此时左半部所有数据项都比中值小，右半部所有数据项都比中值大。 
## 图示推演过程（以首项 `54` 为中值） 
![[file-20261109145324857.png|274]]
![[file-20261109145438088.png|271]]
初始列表变量为 `[54, 26, 93, 17, 77, 31, 44, 55, 20]`，选定首项 `54` 为中值，`leftmark` 指向 `26`（索引 `1`），`rightmark` 指向 `20`（索引 `8`）。 
**第一轮扫描与交换**：`leftmark` 经 `26 < 54` 向右移至 `93`，因 `93 > 54` 停止；`rightmark` 指向 `20`，因 `20 < 54` 停止。交换 `20` 和 `93`，列表变为 `[54, 26, 20, 17, 77, 31, 44, 55, 93]`。
**第二轮扫描与交换**：继续移动左右标，`leftmark` 越过 `17` 移至 `77`（`77 > 54` 停止）；`rightmark` 越过 `55` 移至 `44`（`44 < 54` 停止）。
交换 `77` 和 `44`，列表变为 `[54, 26, 20, 17, 44, 31, 77, 55, 93]`。 
**第三轮扫描与相错就位**：继续移动，`leftmark` 移至 `77`（索引 `6`，`77 > 54` 停止），`rightmark` 移至 `31`（索引 `5`，`31 < 54` 停止）。此时 `rightmark < leftmark`（两标相错），找到分裂点 `rightmark`（指向 `31`）。交换中值 `54` 和 `31`，列表变为 `[31, 26, 20, 17, 44, 54, 77, 55, 93]`。 
**递归分治**：此时 `54` 已就位（`54 is in place`），对左半部 `[31, 26, 20, 17, 44]`（均 `< 54`）和右半部 `[77, 55, 93]`（均 `> 54`）分别递归执行快速排序。 
# 快速排序Python代码实现 
## 主函数与递归辅助函数 
```python 
#定义快速排序主入口函数 quickSort()，接收待排序列表对象 alist 
def quickSort(alist):
#调用递归辅助函数 quickSortHelper()，内置函数 len() 获取列表长度 
#初始区间为首索引 0 到末索引 len(alist) - 1 
	quickSortHelper(alist, 0, len(alist) - 1) 

# 定义递归辅助函数 quickSortHelper()，接收列表对象 alist 及起止索引变量 first, last 
def quickSortHelper(alist, first, last): 
#基本结束条件：当起始索引小于结束索引时，说明子表至少有2个元素，需要继续分裂排序 
	if first < last: 
#分裂：调用 partition() 分裂函数，返回中值就位后的分裂点索引变量splitpoint
		splitpoint = partition(alist, first, last) 
#递归调用：对分裂点左半部[first, splitpoint - 1]递归调用quickSortHelper() 函数 
		quickSortHelper(alist, first, splitpoint - 1) 
#递归调用：对分裂点右半部分[splitpoint + 1, last]递归调用quickSortHelper()函数 
		quickSortHelper(alist, splitpoint + 1, last) 

# 定义测试列表对象 alist 
alist = [54, 26, 93, 17, 77, 31, 44, 55, 20] 
# 调用 quickSort() 函数对 alist 进行原地排序 
quickSort(alist) 
# 调用内置 print() 函数打印排序后的列表 
print(alist)
```

```python
# 定义分裂函数 partition()，在子区间 [first, last] 内进行原地分裂并返回分裂点索引
def partition(alist, first, last):
    # 选定“中值”：取子区间第一个元素 alist[first] 赋值给基准值变量 pivotvalue
    pivotvalue = alist[first]

    # 左右标初值：左标变量 leftmark 指向中值右侧第一项，右标变量 rightmark 指向子区间末尾项
    leftmark = first + 1
    rightmark = last

    # 定义循环结束标志变量 done，初始设为布尔常量 False
    done = False
    while not done:

        # 向右移动左标：当左标未越过右标，且左标所指元素小于等于中值时，左标右移 1 位
        while leftmark <= rightmark and alist[leftmark] <= pivotvalue:
            leftmark = leftmark + 1

        # 向左移动右标：当右标所指元素大于等于中值，且右标未越过左标时，右标左移 1 位
        while alist[rightmark] >= pivotvalue and rightmark >= leftmark:
            rightmark = rightmark - 1

        # 两标相错就结束移动：若右标移到了左标左侧，将标志变量 done 设为布尔常量 True
        if rightmark < leftmark:
            done = True
        else:
            # 左右标的值交换：借助临时变量 temp 交换 alist[leftmark] 与 alist[rightmark] 的值
            temp = alist[leftmark]
            alist[leftmark] = alist[rightmark]
            alist[rightmark] = temp

    # 中值就位：借助临时变量 temp 将首项中值 alist[first] 与分裂点 alist[rightmark] 交换
    temp = alist[first]
    alist[first] = alist[rightmark]
    alist[rightmark] = temp

    # 返回中值点索引变量 rightmark，也是本次分裂的分裂点
    return rightmark
```
# 快速排序的算法复杂度与空间分析
## 最优与平均时间复杂度
快速排序过程分为两部分：**分裂** 和 **移动**。

**分裂复杂度**：如果分裂总能把数据表分为相等的两部分，那么递归树的高度就是 $O(\log n)$ 的复杂度。
**移动复杂度**：每一层移动需要将每项都与中值进行比对，复杂度是 $O(n)$。
**综合时间复杂度**：两部分结合起来，快速排序的理想/平均时间复杂度就是 $O(n \log n)$。

**空间优势**：而且，算法运行过程中 **不需要额外的存储空间**（原地交换元素）。
> [!question] 为什么归并排序需要额外的存储空间，而快速排序不需要？
> 1. **快速排序是“原址交换（In-place Partitioning）”**：
> 如上方 `partition()` 函数所示，快速排序在分裂列表时，始终传入的是 **同一个列表对象 `alist`** 以及子区间的 **首尾下标 `first` 和 `last`**。
> 不管是左右标元素的互换，还是最后“中值就位”，都只是借助一个临时变量 `temp` 在原列表 `alist` 的内存空间内部直接对调元素位置，没有创建任何新的子列表。
> 2. **归并排序是“异地归并（Out-of-place Merging）”**：
> 归并排序在分裂（使用切片如 `alist[:mid]` 或构建辅助数组）与合并两个有序子表时，无法简单通过两两交换就在原数组上直接排好序（若在原数组强行插入会导致后续元素整体后移，时间复杂度退化为 $O(n^2)$）。
> 因此归并排序必须开辟一个与原列表规模相当的 **额外临时列表（容量为 $O(n)$）**，将左右两个子表的数据按大小顺序依次追加/复制进去，最后再写回原列表。
> 3. **严谨补充（递归调用栈空间）**：
> 课件说“不需要额外的存储空间”，指的是 **不需要像归并排序那样额外开辟 $O(n)$ 的数据存储数组**（原地排序算法）。
> 但如果算上函数递归调用时系统栈帧保存局部变量（`first`、`last`、`splitpoint`）的开销，快速排序在递归过程中其实会占用 $O(\log n)$（平均）至 $O(n)$（最坏退化）的 **系统调用栈空间**。
## 极端情况与退化分析
如果不那么幸运的话，“中值”所在的分裂点过于偏离中部，会造成左右两部分数量不平衡。

**极端退化情况**：当原数据表本身已经是有序或逆序，且每次都固定选第1个数作为中值时，分裂出的两部分中 **有一部分始终没有数据**（一边为 $0$ 个，另一边为 $n-1$ 个）。这样分裂层数从 $\log n$ 退化为 $n$ 层，时间复杂度就退化到 $O(n^2)$，还要加上递归调用的开销（比冒泡排序还糟糕）。
## 中值选取方法的改进
为了避免极端退化情况，可以适当改进下 **中值** 的选取方法，让中值更具有代表性。

**三点取样（Median-of-Three）**
从数据表的 **头、尾、中间** 三个位置各取出一个元素，选出这三个数里的中位数作为“中值”。
这种方式会产生少量的额外计算开销，虽然能有效避免已排序列表导致的退化，但面对特定构造的数据时 **仍然不能完全排除极端情况**。

###  其他具有代表性的采样方法
在实际工程中，还可以使用 **随机取样（Randomized Quicksort，在区间内随机挑选一个位置作为中值）**。

或 **九点取样（Tukey's Ninther，适用于超大规模数组，取三组“三点取样”的中位数之中的中位数）**，从概率上消除固定模式输入引发的 $O(n^2)$ 最坏情况。
