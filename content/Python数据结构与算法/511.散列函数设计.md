# 折叠法
## 基本步骤
将数据项按照位数分为若干段，再将几段数字相加，最后对散列表大小求余，得到散列值。
### 计算示例
例如，对电话号码 `62767255` 进行散列（假设散列表包含 `11` 个槽）：
可以两位两位分为 `4` 段，得到 `62`、`76`、`72`、`55`。
将各段数字相加：`62 + 76 + 72 + 55 = 265`。
对散列表大小求余：`265 % 11 = 1`，所以散列值 `h(62767255) = 1`。
## 隔数反转优化
有时候折叠法还会包含一个 **隔数反转** 的步骤。
例如，分段结果 `(62, 76, 72, 55)` 隔数反转后变为 `(62, 67, 72, 55)`（第 2 段 `76` 反转为 `67`，第 4 段 `55` 反转后仍为 `55`）。
再进行累加：`62 + 67 + 72 + 55 = 256`。
对 `11` 求余：`256 % 11 = 3`，所以 `h'(62767255) = 3`。

>[!notes] 隔数反转的作用
>虽然隔数反转从理论上看来毫无必要，但这个步骤确实为折叠法得到散列函数提供了一种 **微调手段**，以便更好符合散列特性。
# 平方取中法
## 基本步骤
首先将数据项做平方运算，然后取平方数的 **中间两位**，再对散列表的大小求余。
### 计算示例
例如，对 `44` 进行散列（散列表大小为 `11`）：
首先计算平方：`44 * 44 = 1936`。
然后取中间的两位数字：`93`。
对散列表大小 `11` 求余：`93 % 11 = 5`。

## 除留余数法与平方取中法对比
以下为散列表大小为 `11` 时，对同一组数据项分别采用除留余数法（Remainder）和平方取中法（Mid-Square）的映射结果对比：

| Item | Remainder | Mid-Square |
| :---: | :---: | :---: |
| 54 | 10 | 3 |
| 26 | 4 | 7 |
| 93 | 5 | 9 |
| 17 | 6 | 8 |
| 77 | 0 | 4 |
| 31 | 9 | 6 |

在这组数据下，两个都是 **完美散列函数**，分散度都很好，但平方取中法的 **计算量稍大**。
# 非数项的散列设计
## 字符串的 ASCII 码累加法
我们也可以对非数字的数据项进行散列，只需把字符串中的每个字符看作对应的 **ASCII 码** 即可。
将字符串所有字符对应的整数累加，最后对散列表大小求余。
### 计算示例
以字符串 `"cat"` 为例（假设散列表大小为 `11`）：
调用 `ord()` 函数获取各字符的 ASCII 码：`ord('c')` 返回 `99`，`ord('a')` 返回 `97`，`ord('t')` 返回 `116`。
累加所有整数：`99 + 97 + 116 = 312`。
对散列表大小 `11` 求余：`312 % 11 = 4`。

### Python 代码实现
```python
# 定义针对字符串的散列函数 hash()
def hash(astring, tablesize):
    # 定义局部变量 sum，初始化为 0 用于累加 ASCII 码值
    sum = 0
    # 调用 range() 类（构造器）和 len() 函数生成索引序列并遍历字符串
    for pos in range(len(astring)):
        # 调用 ord() 函数获取当前索引字符的 ASCII 码值并累加
        sum = sum + ord(astring[pos])

    # 对散列表大小 tablesize 取模并返回槽号
    return sum % tablesize
```
## 变位词冲突与位置加权改进
单纯将字符 ASCII 码相加的散列函数，对所有的 **变位词**（如 `"cat"` 与 `"act"`、`"tac"`）都会返回相同的散列值，从而导致必然的散列冲突。 
为了防止这一点，可以将字符在字符串中所处的 **位置（从 1 开始计数的序号）作为权重因子**，乘以该字符的 `ord()` 函数返回值后再累加。
### 改进计算示例
同样以 `"cat"` 为例（散列表大小为 `11`）： 第 `1` 位字符 `'c'`：`99 * 1 = 99`。
第 `2` 位字符 `'a'`：`97 * 2 = 194`。 
第 `3` 位字符 `'t'`：`116 * 3 = 348`。
加权累加：`99 * 1 + 97 * 2 + 116 * 3 = 641`。 
对散列表大小 `11` 求余：`641 % 11 = 3`。

# 散列函数设计的基本原则
我们还可以设计出更多的散列函数方法，但要坚持的一个基本出发点是：**散列函数不能成为存储过程和查找过程的计算负担**。 
如果散列函数设计太过复杂，花费大量的计算资源去计算槽号，可能还不如简单地进行顺序查找或者二分查找，这样就失去了散列本身的意义。
