# 完美散列函数的基本概念
## 定义与局限性
给定一组数据项，如果一个散列函数能把每个数据项映射到不同的槽中，那么这个散列函数就可以称为 **“完美散列函数”**。

对于固定的一组数据，总是能想办法设计出完美散列函数。
但如果数据项经常性的变动，很难有一个系统性的方法来设计对应的完美散列函数。
当然，冲突也不是致命性的错误，后续会有专门的冲突解决机制来处理。
## 构造思路与现实权衡
获得完美散列函数的一种方法是扩大散列表的容量，大到 **所有可能出现** 的数据项都能够占据不同的槽。

但这种方法对于可能数据项范围过大的情况并不实用。
例如：假如要保存手机号（11位数字），完美散列函数得要求散列表具有百亿（$10^{11}$）个槽，会浪费太多存储空间。

退而求其次，好的散列函数需要具备以下特性：
**冲突最少**：近似完美。
**计算难度低**：额外开销小。
**充分分散数据项**：节约空间。
# 完美散列函数的更多用途（数据“指纹”）
## 数据“指纹”或者“摘要”
除了用于在散列表中安排数据项的存储位置，散列技术还用在信息处理的很多领域。

由于完美散列函数能够对任何不同的数据生成不同的散列值，如果把散列值当作数据的 **“指纹”** 或者 **“摘要”**，这种特性被广泛应用在 **数据的一致性校验** 上。
>[!notes] 理论与实用边界
>由 **任意长度** 的数据生成 **长度固定** 的“指纹”，还要求具备 **唯一性**，这在数学上是无法做到的（受限于鸽巢原理），但设计巧妙的“准完美”散列函数却能在实用范围内做到这一点。
## 数据“指纹”函数需要具备的特性
作为一致性校验的数据“指纹”函数需要具备如下四个核心特性：
**压缩性**：任意长度的数据，得到的“指纹”长度是固定的。
**易计算性**：从原数据计算“指纹”很容易（从指纹计算原数据是不可能的，具备**单向性**）。
**抗修改性**：对原数据的微小变动，都会引起“指纹”的大改变（雪崩效应）。
**抗冲突性**：已知原数据和“指纹”，要找到相同指纹的数据（伪造）是非常困难的。
# 散列函数MD5/SHA
## MD5（Message Digest）
最著名的近似完美散列函数是 **MD5** 和 **SHA** 系列函数。
MD5 将任何长度的数据变换为固定长为 **128位（16字节）** 的“摘要”。
128位二进制已经是一个极为巨大的数字空间（$2^{128} \approx 3.4 \times 10^{38}$），据说是地球沙粒的数量。
## SHA（Secure Hash Algorithm）
SHA 是另一组散列函数：
**SHA-0 / SHA-1**：输出散列值 **160位（20字节）**。160位二进制相当于 $10^{48}$，地球上水分子数量估计是 $10^{47}$。
**SHA-256 / SHA-224**：分别输出 **256位**、**224位**。256位二进制相当于 $10^{77}$，已知宇宙所有基本粒子大约是 $10^{72} \sim 10^{87}$。
**SHA-512 / SHA-384**：分别输出 **512位** 和 **384位**。
## 碰撞与安全性现状
虽然近年发现 MD5 / SHA-0 / SHA-1 三种散列函数能够以极特殊的情况来构造个别碰撞（散列冲突），但在通用非对抗的实用中从未有实际的威胁。
关于数量级的知识参考：`http://zh.wikipedia.org/wiki/数量级_(数)`。
# Python的散列函数库hashlib
## 分块计算与内存优化
Python 内置了散列函数库 `hashlib`。
除了对单个字符串进行散列计算之外，还可以调用散列对象的 `update()` 实例方法来对任意长的数据分部分来计算。
这样不管多大的数据（一个 G 甚至一个 T）都不会有内存不足的问题。
## 代码示例
```python
import hashlib

# 调用 hashlib 模块的 md5() 构造函数创建 MD5 散列实例对象 m
m = hashlib.md5()

# 调用 m 对象的 update() 实例方法分批次传入数据更新散列状态
m.update("hello world!")
m.update("this is part #2")
m.update("this is part #3")

# 调用 m 对象的 hexdigest() 实例方法获取十六进制字符串格式的摘要结果
m.hexdigest()

#输出: a12edc8332947a3e02e5668c6484b93a
```
# 完美散列函数用于数据文件一致性判断
## 数据文件一致性判断
为每个文件计算其散列值，仅对比其散列值即可得知是否文件内容相同。
通过将大体积文件压缩映射为固定长度的数据“指纹”，避免了逐字节比对大文件带来的极高 I/O 与传输开销。

应用场景如下：
### 网络文件下载完整性校验
用户下载文件后，在本地重新计算散列值并与官方发布的散列值对比，即可验证文件是否在传输过程中发生损坏或被恶意篡改。
### 文件分享系统去重（极速秒传）
网盘中相同的文件（尤其是电影等大文件）无需重复存储多次。
客户端上传前先计算并提交本地文件的散列值，若服务端已存在相同散列记录，则直接建立软引用指针完成“秒传”，大幅节约云端物理存储空间与上行带宽。
## 加密形式保存密码
服务器数据库仅保存用户密码的散列值（哈希摘要），不保存明文。
用户登录输入密码后，系统现场计算输入密码的散列值并与数据库中存储的散列值进行比对。
无需保存密码的明文即可准确判断用户是否输入了正确的密码。
>[!notes] 安全扩展说明
>利用散列函数的单向性（易计算、抗逆向推导），即使后端数据库泄露，攻击者也难以直接还原出用户的原始密码明文。
>现代工程实践中通常还会结合加盐（Salt）与慢哈希算法（如 bcrypt、Argon2）来抵御彩虹表反查。
## 防文件篡改
原理同数据文件一致性判断。
通过散列函数的抗修改性（雪崩效应），原数据的任何微小改动都会引发散列摘要的剧烈变动，使篡改行为极易被察觉。
除了基础散列算法外，工程上还会结合数字签名、公钥加密等更多密码学机制来协同保护数据文件。

防篡改与防抵赖是电子商务与电子合同等信息技术的核心基础。
在电子合同、交易账单中引入散列摘要与签名机制，能够确保合同内容自签署后未经修改，且发信人无法否认签署行为。
## 彩票投注应用
彩民下注前，彩票发行机构预先将已生成的开奖结果计算散列值并向社会公开发布。
公布散列值后，彩民进行下注。
开奖后，机构公布中奖结果明文；
彩民可以通过将公布的现场计算散列值，并与开奖前发布的散列值进行比对，以此验证机构是否在下注后暗箱作弊或临时篡改开奖数字。
>[!tips] 密码学原理：承诺机制（Commitment Scheme）
>此处利用了散列函数的两大特性：
>1. 隐藏性（Hiding）：由于单向性，彩民在下注前无法从散列值推算出开奖数字。
>2. 绑定性（Binding）：由于抗碰撞性，机构无法在下注结束后临时找到另一组能生成相同散列值的数字来替换开奖结果。
