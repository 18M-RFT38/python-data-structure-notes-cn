# 词梯问题（Word Ladder）
## 词梯问题定义与求解思路
词梯（Word Ladder）是由《爱丽丝漫游奇境》的作者 Lewis Carroll 于 1878 年发明的单词游戏。
游戏要求从一个起始单词演变为目标单词，中间可以经过多个过渡单词，且相邻两个单词之间**只能相差 1 个字母**。

以 `FOOL` 变换到 `SAGE` 为例，一条合法的 6 步变换序列为：`FOOL >> POOL >> POLL >> POLE >> PALE >> SALE >> SAGE`。

我们的目标是找到**最短**的单词变换序列。

采用图来解决这个问题的步骤分为三步：
首先将可能的单词之间的演变关系表达为图；
接着采用 **广度优先搜索（BFS）** 搜寻从开始单词到结束单词之间的所有有效路径；
最后选择其中最快到达目标单词的路径。
# 构建单词关系图
## 单词关系图的建模与稀疏性
将大规模单词集合放入图中的建模规则非常直接：
将单词作为顶点的标识 `Key`；
如果两个单词之间仅相差 1 个字母，就在它们之间设一条边。
![[file-20261122144355071.jpeg|283]]

由于“相差 1 个字母”是对称关系且每步变换代价相同，所用的图是**无向图**，边**没有权重**。
![[file-20261122144413411.jpeg|408]]
从 `FOOL` 到 `SAGE` 的每条路径都是一个解。
无权图中最短路径可能不止一条，BFS 会在首次触达终点时锁定最短步数。

以课程样例数据文件（包含 5,110 个 4 字母单词）为例，如果采用**邻接矩阵**表示这个单词关系图，需要 $5,110 \times 5,110 = 26,112,100$（约 2,600 万）个矩阵单元。
而单词关系图总计只有 53,286 条边，仅仅达到矩阵单元数量的 $0.2\%$。
因此单词关系图是一个**非常稀疏的图**，底层更适合用基于字典（[[508.什么是散列|散列]]）的 **邻接表** 来表示。
## 建图算法改进：直接比较法 vs. 通配符分桶法
将所有单词作为顶点加入图中后，建立边最直接的算法是对每个顶点与其它所有单词逐一比较，若相差仅 1 个字母则建边。
该算法的时间复杂度为 $O(n^2)$，对于 5,110 个 4 字母单词需要超过 2,600 万次比较。

改进的算法是**创建大量的桶（Bucket）**，每个桶存放若干单词。
桶标记是去掉 1 个字母、用通配符 `_` 占空的单词（以 `POPE` 为例，对应 `_OPE`、`P_PE`、`PO_E`、`POP_` 四个桶）。
![[file-20261122144730315.png|370]]
所有匹配标记的单词都放到对应的桶里；所有单词就位后，再在同一个桶的单词之间建立边即可。
## 采用字典建立桶：`buildGraph()` 函数
`buildGraph(wordFile)` **函数**接收词表文件路径，先通过字典完成分桶，再对同桶单词调用 `Graph` **类**的 `addEdge()` **实例方法**建边。

```python
# 定义建图外部函数 buildGraph()，形参 wordFile 为词表文件路径字符串
def buildGraph(wordFile):
    # 初始化局部字典变量 d，结构为 {桶标签字符串: [单词列表]}
    d = {}
    # 调用 Graph() 类构造器创建图实例对象 g
    g = Graph()
    # 调用内置函数 open() 以只读模式打开词表文件
    wfile = open(wordFile, 'r')

    # 第一阶段：创建相差一个字母的单词桶（4字母单词属于4个桶）
    for line in wfile:
        # 对行字符串 line 进行切片，去掉末尾自带的换行符 '\n'
        word = line[:-1]
        # 调用内置函数 range() 与 len() 遍历单词的每一个字符下标 i
        for i in range(len(word)):
            # 挖掉第 i 个字母并替换为 '_'，生成通配符桶标签
            bucket = word[:i] + '_' + word[i+1:]
            # 检查桶标签 bucket 是否已作为键存在于字典 d 中
            if bucket in d:
                # 桶已存在，调用列表的 append() 实例方法追加当前单词
                d[bucket].append(word)
            else:
                # 桶不存在，在字典 d 中新建只含当前单词的列表
                d[bucket] = [word]

    # 第二阶段：同一个桶单词之间建立边
    # 调用字典 d 的 keys() 实例方法遍历所有桶标签
    for bucket in d.keys():
        for word1 in d[bucket]:
            for word2 in d[bucket]:
                # 排除单词自身与自己配对
                if word1 != word2:
                    # 调用 Graph 实例方法 addEdge() 在两单词顶点间建立边
                    g.addEdge(word1, word2)

    return g
```
### `word = line[:-1]` 的去换行处理
`line` 是从文件里读出来的一行文本，文件里每一行单词末尾自带一个看不见的换行符 `\n`。
`[:-1]` 切片取从开头到倒数第 1 个字符之前（不包含最后一个字符），把 `"fool\n"` 末尾的 `\n` 扔掉，得到 `"fool"`。
>[!attention] 换行符切片的边界情况
>如果词表文件最后一行没有换行符，`line[:-1]` 会误删最后一个字母；实际工程中更稳妥的做法是调用字符串的 `strip()` **实例方法**（`word = line.strip()`）。

### `bucket = word[:i] + '_' + word[i+1:]` 的切片挖空原理
先记住切片规则：`word[:i]` 从开头取到下标 `i`（不包含 `i`），`word[i+1:]` 从下标 `i+1` 一直取到末尾。
这行代码的本质是遍历单词的每一个位置 `i`，把单词在位置 `i` 切开，丢掉第 `i` 个字母并填上下划线 `_`，得到一个桶标签。

以单词 `FOOL`（字母下标 `F(0) O(1) O(2) L(3)`）为例：
当 `i = 0` 时，`word[:0]` 为 `""`，`word[1:]` 为 `"OOL"`，拼接得到 `_OOL`。
当 `i = 1` 时，`word[:1]` 为 `"F"`，`word[2:]` 为 `"OL"`，拼接得到 `F_OL`。
当 `i = 2` 时，`word[:2]` 为 `"FO"`，`word[3:]` 为 `"L"`，拼接得到 `FO_L`。
当 `i = 3` 时，`word[:3]` 为 `"FOO"`，`word[4:]` 超出长度为空字符串 `""`，拼接得到 `FOO_`。

下划线 `_` 是占位符，代表“这个位置可以换任意字母”。
只要两个单词生成了同一个 `bucket`（例如 `FOOL` 和 `POOL` 在 `i=0` 时都生成 `_OOL`），就说明它们只有下划线所在位置不一样、其余字母完全相同，即互为只差 1 个字母的邻居。

### `if bucket in d:` 的字典建桶逻辑
`d` 是存桶的字典，键（key）是 `bucket`（如 `_OOL`），值（value）是存放所有属于这个桶的单词的列表。
`if bucket in d` 检查这个桶标签是否已经在字典 `d` 里面存在。

如果 `bucket` 已经存在（`True`），说明这个桶之前已经建好，直接调用列表的 `append()` **实例方法**把当前单词追加进去（例如 `d` 中已有 `"_OOL": ["FOOL"]`，再来 `POOL` 时变为 `"_OOL": ["FOOL", "POOL"]`）。
如果 `bucket` 不在 `d` 中（`False`，走 `else` 分支），说明这是第一次碰到这个桶，必须新建列表 `d[bucket] = [word]`；
必须写成列表 `[word]` 而不能直接写 `word`，因为后面还要持续调用 `append()` 往里加单词。

### 三层 `for` 循环的桶内建边逻辑
外层 `for bucket in d.keys():` 锁定同一个桶（桶里所有单词互相之间只差 1 个字母，全部满足建边条件）；
内层两重循环取出桶里任意一对不同的单词（`if word1 != word2` 排除自己和自己配对），调用 `g.addEdge(word1, word2)` **实例方法**两两互相连边。

>[!question] 桶内建边是否存在重复添加？
>如果桶里是 `[A, B, C]`，两层循环是有序遍历，组合有 `A-B`、`A-C`、`B-A`、`B-C`、`C-A`、`C-B`。
>由于 `Graph` 是无向图，`A` 对 `B` 建一条后 `B` 对 `A` 又会再建一次，这里产生了重复添加边的冗余，但不影响 BFS 找最短路径。
# 实现广度优先搜索（BFS）
## BFS 算法原理与顶点属性
在单词关系图建立完成以后，需要用到 **广度优先搜索（Breadth First Search, BFS）** 算法在图中寻找词梯问题的最短序列。
BFS 是搜索图的最简单算法之一，也是其它一些重要图算法的基础。

给定图 $G$ 以及起始顶点 $s$，BFS 搜索所有从 $s$ 可到达顶点的边，并且在达到更远的距离 $k+1$ 的顶点之前，会先找到**全部距离为 $k$ 的顶点**。
整个过程可以想象为以 $s$ 为根构建一棵树，从顶部向下逐步增加层次，保证在增加层次之前添加了所有兄弟节点到树中。

![[file-20261122145350870.png|419]]
>[!attention]
>如图：从fool开始。
>第一轮距离k=1时,与fool直接相连的有foul、foil、cool、pool
>再来看距离k=2时,与fool相连的有foil、fail、pool、poll
>之后再距离k=3时,与fool相连的有fail、fall、poll、pole
>再让距离k=4、k=5...一步步的扩展出去，这就叫做**广度优先**
>但我们同时也发现了问题，有点节点的距离并不是固定的值，也就是说，出现了重复搜索的现象

为了跟踪顶点的加入过程、避免重复访问（防止在环路中出现同一个节点距离不固定、被更长路径覆盖的问题），要为每个 `Vertex` 对象增加 3 个**实例属性**，并配合一个[[308~309.队列抽象数据类型与热土豆问题|队列（Queue）]]决定下一个要探索的队首顶点：
`distance` **实例属性**：记录从起始顶点到此顶点的路径长度。
`predecessor`（代码中为 `pred`）**实例属性**：记录前驱顶点，用于反向追溯到起点。
`color` **实例属性**：标识此顶点是尚未发现（**白色**）、已经发现（**灰色**）、还是已经完成探索（**黑色**）。
## BFS 标准迭代过程与实例运行
从起始顶点 $s$ 开始，将其作为刚发现的顶点标注为灰色、距离为 `0`、前驱为 `None` 并加入队列，接下来是一个循环迭代过程：
首先从**队首**取出一个顶点作为**当前顶点**；
接着遍历当前顶点的**邻接顶点**，如果是尚未发现的白色顶点，就将其颜色改为灰色（已发现）、距离增加 `1`、前驱顶点设为当前顶点并加入到队列中；
遍历完成后，将当前顶点设置为黑色（已探索过），循环回到第一步从队首取下一个顶点。

![[file-20261122150433879.png|375]]
以 `fool` 为起点运行时，`fool` 首先出队并标黑，其邻居 `pool`、`foil`、`cool`（以及 `foul`）被发现，距离记为 `1`、前驱指向 `fool`、标灰入队。
![[file-20261122150729225.png|313]]
接着 `pool` 出队并标黑，发现距离为 `2` 的 `poll`（前驱指向 `pool`）；
![[file-20261122150911491.png|354]]
随后 `foil` 出队发现距离为 `2` 的 `fail`。接下来的两个节点都不向队列或树添加新内容，`foul`、`cool` 出队标黑。

依此逐层扩展至 `pall`、`pole`（第 3 层）与 `pale`、`pope`（第 4 层）.......
最终通过 `pred` 指针沿 `page -> pale -> pole -> poll -> pool -> fool` 反向回溯，即可还原最短路径。

```python
class Vertex:
    def __init__(self, key):
        self.id = key               # 实例属性：顶点标识
        self.connectedTo = {}       # 实例属性：邻接表字典 {邻居Vertex对象: 边权重}
        #  **BFS 新增的三个实例属性** 
        self.distance = 0           # 起始顶点到当前顶点的距离
        self.pred = None            # 前驱顶点引用（用于反向回溯路径）
        self.color = 'white'        # 顶点状态：white未发现，gray已发现待扩展，black已处理完

    def addNeighbor(self, nbr, weight=0):
        self.connectedTo[nbr] = weight

    def getConnections(self):
        return self.connectedTo.keys()

    def getId(self):
        return self.id

    def getWeight(self, nbr):
        return self.connectedTo[nbr]

    #  **BFS 新增的 set / get 实例方法** 
    def setDistance(self, d):
        self.distance = d

    def getDistance(self):
        return self.distance

    def setPred(self, p):
        self.pred = p

    def getPred(self):
        return self.pred

    def setColor(self, c):
        self.color = c

    def getColor(self):
        return self.color
```

### `bfs()` 函数
```python
# 定义广度优先搜索外部函数 bfs()，形参 g 为 Graph 实例，start 为起始 Vertex 实例
def bfs(g, start):
    # 调用 Vertex 实例方法 setDistance() 和 setPred() 初始化起点
    start.setDistance(0)
    start.setPred(None)
    # 调用 Queue() 类构造器创建队列实例 vertQueue
    vertQueue = Queue()
    # 调用 Queue 实例方法 enqueue() 将起点入队
    vertQueue.enqueue(start)

    # 调用 Queue 实例方法 size() 判断队列是否非空
    while (vertQueue.size() > 0):
        # 调用 Queue 实例方法 dequeue() 取队首作为当前顶点
        currentVert = vertQueue.dequeue()
        # 调用 Vertex 实例方法 getConnections() 遍历所有邻接顶点
        for nbr in currentVert.getConnections():
            # 调用 Vertex 实例方法 getColor()，仅处理尚未发现的白色顶点
            if (nbr.getColor() == 'white'):
                # 调用 Vertex 实例方法 setColor() 标记为灰色（已发现）
                nbr.setColor('gray')
                # 调用 getDistance() 与 setDistance() 实例方法，距离设为当前顶点距离 + 1
                nbr.setDistance(currentVert.getDistance() + 1)
                # 【高亮】调用 Vertex 实例方法 setPred() 记录前驱顶点，用于后续回溯
                nbr.setPred(currentVert)
                # 将新发现的邻接顶点入队尾
                vertQueue.enqueue(nbr)
        # 调用 Vertex 实例方法 setColor() 将当前顶点设黑色（探索完毕）
        currentVert.setColor('black')
```
**一次 `bfs(g, A)` 建好整棵“最短路径树”**：从起点 `A` 一层层往外铺开，所有能从 `A` 连通到达的顶点都会被写好两个核心**实例属性**——`distance`（到 `A` 的最短步数）和 `pred`（指向上一层父节点的指针）。
### `traverse()` 回溯函数与主调用流程
在以 `FOOL` 为起始顶点遍历所有顶点，并为每个顶点着色、赋距离和前驱之后，即可通过回溯函数 `traverse()` 确定 `FOOL` 到任何单词顶点的最短词梯。
```python
# 定义回溯外部函数 traverse()，形参 y 为目标单词对应的 Vertex 实例
def traverse(y):
    x = y
    # 调用 Vertex 实例方法 getPred()，只要存在前驱就继续向上回溯
    while (x.getPred()):
        # 调用内置函数 print() 与 Vertex 实例方法 getId() 输出当前单词
        print(x.getId())
        x = x.getPred() # 更新x
    # 循环结束时 x 为起点（pred 为 None），打印起点单词
    print(x.getId())

# 调用 buildGraph() 函数构建 4 字母单词关系图
wordgraph = buildGraph("fourletterwords.txt")
# 调用 Graph 实例方法 getVertex() 获取 'FOOL' 顶点，执行 bfs() 函数
bfs(wordgraph, wordgraph.getVertex('FOOL'))
# 获取 'SAGE' 顶点并调用 traverse() 函数反向打印最短词梯
traverse(wordgraph.getVertex('SAGE'))
```

>[!attention] 输出顺序说明
>`traverse(y)` 从终点 `SAGE` 沿着前驱一路指回 `FOOL`，因此直接打印出的单词序列是逆序的（`SAGE -> SALE -> PALE -> POLE -> POLL -> POOL -> FOOL`）。
**任意 `traverse(B)` 顺藤摸瓜**：只要 `B` 在 `A` 的连通区内，直接调用 `traverse(B)`，就会沿着 `pred` 一级一级往回跳，直到撞上唯一一个 `pred` 为 `None` 的起点 `A` 停下，还原出 `A` 到 `B` 的最短词梯（打印出来是从 `B` 倒推回 `A`）。
# 广度优先搜索算法分析
BFS 算法主体是两个循环的嵌套。
外层 `while` 循环对每个顶点访问 1 次，时间复杂度是 $O(|V|)$；
嵌套在 `while` 中的 `for` 循环，由于每条边只有在其起始顶点 $u$ 出队的时候才会被检查 1 次，而每个顶点最多出队 1 次，所以边最多被检查 1 次，一共是 $O(|E|)$。
综合起来，BFS 的时间复杂度为 $O(|V| + |E|)$。

词梯问题还包括另外两个部分的时间开销。
建立 BFS 树之后，沿前驱回溯顶点到起始顶点的过程最多经过全部顶点，时间复杂度最多为 $O(|V|)$；而创建单词关系图在最坏情况下需要的时间最多为 $O(|V|^2)$。
