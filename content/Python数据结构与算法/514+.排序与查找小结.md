# 排序与查找的算法选择与信息分类
## 算法的选择：综合权衡
排序算法有时并不存在绝对的优劣，尤其是时间复杂度处于同一数量级的算法。
要在特定的应用场合取得最高排序性能，需要对 **数据本身** 进行分析，针对处理数据对象的特性来选择相应的排序算法。
除了时间复杂度，**空间复杂度** 也是算法选择时需要考量的关键因素。例如[[506.归并排序算法及分析|归并排序]]的时间复杂度稳定为 $O(n \log n)$ ，但需要额外一倍的存储空间（空间复杂度为 $O(n)$）。
因此，算法选择不是单一维度的优劣判断，需要综合考虑 **运行环境要求** 与 **处理数据对象的特性**。
## 查找过程的信息与存储结构映射
**存取（access）**：由物理位置直接存储或获取数据值。
**查找（search）**：由目标数据值确定其在数据集中的存储位置。

根据数据存储位置与其值之间的关联程度，可将查找结构划分为三个层次：
**无序表（数据存储位置与其值无关）**：元素之间只有相等或不相等的判别关系，只能采用顺序查找 [[501.顺序查找算法及分析|顺序查找]]，时间复杂度为 $O(n)$ [[313~314.无序表抽象数据类型及其python实现|无序表]]。
**有序表（数据存储的相对位置与其值相关）**：若数据项支持大小比较，按照大小排序后可采用二分查找 [[502.二分查找算法及分析|二分查找]]，时间复杂度降为 $O(\log n)$ [[315.有序表抽象数据类型及其python实现|有序表]]。
**散列表（数据存储的绝对位置与其值相关）**：数据值与存储位置之间直接存在散列函数映射关系 [[508.什么是散列|什么是散列]]，通过散列函数直接定位槽位，理想时间复杂度达到 $O(1)$。
## 排序信息与ADT Map实现回顾
排序过程中的比较信息可分为三类（详见 [[514.排序算法小结#排序过程中的比较信息|排序过程中的比较信息]]）：
**基于比较的一阶信息**：仅利用 $a_i, a_j$ 之间的直接大小比较（如 $a_i < a_j$），代表算法为冒泡、选择、插入、谢尔排序，时间复杂度在 $O(n^2)$ 级别。
**基于比较的二阶信息**：利用 $a_i, a_j$ 与 $a_j, a_k$ 之间的大小传递性信息，代表算法为快速排序、归并排序，时间复杂度为 $O(n \log n)$。
**基于先验信息的非比较排序**：预先知道各数字符号之间的大小关系，代表算法为基数排序、桶排序，时间复杂度为 $O(n)$。

在 [[513.抽象数据类型映射及python实现|抽象数据类型映射ADT Map]] 中，除了使用散列表实现 `put()` 方法与基于内容关联的 `get()` 方法外，还可以采用 **无序表**（配合顺序查找的 `get()` 方法）、**有序表**（配合二分查找的 `get()` 方法）以及后续的 **二叉排序树** 来实现。

>[!notes] 映射（Map）与集合（Set）的关系
>ADT Map 保存的是 `key-val` 键值关联对；如果去掉关联的数据值 `val`，仅保留具有唯一性的关键码 `key`，该结构就退化为集合（`set` 类）。
# 二次探测与散列平均比对次数答疑
## 二次探测法与线性探测对比
在 [[512.冲突解决方案#二次探测Quadratic Probing|二次探测]] 中，探测槽号按原散列值 $h$ 加上平方数递增：$h, h+1, h+4, h+9, h+16 \dots$（即第 $i$ 次冲突位置为 $(h + i^2) \bmod \text{sizeoftable}$）。

>[!question] 既然二次探测存在周期性（可能出现还有空槽却无法插入的情况），为什么仍认为它比线性探测更好？
>二次探测虽然会因平方余数的周期性而只能覆盖部分槽位，但在散列表大小 `sizeoftable` 属性为 **素数** 时，它至少能够到达表中 $1/2$ 较为分散的槽位（当负载因子 $\lambda < 0.5$ 时，数学上保证一定能找到空槽插入）。
>二次探测的主要相对优势在于通过平方步长跳跃 **避免数据在局部集中**，从而防止像线性探测那样引发连锁冲突（一次聚集现象）。

以平方数对素数表长 `5` 和 `17` 取模为例，探测偏移量分布如下：

```text
NO, **2, mod 5, mod 17
00, 000,   0,     00
01, 001,   1,     01
02, 004,   4,     04
03, 009,   4,     09
04, 016,   1,     16
05, 025,   0,     08
06, 036,   1,     02
07, 049,   4,     15
08, 064,   4,     13
```
## 负载因子与平均查找次数估算实例
根据 [[513.抽象数据类型映射及python实现#散列算法分析|散列算法分析]] 中的平均比对次数公式，当采用线性探测的开放定址法解决冲突（$0 < \lambda < 1$）时：
成功的查找平均比对次数为 $\frac{1}{2}\left(1 + \frac{1}{1-\lambda}\right)$，不成功的查找平均比对次数为 $\frac{1}{2}\left(1 + \left(\frac{1}{1-\lambda}\right)^2\right)$。
当采用数据链（拉链法）解决冲突（$\lambda$ 可大于 $1$）时：
成功的查找平均比对次数为 $1 + \frac{\lambda}{2}$，不成功的查找平均比对次数为 $\lambda$。

**MOOC 典型例题验算**：若采用线性探测法解决冲突，负载因子 $\lambda = 0.8$，将其代入成功查找公式可得：
$$\frac{1}{2}\left(1 + \frac{1}{1 - 0.8}\right) = \frac{1}{2}(1 + 5) = 3$$
即成功查找平均需要比对次数约为 `3` 次。
# MD5算法内部结构与碰撞演进
## MD5的基本规范与分组填充规则
**MD5** 全称为 **Message-Digest Algorithm**（消息摘要算法），由美国密码学家罗纳德·李维斯特（Ronald Linn Rivest）设计并于 1992 年公开，用以取代 MD4 算法，其标准规范定义于 **RFC-1321**（参见 [[509.完美散列函数#散列函数MD5/SHA|完美散列函数]]）。
MD5 接收不定长度的输入信息，以 **512 位（512-bit）分组** 为单位循环处理，每一分组又被拆分为 16 个 **32 位小端序（little-endian）子分组** `w[i]`（$0 \le i \le 15$）。
经过一系列非线性循环处理后，算法输出四个 32 位分组状态（`h0, h1, h2, h3`），将这四个 32 位分组级联后即生成一个固定长度的 **128 位（128-bits）散列值**。

**消息填充规则（Pre-processing）**：
首先在明文数据末尾追加一个比特 `1`，随后连续填充比特 `0`（即追加二进制串 `10...`），使填充后的消息长度 $L$ 满足 $L \bmod 512 = 448$。
最后再附加 **64 bits**（以 64 位小端序整数形式）表示原始明文数据的比特长度，使总长度恰好凑成 `512 bits` 的整数倍分组。

**MD5 处理整体流程**：
明文数据 $\to$ 信息填充 $\to$ 结构初始化 $\to$ 文件分组 $\to$ 循环调用压缩算法处理每个 512-bit 分组 $\to$ 所有分组处理完成后执行最后一次累加 $\to$ 输出 128 位散列摘要。
## MD5算法伪代码实现
### 常量表与初始链接变量定义
MD5 伪代码中所有变量均为无符号 32 位整数（unsigned 32 bits），算术加法运算均对 $2^{32}$ 取模（wrap modulo $2^{32}$）。
移位量数组 `r[0..63]` 指定了 64 步循环中每一步的循环左移位数；常量数组 `k[0..63]` 则取自正弦函数 $\sin(i+1)$ 绝对值乘以 $2^{32}$ 后的整数部分（借由三角函数无理数消除人为后门嫌疑）：

```text
// Note: All variables are unsigned 32 bits and wrap modulo 2^32 when calculating
var int[64] r, k

// r specifies the per-round shift amounts
r[ 0..15] := {7, 12, 17, 22,  7, 12, 17, 22,  7, 12, 17, 22,  7, 12, 17, 22}
r[16..31] := {5,  9, 14, 20,  5,  9, 14, 20,  5,  9, 14, 20,  5,  9, 14, 20}
r[32..47] := {4, 11, 16, 23,  4, 11, 16, 23,  4, 11, 16, 23,  4, 11, 16, 23}
r[48..63] := {6, 10, 15, 21,  6, 10, 15, 21,  6, 10, 15, 21,  6, 10, 15, 21}

// Use binary integer part of the sines of integers as constants:
for i from 0 to 63
    k[i] := floor(abs(sin(i + 1)) × 2^32)

// Initialize variables (4个32位初始链接变量魔数):
var int h0 := 0x67452301
var int h1 := 0xEFCDAB89
var int h2 := 0x98BADCFE
var int h3 := 0x10325476

// Pre-processing:
append "1" bit to message
append "0" bits until message length in bits ≡ 448 (mod 512)
append bit length of message as 64-bit little-endian integer to message
```
### 分块主循环（64步非线性迭代）
对每个 512-bit 分块，将其拆分为 16 个 32-bit 字 `w[0..15]`，并通过 4 轮（每轮 16 步，共 64 步）不同的位逻辑函数 $f$ 与子块下标置换公式 $g$ 进行混合迭代：

```text
// Process the message in successive 512-bit chunks:
for each 512-bit chunk of message
    break chunk into sixteen 32-bit little-endian words w[i], 0 ≤ i ≤ 15

    // Initialize hash value for this chunk:
    var int a := h0
    var int b := h1
    var int c := h2
    var int d := h3

    // Main loop:
    for i from 0 to 63
        if 0 ≤ i ≤ 15 then
            f := (b and c) or ((not b) and d)
            g := i
        else if 16 ≤ i ≤ 31
            f := (d and b) or ((not d) and c)
            g := (5×i + 1) mod 16
        else if 32 ≤ i ≤ 47
            f := b xor c xor d
            g := (3×i + 5) mod 16
        else if 48 ≤ i ≤ 63
            f := c xor (b or (not d))
            g := (7×i) mod 16

        temp := d
        d := c
        c := b
        b := leftrotate((a + f + k[i] + w[g]), r[i]) + b
        a := temp
    Next i

    // Add this chunk's hash to result so far:
    h0 := h0 + a
    h1 := h1 + b
    h2 := h2 + c
    h3 := h3 + d
```

所有分块处理完成后，将最终的 `h0, h1, h2, h3` 级联输出，即得到完整的 128-bit MD5 散列值。
## Python分块计算二进制文件MD5示例
在 [[509.完美散列函数#Python的散列函数库hashlib|hashlib模块]] 基础用法之上，针对本地大体积二进制文件（如 PDF 或镜像安装包），可通过 `with open(..., "rb")` 语句配合固定字节块循环读取，增量更新散列状态：

```python
import hashlib

# 设置每次读取的字节数变量 blk_size 为 2048 字节
blk_size = 2048
# 调用 hashlib 模块的 md5() 构造函数创建散列函数实例对象 m
m = hashlib.md5()

# 调用内置 open() 函数以二进制只读模式 "rb" 打开文件对象 f
with open("2004-199.pdf", "rb") as f:
    while True:
        # 调用文件对象 f 的 read() 实例方法每次读取 blk_size 字节的数据块 buf
        buf = f.read(blk_size)
        if not buf:
            break
        # 调用散列对象 m 的 update() 实例方法增量更新散列状态
        m.update(buf)

# 调用散列对象 m 的 hexdigest() 实例方法获取并调用 print() 函数打印 16 进制文本串
print(m.hexdigest())
# 运行输出: 7667d184375a8d968e9e107217f7e8ea
```
## MD散列冲突构造与碰撞攻击
1993 年，Bert den Boer 与 Antoon Bosselaers 发现了 MD5 的 **伪冲突（pseudo-collision）**，即同一消息在两组不同初始值下产生相同摘要。
随后 H. Dobbertin 发现了 **自由起始冲突（free-start collision）**，即基于特定选择的非标准初始值 $IV_0'$ 构造出两个不同的 512-bit 碰撞消息。
2004 年，中国密码学家 **王小云（Xiaoyun Wang）**、冯登国、来学嘉、于红波发表著名论文 *Collisions for Hash Functions: MD4, MD5, HAVAL-128 and RIPEMD*，首次在 **MD5 原始标准初始值 $IV_0$** 下高效构造出由两个 1024-bit 消息组成的 **真实碰撞（real collisions）**，彻底终结了 MD5 在高安全抗碰撞场景下的统治地位。

# 完美散列进阶：非对称加密、数字签名与数字证书
## 单纯散列防篡改的局限性
假设 Alice 写了一份电子借据 `doc`，连同散列值 `Hash(doc)` 一起发送给 Bob。
如果 Alice 或 Bob 事后偷偷修改了借据内容变为 `doc'`，并重新计算了对应的 `Hash(doc')`，双方都声称自己手中的版本才是原件，此时仅凭公开的散列函数无法裁定“究竟是谁生成的摘要”，因为任何人都可以调用公开的散列函数计算 `Hash(doc')`。
为了同时解决 **防篡改** 与 **防抵赖（身份认证）** 问题，必须引入 **非对称加密（公开密钥加密）** 体制。
## 基于数学难题的非对称加密
非对称加密基于单向数学难题（例如大整数质因数分解难题）：
选取两个 **特别大** 的素数 $P_1$ 和 $P_2$，计算其乘积 $PU = P_1 \times P_2$。
用 $PU$ 加密的信息，仅能用 $P_1$（或 $P_2$）解密；反之亦然，用 $P_1$ 加密的信息也只能用 $PU$ 解密。
**公开密钥（公钥，$PU$）**：公诸于众，任何人都可以获取。
**私有密钥（私钥，$P_1$ 或 $P_2$）**：由持有人严格保密，切勿泄露。
由于大整数分解在计算上的不可行性，仅知道公钥 $PU$ 无法在合理时间内反推出私钥 $P_1$。
## 非对称加密通信：允许不可靠信道
在传统的 **对称加密**（如凯撒加密 `A - (+3) - D`）中，加密和解密使用的是同一个密钥 `3`，一旦该密钥在公开信道传输时被截取，加密通信即彻底失效。
而在 **非对称加密通信** 中，即便传输信道完全公开、可被任何人截取，依然能保证机密性：
**发送方（公开区域）**：Alice 获取 Bob 公开的公钥 `BPU`，对明文 `text` 加密后向网络发送密文 `BPU(text)`。
**窃密者（公开区域）**：即便从网络中截获了密文 `BPU(text)`，由于没有 Bob 的私钥 `BP1`，无法还原明文。
**接收方（安全区域）**：Bob 收到密文后，使用自己妥善保管的私钥 `BP1` 执行解密运算 `BP1(BPU(text))`，从而安全得到明文 `text`。
## 数字签名：防止篡改与抵赖
将完美散列函数与非对称加密结合，即可构建 **数字签名（Digital Signature）** 机制（以 Alice 向 Bob 出具电子借据 `doc` 为例）：
### 签名流程（Alice端）
第一步，Alice 将原始电子借据 `doc` 输入散列函数，计算得到定长散列值 `Hash(doc)`。
第二步，Alice 使用 **自己的私钥 `AP1`** 对该散列值进行加密，生成数字签名 `AP1(Hash(doc))`。
第三步，Alice 将原始借据 `doc` 与数字签名 `AP1(Hash(doc))` 一并附加发送给 Bob。
### 验证流程（Bob及公众端）
接收方将收到的“数字签名的数据”拆分为原始数据 `doc` 与签名 `AP1(Hash(doc))` 两路处理：
第一路，将 `doc` 输入相同的散列函数，重新计算得到散列值 `Hash(doc)`。
第二路，使用众人皆知的 **Alice 公钥 `APU`** 对签名进行解密，得到 `APU(AP1(Hash(doc)))`。
最后比对两路散列值是否严格相等：
$$\text{Hash}(doc) == \text{APU}(\text{AP1}(\text{Hash}(doc)))$$
若两者散列值完全一致，则证明该数字签名有效。

>[!notes] 数字签名的双重安全保障
>1. **防抵赖（不可否认性）**：因为私钥加密的信息只能用对应的公钥解密，而世上只有 Alice 拥有私钥 `AP1`，其他人无法伪造出能被 `APU` 正常解密的签名 `AP1(Hash(doc))`，所以 Alice 无法抵赖自己签署过借据。
>2. **防篡改（完整性）**：散列值 `Hash(doc)` 被私钥加密锁定在签名中，任何对 `doc` 正文的篡改都会导致重新计算的散列值与公钥解密出的散列值失配。
## 公钥的有效性与数字证书（CA体系）
>[!question] 如果 Alice 谎称“你们拿到的公钥 `APU` 是别人冒名顶替我发布的假公钥”，借此抵赖借据怎么办？
>单纯依靠密码学算法本身无法证明“某个公钥在现实世界中属于谁”，这需要引入技术之外的信任机制：**由权威机构（CA，Certificate Authority）发行数字证书**。

**数字证书的签发与验证逻辑**：
大家都信任权威机构（如国家认证的证书中心、银行或根 CA 机构 `DigiCert`、`GeoTrust` 等）。
申请人 Alice 通过线下实名等身份认证途径，向权威机构提交个人信息 `AliceInfo` 与自己的公钥 `APU`。
权威机构核实无误后，使用 **权威机构自己的私钥 `AuthP1`** 对 Alice 的身份信息与公钥进行加密签名，生成 **数字证书**：
$$\text{Cert}_{\text{Alice}} = \text{AuthP1}(\text{AliceInfo} + \text{APU})$$
任何人在验证时，只需用操作系统或浏览器内置的权威机构公钥解密该数字证书，即可确认公钥 `APU` 的确属于真实身份的 Alice，彻底杜绝公钥冒名顶替与事后抵赖。
# 【K08】散列表自动扩容实现
## 课堂练习题目要求
设计算法重新实现 [[513.抽象数据类型映射及python实现#实现ADT Map|散列表 HashTable 类]] 的 `put()` 实例方法，使得散列表可以在 **负载因子 $\lambda$** 达到一个预设阈值时自动调整大小（动态扩容）。
算法需要妥善处理散列表中已有的现有数据项，保证在扩充散列表之后，依然能通过 `get()` 实例方法正常访问所有现有的数据项。
## 为什么扩容必须执行再散列（Rehashing）
>[!attention] 核心考点：扩容后绝不能直接原样复制列表槽位
>散列表中每个 `key` 的存放位置依赖于对当前表长 `self.size` 属性取余的结果：`hashvalue = key % self.size`。
>当散列表容量从旧表长（如 `11`）扩充为新表长（如 `23`）后，同一个 `key` 对新表长取余计算出的散列槽位已经发生改变！若直接按原下标复制到新列表中，后续调用 `get()` 方法按新表长取余查找时将无法定位到原有数据。
>因此，扩容时必须遍历旧表中的所有非 `None` 有效键值对，按照 **新表长重新计算散列位置** 并逐一重新插入新表中。
## 支持自动扩容的HashTable类Python实现
```python
class HashTable:
    # 定义 __init__() 构造方法初始化支持动态扩容的散列表实例对象
    def __init__(self, size: int = 11, load_factor_threshold: float = 0.75):
        # 设置实例属性 size 表示当前散列表槽数（初始取素数 11）
        self.size = size
        # 设置实例属性 count 记录当前已存储的有效键值对数量
        self.count = 0
        # 设置实例属性 load_factor_threshold 表示触发扩容的负载因子阈值
        self.load_factor_threshold = load_factor_threshold
        # 初始化平行列表实例属性 slots 与 data
        self.slots = [None] * self.size
        self.data = [None] * self.size

    # 定义 hashfunction() 实例方法：采用求余法计算初始散列值
    def hashfunction(self, key: int, size: int) -> int:
        return key % size

    # 定义 rehash() 实例方法：采用线性探测 "+1" 计算再散列位置
    def rehash(self, oldhash: int, size: int) -> int:
        return (oldhash + 1) % size

    # 定义 _is_prime() 辅助实例方法：判断整数 n 是否为素数
    def _is_prime(self, n: int) -> bool:
        if n < 2:
            return False
        for i in range(2, int(n ** 0.5) + 1):
            if n % i == 0:
                return False
        return True

    # 定义 _next_prime() 辅助实例方法：寻找大于等于 n 的最小素数作为新表长
    def _next_prime(self, n: int) -> int:
        candidate = n
        while not self._is_prime(candidate):
            candidate += 1
        return candidate

    # 定义 _resize() 实例方法：扩充散列表容量并迁移重散列所有旧数据项
    def _resize(self) -> None:
        # 保存旧表的 slots 与 data 列表引用
        old_slots = self.slots
        old_data = self.data
        
        # 调用 _next_prime() 实例方法将表容量扩充为原大小 2 倍以上的最小素数
        self.size = self._next_prime(self.size * 2)
        # 按新表长重新初始化空的 slots 与 data 列表属性，并重置计数属性 count
        self.slots = [None] * self.size
        self.data = [None] * self.size
        self.count = 0

        # 遍历旧表，调用 put() 实例方法将所有非空数据项按新表长重新散列插入
        for i in range(len(old_slots)):
            if old_slots[i] is not None:
                self.put(old_slots[i], old_data[i])

    # 定义 put() 实例方法：写入或更新键值对，并在达到负载因子阈值时自动扩容
    def put(self, key: int, data) -> None:
        # 若当前负载因子预计达到或超过预设阈值，先调用 _resize() 实例方法扩容
        if (self.count + 1) / self.size >= self.load_factor_threshold:
            self._resize()

        # 调用 hashfunction() 实例方法计算当前 key 的初始散列槽号
        hashvalue = self.hashfunction(key, self.size)

        # 分支 1：目标槽位为空，直接填入 key 和 data，有效计数属性 count 加 1
        if self.slots[hashvalue] is None:
            self.slots[hashvalue] = key
            self.data[hashvalue] = data
            self.count += 1
        else:
            # 分支 2：目标槽位已存放相同的 key，直接用新 data 替换旧值（不增加 count）
            if self.slots[hashvalue] == key:
                self.data[hashvalue] = data
            else:
                # 分支 3：发生冲突，调用 rehash() 实例方法线性探测下一个槽位
                nextslot = self.rehash(hashvalue, self.size)
                while self.slots[nextslot] is not None and self.slots[nextslot] != key:
                    nextslot = self.rehash(nextslot, self.size)

                if self.slots[nextslot] is None:
                    self.slots[nextslot] = key
                    self.data[nextslot] = data
                    self.count += 1
                else:
                    self.data[nextslot] = data
```
