# 递归调用的实现
## 函数调用与系统调用栈
当一个**函数**被调用的时候，系统会把调用时的 **现场数据** 压入到 **系统调用栈** 中。
每次调用，压入栈的现场数据称为 **栈帧（Stack Frame）**。
当**函数**返回时，要从调用栈的栈顶取得 **返回地址**，恢复现场，弹出 **栈帧**，按地址返回。
[[301~302.线性结构及栈抽象数据类型|栈]]
![[file-20261030231400502.png]]
>[!notes] 现场数据与栈帧的组成
>**栈帧**中保存的“现场数据”通常包含：
>当前调用的**函数参数**（如 `n`、`base`）
>**局部变量**以及当前调用结束后继续执行的**返回地址**（即调用点指令位置）。
>
>由于递归调用是**函数**调用自身，每一次递归都会在**系统调用栈**顶开辟一个新的**独立栈帧**，各层级的同名局部变量彼此隔离、互不覆盖。
## 实例解析：进制转换递归调用过程 (`toStr`)
以十进制整数 `10` 转换为二进制字符串（即调用 `toStr(10, 2)` **函数**）为例，其递归调用入栈与返回出栈的完整次序如下：
### 1. 调用次序（逐层入栈）
**第1层调用（栈底栈帧）**：调用 `toStr(10, 2)` **函数**，当前栈帧记录局部变量 `n = 10`、`base = 2`，挂起等待表达式 `toStr(10 // 2, 2) + convertString[10 % 2]`（即 `toStr(5, 2) + '0'`），压入**系统调用栈**。
**第2层调用（第2层栈帧）**：调用 `toStr(5, 2)` **函数**，当前栈帧记录局部变量 `n = 5`、`base = 2`，挂起等待表达式 `toStr(5 // 2, 2) + convertString[5 % 2]`（即 `toStr(2, 2) + '1'`），压入**系统调用栈**。
**第3层调用（第3层栈帧）**：调用 `toStr(2, 2)` **函数**，当前栈帧记录局部变量 `n = 2`、`base = 2`，挂起等待表达式 `toStr(2 // 2, 2) + convertString[2 % 2]`（即 `toStr(1, 2) + '0'`），压入**系统调用栈**。
**第4层调用（栈顶，触发基本结束条件）**：调用 `toStr(1, 2)` **函数**，此时满足基本结束条件 `1 < 2`（`n < base`），不再继续递归，直接得出返回值 `'1'`。
### 2. 返回次序（逐层出栈）
**第4层返回**：`toStr(1, 2)` **函数**直接向第3层返回字符串 `'1'`。
**第3层恢复与弹出**：恢复 `toStr(2, 2)` **栈帧**现场，计算 `'1' + '0'` 得到 `'10'`，弹出该**栈帧**并向第2层返回 `'10'`。
**第2层恢复与弹出**：恢复 `toStr(5, 2)` **栈帧**现场，计算 `'10' + '1'` 得到 `'101'`，弹出该**栈帧**并向第1层返回 `'101'`。
**第1层恢复与弹出**：恢复栈底 `toStr(10, 2)` **栈帧**现场，计算 `'101' + '0'` 得到最终结果 `'1010'`，弹出栈底**栈帧**，整个递归调用执行完毕。

```python
# 定义进制转换递归函数 toStr()，接收整数参数 n 与进制基数参数 base
def toStr(n, base):
    # 定义局部字符串变量 convertString，用于映射余数到对应字符
    convertString = "0123456789ABCDEF"
    # 基本结束条件（最小规模问题）：当参数 n 小于参数 base 时直接查表返回
    if n < base:
        return convertString[n]
    else:
        # 减小问题规模：递归调用 toStr() 函数自身，并将返回结果与当前余数字符拼接
        return toStr(n // base, base) + convertString[n % base]
```

>[!tips] 调用栈的后进先出（LIFO）特性
>观察上述过程可以发现：**调用次序（入栈）** 是从 `toStr(10)` 递减到 `toStr(1)`，而 **返回次序（出栈）** 则是从 `toStr(1)` 回溯拼接到 `toStr(10)`。
>这体现了**系统调用栈**严格遵循 **后进先出（LIFO）** 的栈结构规律，编译器/解释器在底层自动借助系统栈完成了现场保护与逆序回溯。
# Python中的递归深度限制
## RecursionError 异常与成因
在调试递归算法程序的时候，经常会碰到这样的错误：**`RecursionError` 异常类** 
[[25.例外处理|异常处理]]。
产生原因在于：**递归的层数太多，系统调用栈容量有限**

```python
# 定义无参递归函数 tell_story()
def tell_story():
    # 调用内置函数 print() 输出字符串
    print("“从前有座山，山上有座庙，庙里有个老和尚，他在讲：")
    # 在函数内部无条件递归调用 tell_story() 函数自身（缺失基本结束条件）
    tell_story()

# 调用内置函数 print() 输出提示语
print("给你讲个故事：")
# 调用 tell_story() 函数启动递归
tell_story()
```

## 递归溢出的排查方向
当程序抛出 `RecursionError` **异常类**时，应当重点从以下两个维度检查代码逻辑（对应[[401.什么是递归|递归三定律]]中的前两条）：
**检查基本结束条件**：检查程序中是否**忘记设置基本结束条件（Base Case）**，或者条件判断分支永远无法触发，导致**无限递归**（如上方 `tell_story()` **函数**示例）。
**检查演进速度**：检查递归调用向**基本结束条件演进是否太慢**（例如每次递归问题规模缩减过小，或输入数据规模过大），导致在到达基本结束条件前递归层数已经超出系统上限，引发**调用栈溢出（Stack Overflow）**。

# 使用 sys 模块获取与调整递归深度
在 Python 内置的 `sys` **模块**中，提供了专门的**函数**用于获取和调整解释器允许的最大递归深度：
`sys.getrecursionlimit()` **函数**：获取当前 Python 解释器设置的最大递归深度限制（默认返回值为 `1000` 层）。
`sys.setrecursionlimit(limit)` **函数**：将 Python 解释器的最大递归深度上限修改为指定的整数参数 `limit`。
```python
# 导入 Python 内置的 sys 模块
import sys

# 调用 sys 模块的 getrecursionlimit() 函数获取默认最大递归深度（默认返回 1000）
sys.getrecursionlimit()
# 输出: 1000

# 调用 sys 模块的 setrecursionlimit() 函数将最大递归深度调整为 3000
sys.setrecursionlimit(3000)

# 再次调用 sys 模块的 getrecursionlimit() 函数验证修改结果
sys.getrecursionlimit()
# 输出: 3000
```

>[!attention] 调整递归深度的注意事项
>1. **默认限制的目的**：Python 默认将最大递归深度限制为 `1000`，是为了防止错误的无限递归耗尽操作系统分配给进程的内存空间，从而避免整个 Python 解释器进程直接崩溃（Segmentation Fault）。
>2. **并非无限调大**：调用 `sys.setrecursionlimit()` **函数**只能调高 Python 解释器层面的计数阈值，实际可达到的递归深度仍然受限于操作系统底层的 **C 语言调用栈物理内存大小**。若递归层数极深，建议改写为基于循环与显式栈的非递归（迭代）算法。
