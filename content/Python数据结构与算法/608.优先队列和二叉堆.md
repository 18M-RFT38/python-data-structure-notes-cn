# 优先队列 Priority Queue
## 基本概念与应用场景
前面我们学习了一种 **FIFO（先进先出）** 数据结构：[[308~309.队列抽象数据类型与热土豆问题|队列]]。
队列有一种变体称为 **“优先队列（Priority Queue）”**。
**现实与系统中的典型场景**：
银行窗口取号排队时，VIP 客户可以插到队首优先办理。
操作系统中执行关键任务的进程或用户特别指定的进程，在调度队列中靠前。
（例如在 Windows 任务管理器中选中 `wps.exe` 等进程，设置优先级为实时、高、高于正常、正常、低于正常或低）
![[file-20261118112327054.png|287]]
## 优先队列的内部次序与操作复杂度
优先队列的 **出队（Dequeue）** 跟普通队列一样，始终从 **队首** 出队。
但在优先队列内部，数据项的次序却是由 **“优先级”** 来确定的：
**高优先级** 的数据项排在队首，而 **低优先级** 的数据项则排在后面。
这样，优先队列的 **入队（Enqueue）** 操作就比较复杂，需要将新加入的数据项根据其优先级尽量挤到队列前方。

> [!question] 
> 有什么方案可以用来实现优先队列？出队和入队的复杂度大概是多少？
>
> 如果采用线性结构（如 Python 的 `list` 列表）维护有序表，每次插入新元素时，即使使用二分查找在 $O(\log n)$ 时间内找到插入位置，移动后续元素依然需要 $O(n)$ 的时间复杂度。
> 为了同时优化入队和出队的性能，我们需要放弃完全线性的排列，转而采用 **树形结构（二叉堆 Binary Heap）**。
> 二叉堆利用完全二叉树的高度性质，不要求所有元素全局绝对排好序，只维持父子节点的偏序关系，从而将 **入队** 和 **出队** 的时间复杂度同时优化并稳定在 $O(\log n)$ 水平！
# 二叉堆 Binary Heap 实现优先队列
## 二叉堆的核心特性与分类
实现优先队列的经典方案是采用 **二叉堆（Binary Heap）** 数据结构。
二叉堆能够将优先队列的 **入队** 和 **出队** 复杂度都保持在 $O(\log n)$。

二叉堆的有趣之处在于，其 **逻辑结构** 上像二叉树，物理实现上却是用 **非嵌套的列表（单层 `list`）** 来实现的！

**最小堆（min heap）**：最小 `key` 排在队首的二叉堆。
**最大堆（max heap）**：反之，最大 `key` 排在队首的二叉堆。
## ADT BinaryHeap 的操作定义
`BinaryHeap()` 类（构造器）：创建一个空二叉堆对象。
`insert(k)` 实例方法：将新 `key` 加入到堆中。
`findMin()` 实例方法：返回堆中的最小项，最小项仍保留在堆中。
`delMin()` 实例方法：返回堆中的最小项，同时从堆中删除。
`isEmpty()` 实例方法：返回堆是否为空。
`size()` 实例方法：返回堆中 `key` 的个数。
`buildHeap(list)` 实例方法：从一个 `key` 列表创建新堆。
## 代码演示：使用 pythonds 模块中的 BinHeap
```python
from pythonds.trees.binheap import BinHeap

# 调用 BinHeap() 类（构造器）创建一个空的最小二叉堆实例对象 bh
bh = BinHeap()

# 调用 bh 对象的 insert() 实例方法，依次将整数 key 插入二叉堆中
bh.insert(5)
bh.insert(7)
bh.insert(3)
bh.insert(11)

# 调用 bh 对象的 delMin() 实例方法移除并返回当前最小项，传给 print() 函数输出
print(bh.delMin()) # 输出：3
print(bh.delMin()) # 输出：5
print(bh.delMin()) # 输出：7
print(bh.delMin()) # 输出：11

```

无论 `insert()` 实例方法插入数据的顺序如何（如依次插入 `5, 7, 3, 11`）。
每次调用 `delMin()` 实例方法出队时，总是按照从小到大的优先级顺序（`3 -> 5 -> 7 -> 11`）依次弹出最小元素。
# 用非嵌套列表实现二叉堆
## 树的平衡性与完全二叉树
为了使堆操作能保持在 **对数水平（**$O(\log n)$**）** 上，就必须采用二叉树结构。
同样，如果要使操作 **始终** 保持在对数数量级上，就必须始终保持二叉树的 **“平衡”**（即树根左右子树拥有相同或相近数量的节点）。
![[file-20261118112901595.png]]

> [!question] 
> 对于一个 $k$ 层的二叉树来说，最好的节点个数是 $2^k - 1$ 个，为什么？
> **底层原理解析**：
> 1. **等比数列求和（满二叉树）**：在二叉树中，第 1 层（根节点）最多有 $2^0 = 1$ 个节点，第 2 层最多有 $2^1 = 2$ 个节点，……，第 $k$ 层最多有 $2^{k-1}$ 个节点。
> 当每一层都完全填满（即形成 **满二叉树 / 完美二叉树**）时，整棵树的节点总数恰好为等比数列求和：
> 
$$N = 2^0 + 2^1 + 2^2 + \dots + 2^{k-1} = 2^k - 1$$
>
> 2. **为什么是“最好”的**：在固定层数 $k$ 下，满二叉树容纳了最多的节点数 $N = 2^k - 1$。
>反过来推导，当节点总数为 $N$ 时，树的高度 $k = \log_2(N + 1)$ 达到理论最小值，且树根左右子树的节点数量完全相等（绝对平衡）。
>由于二叉堆的插入（上浮）和删除（下沉）操作都是沿着从根到叶子的路径进行的，最大操作次数取决于树的层数 $k$，因此这种结构能把时间复杂度严格死死压在最优的 $O(\log n)$！
## 采用“完全二叉树”近似实现平衡
在实际操作中，节点个数不一定总是恰好满足 $2^k - 1$，因此我们采用 **“完全二叉树（Complete Binary Tree）”** 的结构来 **近似实现“平衡”**。

**完全二叉树的定义与结构特征**：
叶节点最多只出现在 **最底层** 和 **次底层**。
而且最底层的叶节点都 **连续集中在最左边**。
每个内部节点都有两个子节点，**最多可有 1 个节点例外**（例外：最底层最右侧叶节点的父节点可能只有左子节点而没有右子节点）。

# 完全二叉树的列表实现及性质
## 下标映射关系（核心性质）
完全二叉树由于其特殊性（节点按层从上到下、从左到右连续紧密排列，中间没有任何空洞），可以用 **非嵌套列表（单层 `list`）** 以简单的方式实现，具有非常好的数学性质。

如果节点的下标为 $p$，那么：
**左子节点下标** 为 $2p$
**右子节点下标** 为 $2p + 1$
**父节点下标** 为 $p // 2$（Python 整数整除，向下取整）
![[file-20261118112934837.png]]

> [!tips] 
> 列表首项占位技巧（Index 0 哨兵位）
> 在列表中实现二叉堆时，通常会在列表的下标 `0` 处先放一个无意义的占位元素 `0`（即初始化列表为 `[0]`），让真正的 **根节点从下标 `1` 开始存放**。
> 这样做的目的是为了直接套用 $2p$、$2p+1$ 和 $p // 2$ 公式！如果根节点从 `0` 开始，套用 $2 \times 0$ 依然是 `0`，公式就会变成 $2p+1$ 和 $2p+2$，不如从下标 `1` 开始直观简明。
# 堆次序 Heap Order
![[file-20261118113104472.png|335]]
**堆次序（Heap Order，以最小堆为例）**：任何一个节点 $x$，其父节点 $p$ 中的 `key` 均 **小于或等于** $x$ 中的 `key`。
这样，符合“堆”性质的二叉树，其中 **任何一条从根节点到叶节点的路径，均是一个已排序数列**，且 **根节点的 `key` 最小**（始终位于列表下标 `1` 的位置）。

> [!attention]
>  易错点辨析：堆次序 vs 二叉搜索树（BST）次序
> 二叉堆只保证 **父节点与子节点之间** 的大小关系（纵向路径有序），**不保证左右兄弟节点或不同分支之间** 的绝对大小关系！
> 例如在示例树中，第 3 层的节点 `14` 和 `18`（左子树分支）拥有子节点 `33`、`17`、`27`，它们比同一层甚至下一层右子树分支的节点 `19`、`21` 还要大，但这完全符合堆次序——因为只要满足 $5 < 9 < 14 < 33$ 以及 $5 < 11 < 19$ 这样每条纵向路径递增即可。
