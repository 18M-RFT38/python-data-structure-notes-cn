# 散列函数的最酷应用：区块链技术
## 分布式数据库基本概念
作为 [[508.什么是散列|散列函数]] 与 [[509.完美散列函数|加密散列算法]] 最具代表性的现代工程应用，**区块链（Blockchain）** 本质上是一种 **分布式数据库**。
它由通过网络相互连接的众多节点（Node）共同组成。
网络中的每个节点都完整保存着整个数据库的所有数据副本。
在任何地点、任何节点存入的数据，最终都会在全网所有节点之间完成同步。
## 核心本质特征：去中心化
区块链最本质的特征是 **“去中心化”（Decentralization）**。
整个网络中不存在任何控制中心节点或协调中心节点。
所有节点的地位都是平等的，没有任何单一机构或个体能够控制整个网络。
>[!question] 去中心化网络的核心信任难题
>在没有中心化权威机构背书、且节点之间不需要相互信任的开放网络环境中，如何才能防止历史账本数据被恶意篡改和破坏？这正是区块链通过“链式散列结构”与“工作量证明机制”协同解决的核心问题。
# 区块链的基本结构与不可修改性
## 区块的内部组成（Head 与 Body）
区块链由一个个按时间顺序相连的 **区块（block）** 组成，每个区块在结构上分为 **区块头（head）** 和 **区块体（body）** 两部分。

**区块头（head）**：记录当前区块的 **元数据（Metadata）** 以及**链接到前一个区块**的信息。核心包含区块 **生成时间（Timestamp）** 与 **前一个区块整体（`head+body`）的散列值**。

**区块体（body）**：记录实际业务数据（`Data`），例如在加密货币系统中记录具体的交易明细账本。
>[!notes] 数据结构视角：带哈希指针的逆向单向链表
>对比 [[313~314.无序表抽象数据类型及其python实现#链式存储的基本思想|链表]]，普通链表节点（`Node` 类）通过 `next` 引用属性指向后继节点的内存地址；
>而区块链中的每个区块通过区块头中的 `prev: H( )` 散列值属性逆向指向前驱区块：
>$$H_{\text{prev}} = \text{Hash}(\text{Head}_{i-1} \parallel \text{Body}_{i-1})$$
>这种同时保存“前驱指向关系”与“前驱全量数据密码学摘要”的指针称为 **哈希指针（Hash Pointer）**，链条最末端指向最新区块的 `H( )` 即为整条区块链的数字指纹锚点。

![[file-20261114172935424.png|365]]
## 区块链的不可修改性（抗篡改原理）
由于密码学散列值具有极强的 **抗修改性（雪崩效应与抗碰撞性）**，任何对某个历史区块（如 `Block 51`）内部数据的微小改动，必然引起该区块整体散列值的剧烈变化。

一旦该区块的散列值改变，其后继区块（`Block 52`）区块头中记录的“前驱区块散列值”就会与之失配，导致被改动的区块脱离链条。
为了不导致这个区块脱离链条，篡改者就必须同步重新计算并修改其后 **所有后续区块**（`Block 52`、`Block 53`、`Block 54`……）的散列值。

由于区块链引入了 **“工作量证明”** 的机制，这种大规模链式重算在现实中是不可能实现的，除非篡改者掌握了 **全网 51% 以上的计算力**（即 **51% 算力攻击**）。

# 工作量证明：Proof of Work (PoW)
## 出块速度控制与矿工算力竞争
由于区块链是大规模的分布式数据库，全网节点之间的网络广播与数据同步较慢，因此新区块的添加速度必须得到严格控制。
目前最大规模的区块链 **Bitcoin（比特币）** 采用的控制速度是：**平均每 10 分钟生成一个区块**。

在工作量证明（Proof of Work, 简称 **PoW**）机制下，全网参与者不惜付出海量的计算资源，去抢着算出一个区块的 **有效散列值**。
只有最先算出有效散列值的那位 **“矿工”（Miner）**，才有资格把新区块挂接（追加）到区块链主链中。
>[!question] 既然散列函数极易计算，为什么要付出海量计算？
>根据 [[509.完美散列函数|散列函数的性质]]，正向计算一次 SHA-256 散列值的时间复杂度仅为常数阶 $O(1)$ [[202.大O表示法#常见的大O数量级|大O数量级]]。
>但密码学散列函数具有严格的 **单向性（不可逆性）**，无法根据目标散列值反推输入。
>矿工并非只算一次散列，而是为了寻找满足特定数值上限（`target`）的“有效散列值”，必须不断修改区块头中的随机数（`Nonce` 属性）并重复执行海量次正向散列试探。
## 有效散列值的判定：难度系数 Difficulty 与目标值 target
正是因为有效散列值很难算出，才从算法层面 **控制了新区块生成的速度**，便于在整个分布式网络中进行同步。

每个区块都设置了一个 **难度系数（`Difficulty`）**，系统用最大目标常数 **`targetmax`** 除以 **`difficulty`**，得到当前区块的目标阈值 **`target`**：
$$\text{target} = \frac{\text{targetmax}}{\text{difficulty}}$$
**难度变化规律**：难度系数 `Difficulty` 越高，计算出的阈值 `target` 越小，意味着要凑出小于或等于 `target` 的有效散列值就越困难（即散列值十六进制表示开头必须包含更多连续的前导 `0`）。

![[file-20261114173357431.png|360]]
课件给出的目标阈值计算公式与 256 位十六进制常数定义如下：
```python
# 访问预设的最大目标常量 targetmax（256位无符号整数，前32位二进制全为0，即前8位十六进制为0）
targetmax = 0x00000000FFFF0000000000000000000000000000000000000000000000000000
# 定义当前区块的难度系数变量 difficulty（浮点数/整数）
difficulty = 14484.162361

# 通过除法运算符计算当前区块的目标阈值变量 target
target = targetmax / difficulty
```
## 模拟过程
结合 Python 标准库 `hashlib` 模块 [[509.完美散列函数|hashlib散列库]]，可以用如下代码直观模拟矿工枚举 `nonce` 寻找有效散列值的过程：
```python
import hashlib

def mine_block(block_header_str, target):
    # 定义局部整型变量 nonce（随机数），从 0 开始枚举
    nonce = 0
    while True:
        # 调用 str() 类（构造器）将 nonce 转为字符串并与区块头拼接
        # 调用字符串对象的 encode() 方法将其编码为 UTF-8 字节串
        data_bytes = (block_header_str + str(nonce)).encode('utf-8')
        
        # 调用 hashlib 模块的 sha256() 函数创建散列对象，并调用 hexdigest() 方法获取64位十六进制散列字符串
        block_hash_hex = hashlib.sha256(data_bytes).hexdigest()
        
        # 调用 int() 类（构造器）指定基数 16，将十六进制散列字符串转换为大整数并判断是否小于目标值 target
        if int(block_hash_hex, 16) < target:
            # 命中有效散列值，返回成功时的 nonce 变量与散列字符串
            return nonce, block_hash_hex
            
        # 若未小于 target，则将局部变量 nonce 自增 1 继续下一轮试探
        nonce = nonce + 1
```

>[!tips] 前导零（Leading Zeros）与目标值 target 的等价关系
>由于 SHA-256 输出的散列值固定为 256 位无符号整数（64 位十六进制数），将其数值限制在 `target` 以下，等价于要求该 64 位十六进制字符串的高位（左侧开头）必须出现足够多个连续的 `0`。`difficulty` 越大，`target` 越小，要求的前导 `0` 个数就越多，单次哈希命中的概率呈指数级下降。

>[!attention] 为什么矿工实际到账 12.69684668 BTC 大于固定奖励 12.5 BTC？
>矿工成功打包一个区块所获得的总收益由 **“区块固定记账奖励（Block Subsidy）”** 与 **“区块内所有交易的手续费总和（Transaction Fees）”** 两部分相加构成：
>$$\text{矿工总收益} = 12.5\text{ BTC（固定记账奖励）} + 0.19684668\text{ BTC（2375笔交易手续费）} = 12.69684668\text{ BTC}$$
# 挖矿经济激励与算力演进
## 为什么矿工抢着生成区块？（利益驱动与记账奖励）
矿工不惜投入巨额硬件与电力成本抢着生成区块，最直接的原因是 **因为有利益**。
在加密货币 Bitcoin 体系中，每个区块内包含的数据是 **“交易记录”**，也就是全网共享的 **“账本”**，维护账本的一致性与安全性对于货币体系至关重要。
Bitcoin 协议规定，每个新生成的区块中都包含了一定数量的比特币作为 **“记账奖励”**，这种经济激励机制鼓励了全球更多人加入到抢先记账（挖矿）的行列中。

![[file-20261114173618119.png|434]]
以课件截取时点（2019 年 8 月 29 日）的汇率 **`1 BTC = 9,498.07 美元`** 计算，单个区块 `12.69684668 BTC` 的记账收益折合超过 **12 万美元**；而在 2017 年 12 月 15 日的历史峰值（**`1 BTC = 19,650.01 美元`**）时，单个区块奖励价值更是接近 **25 万美元**。

## 硬件摩尔定律与挖矿算力升级
由于硬件 **摩尔定律（Moore's Law）** 的存在，全网挖矿计算力将持续递增；为了维持平均每 10 分钟生成一个区块的恒定速度，区块链的难度系数 **`Difficulty`** 也将随之动态持续递增。
挖矿硬件与算力量级的演进历程如下：
**CPU 挖矿阶段**：约 $20\text{ MHash/s}$（每秒 $2 \times 10^7$ 次散列运算）。
**GPU（显卡）挖矿阶段**：约 $400\text{ MHash/s}$（每秒 $4 \times 10^8$ 次散列运算）。
**FPGA（现场可编程门阵列）阶段**：约 $25\text{ GHash/s}$（每秒 $2.5 \times 10^{10}$ 次散列运算）。
**ASIC（专用集成电路矿机）阶段**：单机约 $3.5\text{ THash/s}$（每秒 $3.5 \times 10^{12}$ 次散列运算）。
**大规模工业集群挖矿阶段**：算力达到 $3.5\text{ THash/s} \times X$，演变为依托大型机房机柜、专业散热通道与高空作业车运维的重资产工业级矿场。
![[file-20261114173705440.png|359]]
## 比特币总量控制与每 4 年减半机制
为了保持货币总量不会无限增加（防止恶性通货膨胀），Bitcoin 协议规定 **每 4 年（每产生 210,000 个区块）奖励的比特币数量减半**。
**2008 年（创世之初）**：每个区块固定记账奖励为 **`50` 个 BTC**。
**2012 年（第一次减半）**：每个区块固定记账奖励降至 **`25` 个 BTC**。
**2016 年至 2019 年（课件录制时）**：每个区块固定记账奖励为 **`12.5` 个 BTC**。
>[!notes] 比特币 2100 万枚总量上限的数学推导
>按平均每 10 分钟生成 1 个区块计算，4 年（约 $210,000$ 个区块）构成一个减半周期。利用无穷等比数列求和公式，比特币最终发行的货币总量上限恒定收敛于 **2100 万枚**：
>$$\text{Total BTC} = \sum_{i=0}^{32} 210000 \times \frac{50}{2^i} \approx 210000 \times 50 \times 2 = 21,000,000\text{ BTC}$$
>当未来固定记账奖励趋近于 `0` 后，矿工维护区块链网络的收益将完全由区块内的 **交易手续费（Transaction Fees）** 支撑。
# 区块链技术飞速扩张的应用生态
除数字货币（`Currencies`，如 Bitcoin、Litecoin、Zcash）外，基于散列防篡改与分布式共识的区块链技术已飞速扩张至全行业应用生态（参考 `https://36kr.com/p/5114727.html` 及 `BLOCKCHAIN PROJECT ECOSYSTEM` 全景图）：
![[file-20261114173725885.png|355]]
**开发者工具与智能合约（Developer Tools）**：涵盖智能合约平台（Smart Contracts，如 Ethereum）、链下扩容方案（Scaling，如 Lightning Network）、预言机（Oracles）及跨链互操作协议（Interoperability，如 Polkadot、Cosmos）。
**主权治理与数字身份（Sovereignty）**：涵盖去中心化自治组织治理（Governance）、去中心化数字身份认证（Identity）与稳定币（Stablecoins）。
**金融科技（Fintech）**：涵盖去中心化交易所（Trading/DEX）、去中心化借贷（Lending）、链上保险（Insurance）与数字资产管理。
**价值交换与分布式资源（Value Exchange）**：涵盖内容创作变现（Content Monetization）、分布式文件存储（File Storage，如 Filecoin、Sia）、分布式算力共享（Computation）及非同质化数字资产（Non-Fungible Tokens）。
**共享数据与防伪溯源（Shared Data & Authenticity）**：涵盖物联网数据协同（Internet of Things）、供应链与物流溯源（Supply Chain/Logistics）、权威数据存证（Data）与防伪票务（Ticketing）。
