# 复杂递归问题：汉诺塔（河内塔）
## 历史传说与搬盘规则
汉诺塔（又称河内塔，Tower of Hanoi）问题是法国数学家 **Edouard Lucas** 于 **1883年** 根据传说提出来的经典复杂递归问题。
传说一个印度教寺庙里，有 **3根柱子**，其中一根套着 **64个由小到大的黄金盘片**。僧侣们的任务就是要把这一叠黄金盘从一根柱子搬到另一根，但必须遵守**两个规则**：
**规则一**：一次只能搬 **1个** 盘子。
**规则二**：**大盘子全程不能叠在小盘子上**。
传说神的旨意说一旦这些盘子完成迁移，寺庙将会坍塌，世界将会毁灭。
![[file-20261102151001798.png|123]]
## 移动次数与时间复杂度测算
虽然这些黄金盘片跟世界末日有着神秘的联系，但我们却不必太担心。据计算，要搬完这 64 个盘片：
需要的移动次数为 $2^{64} - 1 = 18,446,744,073,709,551,615$ 次。
如果每秒钟搬动一次，则需要 $584,942,417,355$（约 **五千亿**）年！
>[!notes] 汉诺塔移动次数的递推公式推导
>设移动 $n$ 个盘片所需的最少次数为 $T(n)$。根据将上层 $n-1$ 个盘片移走、移动最底层第 $n$ 号大盘、再将 $n-1$ 个盘片移回目标柱的三步过程，可列出递推关系式：
>$$T(n) = 2T(n - 1) + 1, \quad T(1) = 1$$
>通过递推展开 $T(n) + 1 = 2\bigl(T(n - 1) + 1\bigr) = 2^n$，即可求得通项公式 $T(n) = 2^n - 1$，其时间复杂度为指数阶 $O(2^n)$ [[202.大O表示法|大O表示法]]。
# 河内塔问题：分解为递归形式
## 从递归三定律切入分析
面对 $64$ 个或任意 $N$ 个盘片的复杂移动问题，直接人工推演每一步的去向十分困难。我们依然从 [[401.什么是递归#递归“三定律”|递归三定律]] 来分析河内塔问题：寻找 **基本结束条件（最小规模问题）**、思考 **如何减小规模**、以及如何 **调用自身**。
## 以 5 个盘子为例的规模拆解
假设我们有 **5个盘子**，初始穿在 **1#柱（开始柱 `fromPole`）**，需要挪到 **3#柱（目标柱 `toPole`）**，并以 **2#柱（中间柱 `withPole`）** 作为过渡借助：
如果能 **有办法** 把最上面的一摞 **4个盘子** 统统挪到 **2#柱**，那问题就好解决了。
接着把剩下的 **最大号盘子（第5号盘）** 直接从 **1#柱** 挪到 **3#柱**。
最后再用 **同样的办法** 把 **2#柱** 上的那一摞 **4个盘子** 挪到 **3#柱**，就完成了整个移动。
![[file-20261102151055672.png|257]]
## 逐级缩小规模直至 1 个盘子
接下来问题就转化为：如何解决 **4个盘子** 从 **1#柱** 挪到 **2#柱**？此时 **问题规模已经从 5 减小为 4**！
同样是 **想办法** 把上面的一摞 **3个盘子** 挪到 **3#柱**（此时 3#柱充当中间过渡柱），把剩下最大号盘子（第4号盘）从 **1#柱** 挪到 **2#柱**，再用 **同样的办法** 把一摞 **3个盘子** 从 **3#柱** 挪到 **2#柱**。
一摞 **3个盘子** 的挪动也照此办理：分为上面一摞 **2个盘子**，和下面最大号盘子（第3号盘）。
那么 **2个盘子** 怎么移动？不行，就再继续分解为 **1个盘子** 的移动！
# 河内塔问题：递归思路
## 移动 N 个盘片塔的通用三步法则
将高度为 $N$ 的盘片塔从 **开始柱（`fromPole`）**，经由 **中间柱（`withPole`）**，移动到 **目标柱（`toPole`）**，其通用递归过程归纳为以下三步：
**第一步（移开上层 $N-1$ 盘片塔）**：首先将上层 $N-1$ 个盘片的盘片塔，从 **开始柱**，经由 **目标柱**，移动到 **中间柱**。
**第二步（移动底层第 $N$ 号最大盘）**：然后将第 $N$ 个（最大的）盘片，直接从 **开始柱**，移动到 **目标柱**。
**第三步（归位 $N-1$ 盘片塔）**：最后将放置在 **中间柱** 的 $N-1$ 个盘片的盘片塔，经由 **开始柱**，移动到 **目标柱**。
## 基本结束条件（最小规模问题）
上述分解过程的 **基本结束条件**（即最小规模问题）就是：**1个盘片的移动问题**（直接将该盘片从当前开始柱移动到当前目标柱，或当盘片数减为 $0$ 时无需执行任何操作直接返回）。
# 河内塔问题：代码实现与执行过程
## 完整 Python 源码
上面的递归思路用 Python 写出来，几乎跟自然语言描述完全一样：
```python
# 定义移动盘片塔的递归函数 moveTower()
# height：当前盘片塔的盘子数量（高度）形参变量
# fromPole：开始柱名称形参变量；withPole：中间过渡柱名称形参变量；toPole：目标柱名称形参变量
def moveTower(height, fromPole, withPole, toPole):
    # 基本结束条件判断：当盘片高度变量 height >= 1 时才执行三步移动；当 height == 0 时直接退出返回
    if height >= 1:
        # 第一步：减小规模（height - 1），递归调用 moveTower() 函数自身
        # 将上层 height - 1 个盘片从开始柱 fromPole 经由目标柱 toPole 移动到中间柱 withPole
        moveTower(height - 1, fromPole, toPole, withPole)
        # 第二步：调用辅助函数 moveDisk()，将当前最底层的最大盘片 height 直接从开始柱 fromPole 移到目标柱 toPole
        moveDisk(height, fromPole, toPole)
        # 第三步：减小规模（height - 1），再次递归调用 moveTower() 函数自身
        # 将暂存在中间柱 withPole 的 height - 1 个盘片经由开始柱 fromPole 移动到目标柱 toPole
        moveTower(height - 1, withPole, fromPole, toPole)

# 定义移动单个盘片的辅助函数 moveDisk()
# disk：当前被移动的盘片编号形参变量；fromPole：移出柱形参变量；toPole：移入柱形参变量
def moveDisk(disk, fromPole, toPole):
    # 调用内置函数 print()，使用 f-string 格式化字符串输出单步移动盘片的动作日志
    print(f"Moving disk[{disk}] from {fromPole} to {toPole}")

# 调用 moveTower() 递归函数，测试将 3 个盘片从 "#1" 号柱经由 "#2" 号柱移动到 "#3" 号柱
moveTower(3, "#1", "#2", "#3")
```
## 运行结果与执行过程剖析
执行上述代码（`moveTower(3, "#1", "#2", "#3")`），控制台共输出 $2^3 - 1 = 7$ 行移动步骤：
![[file-20261102151141692.png|277]]
### 7 步输出与递归三阶段的一一对应
观察 `moveTower(3, "#1", "#2", "#3")` 函数的 7 行输出，可以清晰看到顶层递归三个阶段的边界：
**第一阶段（第 1～3 行输出）**：对应顶层第 3 行代码 `moveTower(2, "#1", "#3", "#2")` 函数的完整执行结果——将上层 `disk[1]` 和 `disk[2]` 两个盘片组成的子塔从 `#1` 柱经由 `#3` 柱全部搬到了 `#2` 中间柱上。
**第二阶段（第 4 行输出）**：对应顶层第 4 行代码 `moveDisk(3, "#1", "#3")` 函数的执行结果——此时 `#1` 柱只剩下最大的 `disk[3]`，直接将其从 `#1` 柱搬到最终目标 `#3` 柱（`Moving disk[3] from #1 to #3`）。
**第三阶段（第 5～7 行输出）**：对应顶层第 5 行代码 `moveTower(2, "#2", "#1", "#3")` 函数的完整执行结果——将 `#2` 柱上的 `disk[1]` 和 `disk[2]` 子塔经由 `#1` 柱全部搬到 `#3` 目标柱上，叠放在 `disk[3]` 之上。

>[!tips] 为什么代码中的基本结束条件写的是 `if height >= 1:` 而不是 `if height == 1:`？
>课件代码采用了极简的隐式基线写法：当递归下降到只有 1 个盘片（`height == 1`）时，进入 `if height >= 1:` 分支后会依次调用 `moveTower(0, …)`、`moveDisk(1, fromPole, toPole)` 和 `moveTower(0, …)`。
>其中两次 `height == 0` 的 `moveTower(0, …)` 函数调用因不满足 `height >= 1` 会立即空操作返回（真正的递归终止出口为 `height == 0`），从而只执行中间那句 `moveDisk(1, fromPole, toPole)`，等价于直接移动 1 个盘片！
>若改写为显式处理 1 个盘片的形式，代码逻辑完全等价：
>```python
>def moveTower(height, fromPole, withPole, toPole):
>    if height == 1:
>        # 基本结束条件：只有 1 个盘片时，直接调用 moveDisk() 函数从开始柱移到目标柱
>        moveDisk(1, fromPole, toPole)
>    else:
>        moveTower(height - 1, fromPole, toPole, withPole)
>        moveDisk(height, fromPole, toPole)
>        moveTower(height - 1, withPole, fromPole, toPole)
>```

>[!attention] 核心易错点：三次调用中柱子形参的角色轮换
>在定义 `moveTower(height, fromPole, withPole, toPole)` 函数时，四个位置形参的固定语义依次为 `(盘片数, 起始柱, 借用过渡柱, 目标柱)`。
>1. **第一次递归调用** `moveTower(height - 1, fromPole, toPole, withPole)`：目标是把上层小盘先挪到中间柱 `withPole` 暂存，因此 **`withPole` 填在最后一个参数（目标柱）位置**，而原本的目标柱 **`toPole` 填在倒数第二个参数（借用过渡柱）位置**。
>2. **第二次递归调用** `moveTower(height - 1, withPole, fromPole, toPole)`：此时上层小盘已经位于 `withPole` 上，需要从 `withPole` 搬往最终的 `toPole`，因此 **`withPole` 填在第二个参数（起始柱）位置**，而空出来的 **`fromPole` 填在第三个参数（借用过渡柱）位置**。
