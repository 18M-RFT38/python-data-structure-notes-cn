# 信息广播问题与最小生成树
本节承接 [[712.最短路径问题与dijkstra算法|Dijkstra 最短路径算法]]，探讨互联网路由器网络中的**信息广播问题**（Information Broadcast Problem），并由此引出 **最小生成树（Minimum Spanning Tree, MST）** 及经典贪心解法 **Prim 算法**。
## 问题引入与三种解法对比
在互联网中，网游设计者需要让所有玩家实时获知其他玩家所在的位置，网络收音机需要让所有听众同步获取直播的音频数据，两者面临的核心问题都是将同一份消息从广播源（`Broadcast host`）高效分发给所有收听者（`Listener`）。
![[file-20261123211328557.png|377]]
以上方拓扑图为例，广播源经由入口路由器 `A` 接入网络，4 个收听者分别连接在路由器 `C`、`D`、`E`、`G` 上，各路由器之间带有代表通信费用的边权重。
### 单播解法（Unicast）
最简单的解法是由广播源维护一个收听者列表，针对每个收听者分别采用 [[712.最短路径问题与dijkstra算法|最短路径算法]] 单独发送一次消息。
![[file-20261123211505652.png|379]]
由于图中共有 4 个收听者，每条消息会被发送 $4$ 次；其中路由器 `A` 会处理 $4$ 次相同消息，`C` 仅处理 $1$ 次，而位于其它 $3$ 个收听者最短路径上的 `B` 和 `D` 各会处理并转发 $3$ 次相同消息，从而产生许多**额外流量**。
### 洪水解法（Flooding）与 TTL 限制
信息广播问题的暴力解法是将每条消息在路由器间散布出去，所有路由器都将收到的消息转发到自己相邻的路由器和收听者。
如果没有任何限制，消息会在环路中不断被重复接收、永不停止，造成**网络洪水灾难**（广播风暴）。

为此，洪水解法一般会给每条消息附加一个生命值 **TTL（Time To Live）**，初始设置为从消息源到最远收听者的距离；
每个路由器收到消息后，若 $\text{TTL} > 0$ 则将 $\text{TTL}$ 减 $1$ 再转发，若 $\text{TTL} = 0$ 则直接抛弃。
TTL 的设置防止了无限循环灾难的发生，但这种洪水解法显然比前述的单播方法所产生的流量还要大。
### 最小生成树解法（最优解）
信息广播问题的最优解法，依赖于在路由器关系图上选取具有**最小权重的生成树**，让消息从 `A` 出发沿着树的路径层次向下传播。

| 分发方案 | 核心做法 | 流量与可靠性表现 |
| :--- | :--- | :--- |
| **单播解法** | 分别按最短路径向每个听众单发 | 不会死循环，但公共路由器（如 `A, B, D`）重复转发大量冗余消息 |
| **洪水解法 (+TTL)** | 向所有邻居广播扩散，TTL 归零丢弃 | 实现简单且防死循环，但总流量比单播还要大 |
| **最小生成树** | 沿着无圈最小权重树层次向下传播 | **每个路由器只需要处理 $1$ 次消息，同时总费用最小** |

## 最小生成树的定义
**生成树（Spanning Tree）** 是指拥有图中 **所有的顶点** 和 **最少数量的边** ，以保持连通的子图（若图有 $\vert{}V\vert{}$ 个顶点，则生成树恰好包含 $\vert{}V\vert{}-1$ 条边）。
![[file-20261123212806539.png|419]]

图 $G(V, E)$ 的**最小生成树 $T$** 定义为：包含所有顶点 $V$，以及 $E$ 的无圈子集，并且所有选中边的**权重之和最小**。（即在是一棵生成树的基础下，还要保证权重之和最小）

在下方拓扑图中，选取树边 `A-B(2)`、`B-C(1)`、`B-D(1)`、`D-E(1)`、`E-F(1)`、`F-G(1)`（舍弃非树边 `A-C(3)`、`B-E(4)`、`C-F(5)`）即可构成总权重为 $7$ 的最小生成树。
![[file-20261123212048559.png|409]]
信息广播就只需要从A开始，沿着树的路径层次向下传播。这样就可以达到每个路由器只需要处理1次消息，同时总费用最小。
# Prim 算法原理与执行过程
## 贪心策略与“安全边”
解决最小生成树问题的 **Prim 算法** 属于 [[408.优化问题：贪心策略|贪心策略]]，即每一步都沿着最小权重的边向前搜索。
构造最小生成树的思路十分直接：如果 $T$ 还不是生成树，则反复找到一条最小权重的**可以安全添加的边**，并将该边添加到树 $T$ 中。
> [!notes] 什么是“可以安全添加”的边？
> “可以安全添加”的边定义为：**一端顶点在树中，另一端不在树中的边**，以便保持树的无圈特性。
> ![[file-20261123213011391.png]]

在具体实现上，Prim 算法同样复用 [[702~703.图抽象数据类型及其python实现|Graph 类]] 和 [[704~705.词梯问题和广度优先搜索#BFS 与路径回溯的 Python 实现|Vertex类]]中的 `distance` **实例属性** 与 `pred` **实例属性**，并配合 [[608.优先队列和二叉堆|优先队列（PriorityQueue）]] 每次弹出距离最小的未入树顶点。

# Python 实现与逐行解析
基于 `pythonds.graphs` 模块中的 `PriorityQueue` **类**、 `Graph` **类** 与 `Vertex` **类**，定义独立的 `prim()` **函数** 实现最小生成树构建：
```python
from pythonds.graphs import PriorityQueue, Graph, Vertex  # 导入优先队列类、图类与顶点类
import sys                                                # 导入 sys 模块，用于获取最大整数常量

# 定义独立函数 prim()，形参 G 为 Graph 实例，start 为起始 Vertex 实例
def prim(G, start):
    # 1. 初始化与建堆：将所有顶点距离设为无穷大，起点设为 0 并建堆
    pq = PriorityQueue()                                  # 调用 PriorityQueue() 类构造器创建最小堆实例
    for v in G:                                           # 遍历图 G 中的每个 Vertex 实例 v
        v.setDistance(sys.maxsize)                        # 调用 Vertex 实例方法 setDistance()，初始化为 sys.maxsize 属性
        v.setPred(None)                                   # 调用 Vertex 实例方法 setPred()，初始化前驱为 None
    start.setDistance(0)                                  # 调用 Vertex 实例方法 setDistance()，将起点距离设为 0
    pq.buildHeap([(v.getDistance(), v) for v in G])       # 调用 PriorityQueue 实例方法 buildHeap()，用 (距离, 顶点) 元组列表建堆

    # 2. 主循环出队：每次取出离当前生成树最近的未入树顶点
    while not pq.isEmpty():                               # 调用 PriorityQueue 实例方法 isEmpty() 判断队列是否非空
        currentVert = pq.delMin()                         # 调用 PriorityQueue 实例方法 delMin() 弹出当前 distance 最小的顶点
        # 3. 考察邻接顶点并更新最小入树代价
        for nextVert in currentVert.getConnections():     # 调用 Vertex 实例方法 getConnections() 遍历所有邻接顶点
            newCost = currentVert.getWeight(nextVert)     # 调用 Vertex 实例方法 getWeight() 获取单条边的权重
            if nextVert in pq and newCost < nextVert.getDistance():  # 若邻居尚未入树且当前单边权重更小
                nextVert.setPred(currentVert)             # 调用 Vertex 实例方法 setPred() 更新前驱顶点为 currentVert
                nextVert.setDistance(newCost)             # 调用 Vertex 实例方法 setDistance() 更新最小入树代价
                pq.decreaseKey(nextVert, newCost)         # 调用 PriorityQueue 实例方法 decreaseKey() 上浮调整堆中优先级
```
# 与 Dijkstra 算法的区别和联系
对比 `prim()` **函数** 与 [[712.最短路径问题与dijkstra算法|dijkstra() 函数]] 之间的区别和联系。
两者在优先队列框架以及时间复杂度 $O\big((|V|+|E|)\log|V|\big)$（连通图常简写为 $O(|E|\log|V|)$）上完全一致，核心差异集中在循环体内的两行判断逻辑：

| 对比维度                       | Prim 算法（最小生成树）                                | Dijkstra 算法（单源最短路径）                                                      |
| :------------------------- | :-------------------------------------------- | :----------------------------------------------------------------------- |
| **优化目标**                   | 使整棵生成树的**总边权之和最小**                            | 使起点到每个顶点的**累计路径长度最短**                                                    |
| **新代价计算**                  | `currentVert.getWeight(nextVert)`（仅看**单条边权**） | `currentVert.getDistance() + currentVert.getWeight(nextVert)`（**累计路径和**） |
| **防成环判断 `nextVert in pq`** | **必须保留**：防止已入树顶点被更小邻边反向修改 `pred` **实例属性** 而成环 | **通常可省略**：非负权图中路径长度单调递增，已出队顶点不会被更长路径刷新                                   |


> [!tips]
> 两段代码结构几乎完全对称：
> Dijkstra 算的是“到起点的累计总路程”。
> Prim 算的是“连入当前树的单步最近距离”。
> 正因为 Prim 只比较单条边权，所以必须加上 `nextVert in pq` 守住“只连向树外节点”的安全边底线。
