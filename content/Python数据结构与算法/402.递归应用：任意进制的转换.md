# 整数转换为任意进制
## 递归与栈的内在关联
整数转换为任意进制是经典算法，递归与栈之间存在必然的底层关联。
在使用栈结构实现进制转换时，需要显式地执行“入栈”与“出栈”操作来反转余数的输出顺序。

改用递归算法实现时，Python 解释器底层的**函数调用栈**会自动保存每一层递归的局部变量与返回点，从而省去手动管理栈的步骤，优雅地解决从二进制到十六进制的**任意进制转换**。
## 从十进制分析查表与拆解思路
十进制共有十个不同符号，可定义为字符串变量 `convString = "0123456789"`。

**比十小的整数**：转换成十进制时无需继续拆分，直接对 `convString` 字符串变量按索引查表 `convString[n]` 即可得到对应的字符。
**比十大的整数**：想办法将其拆成一系列比十小的整数，再逐个查表转换。

例如整数七百六十九（`769`），将其拆解为七（`7`）、六（`6`）、九（`9`）三个小于十的整数，逐个查表即可拼接得到字符串 `"769"`。

# 基于递归三定律的问题分解
## 寻找基本结束条件与演进方向
对照 [[401.什么是递归|递归三定律]]，在十进制转换问题中，“**基本结束条件**”就是 **小于十的整数**（推广到任意进制即为小于进制基 `base` 的整数）。
将大整数一步步拆解为更小整数的过程，就是向“基本结束条件”演进（减小问题规模）的过程。
## 整数除与求余数拆解操作
我们通过 **整数除** 和 **求余数** 两个算术运算将整数变量 `n` 一步步拆开：

**除以“进制基 `base`”（`n // base`）**：得到的 **整数商** 成为“更小规模”的同质子问题，通过递归调用 `toStr()` 函数自身来解决。
**对“进制基 `base`”求余数（`n % base`）**：得到的 **余数** 总是小于进制基 `base`，天然满足“基本结束条件”，可直接对字符表变量按索引查表转换。

# 任意进制转换：代码实现
## 递归算法代码
```python
# 定义任意进制转换的递归函数 toStr()，接收待转换整数变量 n 和进制基变量 base
def toStr(n, base):
    # 定义局部字符串常量/变量 convertString，存储二至十六进制对应的 16 个字符表
    convertString = "0123456789ABCDEF"
    # 基本结束条件（最小规模）：当整数变量 n 小于进制基变量 base 时
    if n < base:
        # 直接通过索引访问 convertString 字符串变量查表并返回对应字符
        return convertString[n]
    else:
        # 减小规模，递归调用 toStr() 函数自身处理整数商 n // base
        # 并与当前余数 n % base 在 convertString 字符串变量中查表所得的字符进行拼接
        return toStr(n // base, base) + convertString[n % base]

# 调用内置函数 print() 输出 toStr() 函数的返回值（将十进制 1453 转换为十六进制）
print(toStr(1453, 16))
```

## 运行结果与执行过程说明
调用 `toStr(1453, 16)` 函数将十进制整数 `1453` 转换为十六进制字符串：
第一层：`1453 // 16 = 90`，余数 `1453 % 16 = 13`，查 `convertString[13]` 得 `'D'`，等待 `toStr(90, 16)` 函数返回。
第二层：`90 // 16 = 5`，余数 `90 % 16 = 10`，查 `convertString[10]` 得 `'A'`，等待 `toStr(5, 16)` 函数返回。
第三层：`5 < 16` 满足最小规模基本结束条件，查 `convertString[5]` 直接返回 `'5'`。
逐层回溯拼接：`toStr(1453, 16)` 函数最终返回字符串 `"5AD"`，由 `print()` 函数打印输出 `5AD`。

>[!tips] 递归三定律在 `toStr()` 函数中的对应关系
>1. **基本结束条件**：`if n < base:` 分支处理最小规模问题，直接通过 `convertString[n]` 变量索引查表返回。
>2. **向基本结束条件演进**：通过整除运算 `n // base` 将参数变量 `n` 不断缩小，确保有限步内必然达到 `n < base`。
>3. **调用自身**：在 `else` 分支中调用 `toStr(n // base, base)` 函数自身解决规模更小的子问题。
