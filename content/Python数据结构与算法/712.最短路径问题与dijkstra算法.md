# 最短路径问题：介绍
本节承接 [[702~703.图抽象数据类型及其python实现|Graph 类与 Vertex 类]] 以及 [[704~705.词梯问题和广度优先搜索|广度优先搜索（BFS）]]，将无权图上的“最少边数”搜索拓展至**带权图上的最短路径**问题。
## 互联网的带权图建模
当我们浏览网页、发送电子邮件或传输 QQ 消息时，数据会在联网设备之间流动。
![[file-20261123181258380.png|329]]
Internet的工作方式中就包含着图算法。

PC 浏览器向服务器请求网页时，请求先经本地局域网到达路由器 A，再沿着 Internet 中的众多路由器接力传播，最后到达服务器本地局域网所属的路由器 B 并传给服务器。
![[file-20261123181450016.png|273]]
标注为“Internet”的云状结构，实际上是由大量路由器连接而成的网络，这些路由器各自独立而又协同工作，负责将信息从一端传送到另一端。

在命令行中可以通过 `traceroute` `网页`跟踪信息传送经过的路由器路径 
如`tracerout ewww.lib.pku.edu.cn`，可以看到北大的一台本机到北大图书馆服务器之间的一条服务器路径：
![[file-20261123181549045.png]]
由于网络流量的状况会动态影响路径选择算法，在不同时间执行同一追踪，经过的路由器路径可能完全不同。

将互联网路由器体系抽象为**带权图**时，路由器作为图中的顶点，路由器之间的网络连接作为边，而连接速度、网络负载程度、分时段优先级等影响因素则被合成为单一的边权重。
![[file-20261123181843914.png|339]]
解决信息在路由器网络中选择传播速度最快路径的问题，就转变为在带权图上寻找最短路径的问题。
这个问题与 [[704~705.词梯问题和广度优先搜索|BFS 算法解决的词梯问题]] 相似，只是在边上增加了权重；如果所有边的权重相等，问题就会还原回无权图的词梯问题。
# Dijkstra 算法原理与执行流程
## 算法定位与核心机制
解决带权图单源最短路径问题的经典算法是以发明者命名的 **Dijkstra 算法**（`/'dɛɪkstra/`），它是一种基于 [[408.优化问题：贪心策略|贪心策略]] 的迭代算法，用于求出从单个起始顶点到其余所有顶点的最短路径，整体思路接近于广度优先搜索（BFS）。

在具体实现上，算法复用BFS[[704~705.词梯问题和广度优先搜索#BFS 与路径回溯的 Python 实现|Vertex 类]]中的 `distance`**实例属性**来记录从起始顶点到当前顶点的最短带权路径长度（**权重之和**），并对图中的每个顶点迭代一次。

与 BFS 使用普通队列不同，Dijkstra 算法中顶点的访问次序由一个 [[608.优先队列和二叉堆|优先队列（PriorityQueue）]] 来控制，队列中作为优先级依据的正是顶点的 `distance` **实例属性**。
## 算法执行步骤
初始化阶段，只有起始顶点的 `distance` **实例属性** 被设为 `0`，而其他所有顶点的 `distance` 均设为 `sys.maxsize` **属性**（Python 中的最大整数，代表无穷大 $\infty$），随后将全部顶点加入优先队列并建堆。

在迭代过程中，优先队列中每个`distance` 最小的顶点会率先出队。
顶点出队后，该顶点的最短路径和pred此时即被最终确定。算法会遍历它的所有邻接顶点，计算经由当前顶点到达邻接顶点的新路径权重之和；
如果新路径权重小于邻接顶点原有的 `distance`，就会减小并修改该邻接顶点的 `distance` 与前驱 `pred` **实例属性**，同时触发优先队列的堆重排。

随着堆重排完成，优先队列依据更新后的 `distance` 优先级继续依次出队并执行松弛操作（即用经由当前顶点绕道的新路径，尝试把邻接顶点原本更高的距离记录改小并更新前驱），直到队列为空。
## 完整执行过程推演
从起点 $u$ 出发，每一步的出队、松弛与优先队列 `PQ` 变化如下：

**第 1 步（起点 `u` 出队）**：起点 `u`（`d=0`）从优先队列出队并确定最短路径；随后松弛其邻接顶点，将 `x` 更新为 `d=1`（前驱 `u`）、`v` 更新为 `d=2`（前驱 `u`）、`w` 更新为 `d=5`（前驱 `u`），此时优先队列状态为 `PQ = x, v, w`。
![[file-20261123195356850.jpeg|309]]

**第 2 步（`x` 出队）**：当前堆顶最小顶点 `x`（`d=1`）出队并确定最短路径；检查其邻接顶点，发现经 `x` 到达 `w` 的距离为 `1 + 3 = 4 < 5`，于是将 `w` 更新为 `d=4`（前驱改为 `x`），并首次将 `y` 更新为 `d=2`（前驱 `x`），`v` 的距离 `1 + 2 = 3 > 2` 保持不变，此时优先队列重排为 `PQ = v, y, w`。
![[file-20261123195544188.png|326]]

**第 3 步（`v` 出队）**：当前堆顶顶点 `v`（`d=2`）出队并确定最短路径；检查其邻接顶点 `w`，经 `v` 到达 `w` 的距离为 `2 + 3 = 5 > 4`，不更新，此时优先队列为 `PQ = y, w`。
![[file-20261123200219715.png|306]]

**第 4 步（`y` 出队）**：当前堆顶顶点 `y`（`d=2`）出队并确定最短路径；检查其邻接顶点，发现经 `y` 到达 `w` 的距离为 `2 + 1 = 3 < 4`，于是将 `w` 更新为 `d=3`（前驱改为 `y`），同时将 `z` 更新为 `d=3`（前驱 `y`），此时优先队列重排为 `PQ = w, z`。
![[file-20261123200033708.jpeg|303]]

**第 5 步（`w` 出队）**：当前堆顶顶点 `w`（`d=3`）出队并确定最短路径；检查其邻接顶点 `z`，经 `w` 到达 `z` 的距离为 `3 + 5 = 8 > 3`，不更新，此时优先队列仅剩 `PQ = z`。
![[file-20261123201857600.jpeg|287]]

**第 6 步（`z` 出队）**：最后一个顶点 `z`（`d=3`）出队并确定最短路径；所有顶点的最短路径及前驱全部确定完毕，优先队列为空（`PQ = None`）。
![[file-20261123202036348.jpeg|286]]
> [!notes] 最短路径树与前驱回溯
> 每次执行 `setPred()` **实例方法** 更新前驱指针后，所有顶点的前驱指针共同构成一棵以起点 $u$ 为根的**最短路径树**。
> 这与 [[413.递归小结#最优子结构（Optimal Substructure）|最短路径问题的最优子结构]] 一致，从任意顶点沿前驱逆推回 $u$ 即可还原完整路径。
# Python 实现与逐行解析
基于 `pythonds.graphs` 模块中的 `PriorityQueue` **类** 与 `Vertex` **类**，定义独立的 `dijkstra()` **函数** 实现单源最短路径搜索：
```python
from pythonds.graphs import PriorityQueue, Graph, Vertex  # 导入图与优先队列相关类

# 定义独立函数 dijkstra()，形参 aGraph 为 Graph 实例，start 为起始 Vertex 实例
def dijkstra(aGraph, start):
    # 1. 初始化与建堆：对所有顶点建堆，形成优先队列
    pq = PriorityQueue()                                 # 调用 PriorityQueue() 类构造器创建最小堆实例
    start.setDistance(0)                                 # 调用 Vertex 实例方法 setDistance()，将起点距离设为 0
    pq.buildHeap([(v.getDistance(), v) for v in aGraph]) # 调用 PriorityQueue 实例方法 buildHeap()，将所有 (距离, 顶点) 元组建堆

    # 2. 主循环出队：优先队列出队
    while not pq.isEmpty():                              # 调用 PriorityQueue 实例方法 isEmpty() 判断队列是否非空
        currentVert = pq.delMin()                        # 调用 PriorityQueue 实例方法 delMin() 弹出当前 distance 最小的顶点
        # 3. 松弛与重排：修改出队顶点所邻接顶点的 dist，并逐个重排队列
        for nextVert in currentVert.getConnections():    # 调用 Vertex 实例方法 getConnections() 遍历所有邻接顶点
            newDist = currentVert.getDistance() \
                    + currentVert.getWeight(nextVert)    # 调用 getDistance() 与 getWeight() 实例方法计算经 currentVert 到达的新距离
            if newDist < nextVert.getDistance():         # 若新路径更短，执行松弛操作
                nextVert.setDistance(newDist)            # 调用 Vertex 实例方法 setDistance() 更新邻接顶点的最短距离
                nextVert.setPred(currentVert)            # 调用 Vertex 实例方法 setPred() 更新前驱顶点为 currentVert
                pq.decreaseKey(nextVert, newDist)        # 调用 PriorityQueue 实例方法 decreaseKey() 上浮调整堆中优先级
```

`pq.buildHeap()` **实例方法** 接收列表推导式生成的 `(v.getDistance(), v)` 元组列表，利用 [[609.二叉堆的实现|二叉堆]] 的下沉建堆机制在 $O(|V|)$ 时间内完成初始化。

`pq.delMin()` **实例方法** 每次从堆顶取出 `distance` 最小的 `Vertex` **实例** `currentVert`，确保贪心选择当前全局最近节点。

`pq.decreaseKey()` **实例方法**  干的事就三步：在堆里找到 nextVert → 把它绑定的旧距离换成 newDist → 调用 percUp 把它往上浮。从而维持最小堆性质，保证后续 `delMin()` 依然能准确取出最小顶点。
# 算法的局限性与复杂度分析
## 正权重限制与互联网路由现实
> [!attention] Dijkstra 算法只能处理大于 0 的权重
> 如果图中出现**负数权重**，Dijkstra 算法会陷入无限循环（或导致已出队顶点的距离无法被后续更短的负权路径修正）。
> 若图中存在负权边，需改用 Bellman-Ford 等其他算法。

虽然 Dijkstra 算法完美解决了带权图的最短路径问题，但实际 Internet 的路由器中采用的是其他路由算法。

其中最重要的原因是 Dijkstra 算法需要具备**整个图的完整数据**。
对于 Internet 中的单个路由器而言，显然无法将全球所有路由器及其连接信息保存在本地；这不仅是数据量的问题，Internet 动态变化的特性也使得保存全图缺乏现实性。
实际的路由器选径算法通常采用分布式机制，例如**距离向量路由算法**（Distance-Vector Routing）。
## 时间复杂度分析
设图中有 $|V|$ 个顶点、$|E|$ 条边，优先队列底层采用二叉堆实现，总时间复杂度由三部分构成：
建堆阶段调用 `buildHeap()` **实例方法** 将所有顶点加入优先队列并建堆，时间复杂度为 $O(|V|)$。
主循环阶段每个顶点仅出队 $1$ 次，每次调用 `delMin()` **实例方法** 调整堆结构花费 $O(\log|V|)$，因此出队操作总计花费 $O(|V|\log|V|)$。
松弛阶段每条边关联到的顶点最多触发一次 `decreaseKey()` **实例方法**（每次上浮调整花费 $O(\log|V|)$），因此更新优先级操作总计花费 $O(|E|\log|V|)$。
将上述三部分相加，Dijkstra 算法的总时间复杂度数量级为：

$$O\big((|V| + |E|)\log|V|\big)$$

> [!tips] 复杂度简写与稠密图对比
> 当图为连通图时，边数满足 $|E| \ge |V| - 1$，因此上述复杂度在算法题与教材中常简写为 $O(|E|\log|V|)$。若不使用优先队列而直接遍历数组寻找最小 `distance`，时间复杂度为 $O(|V|^2)$，在 $|E| \approx |V|^2$ 的稠密图中反而优于二叉堆版本。
