# 各种排序的要点
## 初级比较排序与增量改进
**冒泡排序**：最稳定的入门排序算法，时间复杂度为 $O(n^2)$，原地排序不需要额外空间（空间复杂度为 $O(1)$）。
**选择排序**：比对次数同冒泡排序（时间复杂度为 $O(n^2)$），但在每一趟扫描中仅记录最大值的位置索引，每趟只做 1 次元素交换，不需要额外空间。

**插入排序**：平均时间复杂度为 $O(n^2)$，最好情况时间复杂度为 $O(n)$，不需要额外空间。
插入排序从第 1 项开始，逐步扩大已排序子列表，寻找“新项”的插入位置。
在已排序子列表中，从后往前依次比对，移动所有比“新项”大的数据项，从而腾出插入空位。
**谢尔排序（希尔排序）**：时间复杂度介于 $O(n)$ 与 $O(n^2)$ 之间，不需要额外空间。
谢尔排序在间隔划分子列表中采用带步长的插入排序（调用 `gapInsertionSort()` 函数）。
步长增量 `gap` 从 $n/2$ 开始倍增减小直到 1，子列表个数随之缩减直到合并为 1 个整体列表，最终完成排序。
## 分治策略的高效排序
**归并排序**：稳定的高级排序算法，时间复杂度恒定为 $O(n \log n)$，需要 1 倍的额外辅助空间（空间复杂度为 $O(n)$）[[407.分治策略|分治策略]]。
归并排序以列表的“中间位置”作为分裂子列表的依据，执行流程遵循“递归分解 $\to$ 归并汇总”的策略。
**快速排序**：最好与平均时间复杂度均为 $O(n \log n)$，最差情况退化为 $O(n^2)$，原地分区操作不需要额外列表存储空间（递归调用栈空间除外）。
快速排序以选定的“中间值（中值/基准值）”作为分裂子列表的依据，执行流程遵循“分裂分区 $\to$ 递归子表”的策略。

在快速排序中，输入数据的初始分布情况以及取中间值的方法（如三数取中法）对防止算法退化至 $O(n^2)$ 特别重要。

# 排序过程中的比较信息
## 一阶信息与平方级瓶颈
一阶信息是指数据项 $a_i$ 与 $a_j$ 之间的直接大小比较结果，例如 $a_i < a_j$。
冒泡排序、选择排序、插入排序、谢尔排序均仅利用了一阶比较信息。
这类算法在每一轮扫描中都会将未排序的部分完整遍历一遍，未排序部分每轮仅能缩小 1 个数。
由于每次比较只能消除局部的逆序关系，算法的时间复杂度被限制在 $O(n^2)$ 级别 
## 二阶的隐含信息与对数级跃迁
二阶隐含信息是指综合利用 $a_i, a_j$ 以及 $a_j, a_k$ 之间大小关系的传递性信息。
如果已知 $a_i > a_j$，同时又有 $a_j > a_k$，根据大小传递性必然有 $a_i > a_k$，此时 $a_i$ 和 $a_k$ 之间根本不需要再次进行直接比较。
**快速排序对二阶信息的利用**：选定的“中值”就是中间媒介 $a_j$，分裂操作会将大于中值的 $a_i$ 和小于中值的 $a_k$ 直接划分到左右两个不同的子表中，在后续递归过程中 $a_i$ 与 $a_k$ 永远不会再次比较。
**归并排序对二阶信息的利用**：在两路有序子表的合并过程中，假设 $a_i$ 属于其中一个子表，而 $a_j$ 与 $a_k$ 属于另一个已排好序的子表，利用子表内部的有序传递性，同样不会让 $a_i$ 和 $a_k$ 发生冗余的重复比较。
通过利用二阶隐含信息，未排序部分的规模在每一轮都能够缩小一半，从而使时间复杂度跃升至 $O(n \log n)$ 级别。
# 具有先验信息的排序算法
## 基数排序的原理与性能
基数排序（Radix Sort）属于典型的具有先验信息的非比较排序算法。
通过把待排序整数表示为某个进制的符号序列（例如十进制数），算法预先知道了进制中各个数字符号之间的天然大小关系（如 $0 < 1 < \dots < 9$）。
用于存放对应位数字的各个基数队列之间具有固定的先后次序 [[308~309.队列抽象数据类型与热土豆问题|队列抽象数据类型]]。
在排序过程中，甚至不需要对数据项去直接进行两两比较，只需要按照整数的每一位符号（从低位到高位或从高位到低位）依次分配排到相应的基数队列里，再按序收集出队即可。
因此基数排序具有更好的排序性能，其时间复杂度是 $O(n \log_B N)$ 级别，其中 $B$ 是所选用的基数（如十进制下 $B = 10$），$N$ 是这组数中最大的数，而 $\log_B N$ 代表最大数的总位数。
# 什么是稳定的排序
## 排序稳定性的定义与价值
**稳定排序的定义**：能够保证排序前 2 个相等数据项的前后相对位置，与排序完成后的前后位置顺序完全相同。
**稳定性的核心好处**：支持多关键字（多个键值）的级联排序（例如先按次要键值排好序，再按主要键值进行稳定排序时，同主键值下的次要键值依然保持有序），同时在特定场景下可以减少不必要的元素交换次数。
## 各类排序算法的稳定性判别
**冒泡排序是稳定的**：因为元素交换只发生在相邻的两个数据项之间，遇到相等元素时不发生跨越交换。
**选择排序是不稳定的**：每次寻找极值后需要与未排序区首尾元素直接对调，相等元素可能会跨越多个数据项发生交换，从而打乱原有的先后相对顺序。
**插入排序是稳定的**：在已排序子表中从后向前寻找插入位置时，遇到小于或等于“新项”的元素即停止后移，不会改变相等元素的相对次序。
**谢尔排序是不稳定的**：虽然以插入排序为基础，但由于存在跨步长的多个子表穿插排序，相等的数据项可能被划分在不同子表中独立移动，破坏了原有的相对次序。
**基数排序是稳定的**：利用队列先进先出（FIFO）的特性，相同位数值的数据项始终严格按照原有的先后顺序进入队列并依次出队列。
**归并排序是稳定的**：在左右子表合并的过程中，当左右两端元素相等时，优先取用左半部子表的数据项放入结果表，左半部始终保持在前面，绝不破坏相同数据项的相对位置。
**快速排序是不稳定的**：在右标（`rightmark`）左移与左标（`leftmark`）右移的分治交换过程中，会把列表尾部的数长距离跳跃交换到前面，从而破坏相等元素的相对位置。
# 另一些奇奇怪怪的排序
## 睡眠排序（Sleep Sort）
睡眠排序的核心思路是把列表中的每个数对应分配给一个独立的操作系统线程，并同时启动这些线程。
每个线程内部都调用 `sleep()` 函数休眠对应数值长度的时间，休眠结束后立即输出这个数，利用时间流逝的先后完成排序。
```python
import _thread
from time import sleep

# 定义待排序的整数列表变量 items
items = [6, 2, 5, 3, 1, 7]

# 定义睡眠排序的线程任务函数 sleep_sort()
def sleep_sort(i):
    # 调用 time 模块的 sleep() 函数休眠 i 秒
    sleep(i)
    # 调用内置 print() 函数打印当前数值 i
    print(i)

# 使用列表推导式遍历 items，调用 _thread 模块的 start_new_thread() 函数为每个元素启动新线程
[_thread.start_new_thread(sleep_sort, (i,)) for i in items]

```

> [!attention] 算法局限性说明
> 睡眠排序严格意义上不能算作标准的计算机算法。它极度依赖操作系统的线程调度精度，当数值差距极小或存在负数时会失效，且元素过多时会耗尽系统线程资源 。

## 猴子排序（Bogo Sort）
猴子排序基于随机碰撞思想，每次直接调用洗牌函数将列表随机打乱，然后检验列表是否恰好按升序排好；若未排好则继续随机重排，直到碰巧有序为止。
```python
from random import shuffle

# 定义检验列表是否按升序排列的辅助函数 inorder()
def inorder(lst):
    # 调用内置 len() 函数获取列表长度，调用 range() 类（构造器）生成索引序列
    for i in range(len(lst) - 1):
        # 比较相邻两项，若前项大于后项则说明未排好序
        if lst[i] > lst[i + 1]:
            return False
    return True

# 定义猴子排序主函数 bogo()
def bogo(x):
    # 循环调用 inorder() 函数检验列表 x 是否已经有序
    while not inorder(x):
        # 调用 random 模块的 shuffle() 函数就地随机打乱列表 x 的元素顺序
        shuffle(x)
    return x

# 调用 bogo() 函数对目标列表进行排序，并将返回结果赋值给变量 l
l = bogo([1, 3, 2, 4, 5])
# 调用内置 print() 函数输出排序后的列表 l
print(l)
```
# 排序进阶问题与复杂度大全
## 寻找两个正序数组的中位数
针对“寻找两个正序数组的中位数”（[LeetCode 04 题解](https://www.google.com/search?q=https://leetcode-cn.com/problems/median-of-two-sorted-arrays/solution/xun-zhao-liang-ge-you-xu-shu-zu-de-zhong-wei-shu-by-leetcode-solution/)），最优算法的时间复杂度可以达到 $O(\log(\min(m, n)))$。
**基本分治与二分原理**：在两个正序数组中同时寻找一条分割界限，使得该界限满足两个核心条件：
第一，分割线左右两边包含的数据项总长度相同（若总元素个数为奇数，则左边比右边多 1 个）。
第二，分割线左边的所有数据项全部小于或等于右边的所有数据项（即左半部分的最大值小于等于右半部分的最小值）。
**二分调整过程**：只需在长度较短的那个数组上使用二分查找移动分割线。如果当前分割线左侧元素偏小，则将该数组的二分分割线向右移，同时另一个数组的分割线向左移动同样多的步数（以保持左右两侧总个数不变），直到找到满足界限条件的分割位置。
## 排好序的列表达到 $O(n)$ 复杂度的条件
当输入数据已经是排好序（或极其接近排好序）的列表时，**冒泡排序、插入排序、优化后的归并排序** 均能够达到 $O(n)$ 的最优时间复杂度。
三者的优化原理相同，都是可以在算法执行过程中通过 **简单测试** 来提前跳过无效比对或直接结束循环：
**冒泡排序的优化**：设置交换标志位，如果在某一趟扫描中一次交换次序都没有发生，说明列表已经完全有序，这一趟结束后立即终止整个算法，达到 $O(n)$。
**插入排序的最优情况**：在已排序子表中从右到左与“新项”比对，如果列表已经接近排好序，每次“新项”只需与左邻项比对 1 次且一直没有元素移动发生，单趟立刻结束，整体达到 $O(n)$。
**归并排序的边界测试优化**：如果固定执行标准合并代码而不增加额外判断，归并排序在所有情况下的时间复杂度都是恒定的 $O(n \log n)$。
如果在合并前增加判断左子表末尾最大值 `left[-1]` 和右子表开头最小值 `right[0]` 的优化代码：当发现左边列表最大值小于或等于右边列表最小值（`left[-1] <= right[0]`）时，说明左右两半天然有序，直接拼接合并而无需逐项比较，在接近排好序时同样能达到 $O(n)$。
## 快速排序左右标地位不对称的原因
在快速排序的分裂过程中，左标（`leftmark`）与右标（`rightmark`）的设计并不对称，因为分裂数据表的根本目标是 **找到“中值（基准值）”最终应当所处的位置**。
假设选择列表第 1 项作为“中值”：
设置左右标（`leftmark` 与 `rightmark`），左标向右移动（碰到比中值大的数据项就停止），右标向左移动（碰到比中值小的数据项就停止），然后把左右标所指的数据项进行交换。
继续相向移动，直到左标移到右标的右侧（即 `leftmark > rightmark` 两标交错）时停止移动。
由于中值原本存放在列表最左端，当两标交错停止时，**右标（`rightmark`）所指的位置必然属于小于或等于中值的区域末尾**，这正是“中值”应处的分裂点位置。
最后将最左端的中值和 `rightmark` 位置的数据项交换，即可保证分裂完成后左半部全部比中值小、右半部全部比中值大。

> [!notes] 复杂度表格补充说明
