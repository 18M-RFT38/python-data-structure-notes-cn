# 概念与核心目标
## 从特定应用到“通用”搜索
此前的 [[704~705.词梯问题和广度优先搜索|广度优先搜索（BFS）]] 适合在无权图中寻找起点到终点的最短路径。
而某些特定场景的深度优先搜索（如骑士周游问题）只聚焦于寻找一条满足条件的路径。

**通用的深度优先搜索（Depth First Search, DFS）** 并不针对单一目标终点。
其核心目标是在整张图上进行尽量深的探索，尽可能连接更多顶点，并在必要时进行分支以构建出完整的树结构。

当图中存在多个互不连通的分支，或从单个起点无法触达所有顶点时，通用的深度优先搜索会依次从尚未访问的顶点重新出发，最终创建出多棵树，称为 **深度优先森林（Depth First Forest）** 。
## 新增的顶点与图属性
通用的深度优先搜索同样需要借助 [[702~703.图抽象数据类型及其python实现|Vertex 类]] 的前驱 **实例属性** `pred` 来记录父子关系，从而构建搜索树或森林。[[704~705.词梯问题和广度优先搜索#^313e02|pred指针]]

为了支撑后续的拓扑排序、强连通分支等高级图算法，DFS 额外引入了两个关键的顶点 **实例属性** 以及一个 **全局步数计数器** 。
**发现时间（Discovery）实例属性** ：记录算法是在第几步首次访问到该顶点的（此时顶点颜色被设为灰色）。
**结束时间（Finish）实例属性** ：记录算法是在第几步完成该顶点及其所有后代探索的（此时顶点颜色被设为黑色）。
**全局步数计数器 `time` 实例属性** ：在图子类中新增 `time` **实例属性** ，每当有顶点被发现（变灰）或探索结束（变黑）时递增 `1` ，作为统一的时间戳标尺。

>[!notes] 为什么 BFS 用队列，而 DFS 用递归？
>BFS 需要按距离由近及远逐层扩展，因此显式使用 [[308~309.队列抽象数据类型与热土豆问题|队列]] 来缓存待访问的顶点。
>DFS 则要求沿当前分支一路向下扎到底再回溯，因此直接通过方法间的递归调用，隐式利用了系统的 [[403.递归调用的实现|递归调用栈]] 来保存回溯现场。
# 面向对象设计与 Python 实现
## 类继承与属性扩展
承接 [[702~703.图抽象数据类型及其python实现|Graph 类与 Vertex 类]] 的邻接表实现，带有通用 DFS 算法的图被实现为 `Graph` 的子类 `DFSGraph`（见 [[24.类的继承|类的继承]]）。

对应地，`Vertex` **类** 只需补充 `discovery` 与 `finish` 两个 **实例属性** ，并配上相应的 **setter 和 getter 实例方法** 用于读写时间戳即可
```python 
class Vertex: def __init__(self, key): 
//**保留原有的 id、connectedTo、distance、pred、color 实例属性**// 

self.discovery = 0 # 新增实例属性：记录顶点被发现的步数 
self.finish = 0 # 新增实例属性：记录顶点完成探索的步数 

# 定义实例方法 setDiscovery()，写入发现时间 
def setDiscovery(self, dtime): 
self.discovery = dtime 

# 定义实例方法 getDiscovery()，读取发现时间 
def getDiscovery(self): 
return self.discovery 

# 定义实例方法 setFinish()，写入结束时间 
def setFinish(self, ftime): 
self.finish = ftime 

# 定义实例方法 getFinish()，读取结束时间 
def getFinish(self): 
return self.finish 
```
## DFSGraph 子类完整代码
```python
from pythonds.graphs import Graph

# 定义 DFSGraph 类，继承自父类 Graph
class DFSGraph(Graph):
    # 定义构造方法 __init__()，初始化图并新增步数计数器
    def __init__(self):
        # 调用内置函数 super() 与父类构造方法 __init__()，继承 vertList 和 numVertices 实例属性
        super().__init__()
        self.time = 0  # 新增实例属性：记录算法执行的全局步骤数目
    
    # 定义实例方法 dfs()，对整张图执行通用的深度优先搜索（负责初始化与建森林）
    def dfs(self):
        # 第一次遍历：触发 Graph.__iter__() 特殊方法，对图中所有 Vertex 实例初始化状态
        for aVertex in self:
            aVertex.setColor('white')  # 调用 Vertex 实例方法 setColor()，设为白色（未发现）
            aVertex.setPred(-1)        # 调用 Vertex 实例方法 setPred()，前驱初始化为 -1（或者None）
        # 第二次遍历：确保即使图不连通，也能覆盖所有顶点以构建深度优先森林
        for aVertex in self:
            # 调用 Vertex 实例方法 getColor()，若仍为白色则以它为新树根启动探索
            if aVertex.getColor() == 'white':
                # 调用自身的实例方法 dfsvisit()，递归构建一棵深度优先搜索树
                self.dfsvisit(aVertex)

    # 定义实例方法 dfsvisit()，形参 startVertex 为当前正在探索的 Vertex 实例
    def dfsvisit(self, startVertex):
        # 1. 标记发现：将当前顶点设为灰色，全局步数加 1 ，并记录发现时间
        startVertex.setColor('gray')
        self.time += 1
        startVertex.setDiscovery(self.time)
        # 2. 深度优先递归：调用 getConnections() 实例方法遍历所有邻接顶点
        for nextVertex in startVertex.getConnections():
            # 仅当邻接顶点为白色（尚未发现）时，才沿该边深入探索
            if nextVertex.getColor() == 'white':
                # 调用 setPred() 实例方法，记录startVertex顶点为邻接顶点的前驱
                nextVertex.setPred(startVertex)
                # 递归调用 dfsvisit() 实例方法，将控制权交给更深一层的邻接顶点
                self.dfsvisit(nextVertex)
        # 3. 标记结束：当前顶点的所有邻接顶点均探索完毕，设为黑色并记录结束时间
        startVertex.setColor('black')
        self.time += 1
        startVertex.setFinish(self.time)
```
## 控制流与调用栈拆解
**外层总控 `dfs()` 实例方法** ：
先通过第一个 `for` 循环把全图顶点统一刷白并重置前驱。
再通过第二个 `for` 循环逐一检查顶点，只要遇到还是白色的顶点（说明前面启动的搜索没有覆盖到它），就以它为起点调用 `self.dfsvisit(aVertex)` 深入遍历；若检查到已经变黑的顶点则直接跳过。
如果多个互不连通的分支或不可达的顶点各自拉起了新的搜索树，最终就会构成深度优先森林。

**内层递归 `dfsvisit()` 实例方法** ：
每次进入时，先将当前顶点 `startVertex` 标灰并记录 `Discovery` 时间戳。（把 `startVertex` 压入调用栈）
随后遍历其邻接顶点，每遇到一个白色邻居 `nextVertex`，就先调用 `setPred()` 将当前顶点`startVertex`记为它的前驱，再以该邻居为”起点“递归调用 `dfsvisit()` 深入探索。（遇到有分支时，分叉处父节点的 `for` 循环会停在递归调用这一行。必须进入先发现顶点的那条分支的递归全部走完，并出栈回到分叉处父节点，循环才会接着去检查并进入该父节点其余邻居分支）
当 `startVertex` 的所有邻接顶点都检查完毕并从递归返回后，将它标黑并记录 `Finish` 时间戳。（`startVertex` 弹出调用栈，返回上一层）

>[!attention] Python 2/3 课程代码细节提示
>课件代码中 `aVertex.setPred(-1)` 将初始前驱设为 `-1`（而此前 BFS 笔记中设为 `None`），两者均用于标识“无前驱的树根”，实际回溯判断时保持与初始化值一致即可。

# 算法分析
## 括号性质（Parenthesis Property）
由 DFS 构建出的树，其所有顶点的“发现时间”和“结束时间”属性具有类似 **括号** 嵌套的性质：任意一个父顶点的“发现时间”总严格小于其所有子顶点的“发现时间”，而它的“结束时间”则总严格大于其所有子顶点的“结束时间”。

换言之，父顶点总是比子顶点 **更早被发现** ，也总是比子顶点 **更晚被结束探索** 。
![[file-20261122214629544.png|354]]
以上述示例图为例，
`A` 的时间区间 `[1, 12]` 完整包裹 `B` 的 `[2, 11]`，`B` 又包裹 `C` 的 `[3, 4]` 与 `D` 的 `[5, 10]`，而 `D` 又依次包裹 `E` 的 `[6, 9]` ，`E` `F`也是同样，形成严格嵌套的括号结构。
## 时间复杂度分析
通用的深度优先搜索运行时间同样由顶点遍历与边检查两部分构成。

在 `dfs()` **实例方法** 中有两个各自遍历全图顶点的 `for` 循环，每个循环都会执行 $|V|$ 次，因此这部分时间开销为 $O(|V|)$。

在 `dfsvisit()` **实例方法** 中的 `for` 循环则是针对当前顶点所连接的所有邻接顶点进行检查；由于只有在目标顶点为白色的情况下才会触发递归调用，每个顶点最多只会作为 `startVertex` 进入一次 `dfsvisit()`，因此图中的每条边在全过程中最多只会被检查一步，这部分时间开销为 $O(|E|)$。

将两部分相加，通用的深度优先搜索算法总体时间复杂度与广度优先搜索一样，均为 $O(|V| + |E|)$。
