# 基本概念与原理
## 线性关系与存储下标
如果数据项保存在类似列表（List）这样的集合中，这些数据项在逻辑上具有线性或顺序关系。
在Python列表（`list`）中，数据项的存储位置由 **下标（index）** 唯一定位，这些下标为连续且有序的整数（从 `0` 开始递增）。
通过下标按顺序逐个访问和比对数据项的技术，称为 **顺序查找（Sequential Search）**。
## 查找基本流程
顺序查找从列表的第1个数据项（下标为 `0`）开始。
按照下标递增顺序，逐个比对当前数据项与目标数据项。
若在遍历过程中匹配到目标数据项，则查找成功并返回。
若遍历到最后一个数据项仍未找到目标项，则查找失败。

# 无序表顺序查找实现
## 算法逻辑与代码实现
在无序列表中，数据项没有特定的排列规则，必须依次向后扫描直到找到目标或遍历结束。
```python
def sequentialSearch(alist, item):
    # 定义局部变量 pos（整数），初始化为起始下标 0
    pos = 0
    # 定义局部变量 found（布尔型），初始化为 False 标记未找到
    found = False
    
    # 循环遍历列表：调用 len() 内置函数获取 alist 列表对象的长度属性
    # 当下标合法且未找到目标项时持续循环
    while pos < len(alist) and not found:
        # 访问 alist 列表对象的下标元素 alist[pos]，与目标项 item 进行值比对
        if alist[pos] == item:
            found = True
        else:
            # 下标顺序增长，后移一位
            pos = pos + 1
            
    # 返回最终查找状态布尔值
    return found

# 定义测试列表对象 testlist
testlist = [1, 2, 32, 8, 17, 19, 42, 13, 0]

# 调用 print() 内置函数输出调用 sequentialSearch() 自定义函数的结果
print(sequentialSearch(testlist, 3))   # 目标项 3 不存在，输出 False
print(sequentialSearch(testlist, 13))  # 目标项 13 存在，输出 True
```

>[!notes] 代码实现要点
>`sequentialSearch()` 函数：自定义无序表顺序查找函数，接收列表 `alist` 与目标数据项 `item` 两个参数。
>`len()` 内置函数：获取列表对象的长度属性，用于防止下标越界。
>`pos` 局部变量：维护当前遍历指针的下标偏移量。
>`found` 局部布尔变量：记录查找状态，找到后立即截断 `while` 循环避免无效遍历。
# 无序表顺序查找算法分析
## 基本计算步骤
根据 [[201.什么是算法分析|算法分析]] 的基本要点，评估查找算法复杂度时首先需确定其核心的 **基本计算步骤**。
基本计算步骤必须足够简单且在算法执行过程中被反复调用。
在查找算法中，这种基本计算步骤就是 **数据项的比对**（即判断当前元素是否等于要查找的数据项）。
**比对的执行次数直接决定了算法的时间复杂度**。
## 一般情形与概率假设
为了讨论具有普适性的一般情形，假定无序列表中的数据项并未按值的大小排序，而是随机分布在列表的各个位置。
换言之，假设待查找的数据项在列表各处出现的概率完全相同。
## 无序表复杂度分析
当目标数据项不在列表中时，算法必须比对完列表中全部 $n$ 个数据项才能确认失败，比对次数固定为 $n$ 次。
当目标数据项在列表中时，比对情况随数据项所处位置而变化：

最好情况（Best Case）：目标项恰好位于列表首位（下标为 `0`），只需进行 $1$ 次比对。
最坏情况（Worst Case）：目标项位于列表末尾，需要进行 $n$ 次比对。

平均情况（Average Case）：由于目标项出现在任一位置的概率均等，平均比对次数为 $\frac{n}{2}$ 次。

无论目标项是否存在，顺序查找的最高阶项均为线性阶，整体算法时间复杂度为 $O(n)$。

# 有序表顺序查找原理与实现
## 有序表的提前退出机制
在 [[315.有序表抽象数据类型及其python实现#search(item) 方法：升序剪枝与提前终止]] 中，所有数据项均已按升序或降序排列。
当数据项存在于列表中时，比对过程与无序表完全一致。
不同之处在于：如果目标数据项不存在，比对过程可以 **提前结束** 而无需遍历整个列表。
例如在下图升序列表中中查找数据项 `50`，当遍历到 `54` 时发现 `54 > 50`，因后续所有数据均大于 `54`，即可断定后续不可能存在 `50`，从而直接退出循环。
![[file-20261107200701322.png|371]]
## 有序查找代码实现
```python
def orderedSequentialSearch(alist, item):
    # 定义局部变量 pos（整数），初始化为起始下标 0
    pos = 0
    # 定义局部变量 found（布尔型），标记是否找到目标项
    found = False
    # 定义局部变量 stop（布尔型），标记是否触发提前退出条件
    stop = False
    
    # 循环遍历：调用 len() 内置函数获取列表长度属性
    # 当下标合法且未找到且未触发终止条件时持续循环
    while pos < len(alist) and not found and not stop:
        # 访问 alist 列表元素并比对
        if alist[pos] == item:
            found = True
        else:
            # 有序表核心剪枝：若当前元素大于待查项，后续不可能存在，提前退出
            if alist[pos] > item:
                stop = True
            else:
                # 下标顺序递增
                pos = pos + 1
                
    # 返回查找状态布尔值
    return found

# 定义升序测试列表对象 testlist
testlist = [0, 1, 2, 8, 13, 17, 19, 32, 42]

# 调用 print() 内置函数输出调用 orderedSequentialSearch() 自定义函数的结果
print(orderedSequentialSearch(testlist, 3))   # 遍历至 8 时提前退出，输出 False
print(orderedSequentialSearch(testlist, 13))  # 找到 13，输出 True
```

>[!tips] 标志变量控制
>`stop` 布尔变量：作为提前跳出条件引入，与 `found` 协同控制 `while` 循环的复合条件，避免了在分支内直接写 `break` 语句，保持单入口单出口的结构化编程规范。
# 有序表顺序查找算法分析
## 有序表复杂度对比
在有序表中，由于存在提前退出机制，数据项不存在时的比对次数显著减少：
最好情况（Best Case）：待查项小于列表首个元素，第 $1$ 次比对即发现大于待查项而提前退出。
最坏情况（Worst Case）：待查项大于列表全部元素，仍需比对 $n$ 次。
平均情况（Average Case）：若待查项在列表可能插入的各个空隙概率均等，平均比对次数缩减至 $\frac{n}{2}$ 次。
![[file-20261107200744476.png]]

>[!attention] 算法复杂度本质认知
>从算法渐进时间复杂度来看，有序表的顺序查找依然是 $O(n)$。
>虽然在数据项不存在的情形下，有序性让常数系数减半（平均比对次数从 $n$ 次降至 $\frac{n}{2}$ 次），但这仅仅节省了一定的常数级比对次数，并不能改变其线性阶 $O(n)$ 的数量级。
>若要真正突破线性查找的瓶颈、大幅提升查找效率，后续需要借助二分查找（Binary Search）等分治策略将复杂度降低至 $O(\log n)$。
